# ต้นทุนต่อผู้รับประโยชน์

ต้นทุนต่อผู้รับประโยชน์คือต้นทุนรวมของโครงการหารด้วยจำนวนบุคคลที่ไม่ซ้ำกันซึ่งได้รับบริการ — ทุกคนที่ถูกสัมผัส ไม่ว่าสถานการณ์ของเขาจะเปลี่ยนไปจริงหรือไม่ เป็นตัวเลขประสิทธิภาพที่เร็วที่สุดที่องค์กรผลิตได้ เพราะ "เราให้บริการใคร" แทบจะอยู่ในระบบบริหารจัดการกรณีอยู่แล้ว ขณะที่ "ใครได้รับความช่วยเหลือ" มักไม่อยู่

## เหตุใดจึงสำคัญ

ผู้ให้ทุนขอต้นทุนต่อผู้รับประโยชน์อยู่เสมอ ด้วยเหตุผลที่ป้องกันได้: ได้ทันที เปรียบเทียบได้ข้ามพอร์ตโฟลิโอโครงการที่ต่างกันมาก และตรงไปตรงมาเรื่องขอบเขตการเข้าถึงในแบบที่ข้อกล่าวอ้างเรื่องผลลัพธ์ — ซึ่งใช้เวลายืนยันนานกว่าและขยายเกินจริงได้ง่ายกว่า — ไม่เป็น UK Charities SORP (Statement of Recommended Practice) ซึ่งกำกับว่าองค์กรการกุศลรายงานภายใต้ FRS 102 อย่างไร กำหนดให้รายงานประจำปีของกรรมการมูลนิธิอธิบายความสำเร็จเทียบกับวัตถุประสงค์ แต่บัญชีบริหารขององค์กรการกุศลขนาดเล็กส่วนใหญ่ยังคงใช้ต้นทุนต่อหน่วยบนฐานการเข้าถึงเป็นค่าเริ่มต้น เพราะผลิตถูกและตรวจสอบง่าย

อันตรายคือการปฏิบัติต่อต้นทุนต่อผู้รับประโยชน์ราวกับตอบคำถามที่มันตอบไม่ได้: เงินได้ผลหรือไม่ ดู [ต้นทุนต่อผลลัพธ์](../ต้นทุนต่อผลลัพธ์/) สำหรับตัวชี้วัดที่ตอบคำถามนั้นจริง และ [ผลลัพธ์กับผลผลิต](../ผลลัพธ์กับผลผลิต/) สำหรับความแตกต่างพื้นฐาน ต้นทุนต่อผู้รับประโยชน์เป็นตัวชี้วัดการคัดกรองและการเข้าถึงที่ชอบธรรม — บอกผู้ให้ทุนว่าเงินยืดไปได้ไกลแค่ไหน — แต่ต้นทุนต่อผู้รับประโยชน์ที่ต่ำอาจหมายถึงประสิทธิภาพที่แท้จริง หรือบริการที่บางจนไม่เปลี่ยนอะไรเลย

## คณิตศาสตร์

```
ต้นทุนต่อผู้รับประโยชน์ = ต้นทุนรวมของโครงการ / จำนวนบุคคลที่ไม่ซ้ำกันที่ได้รับบริการ

เปรียบเทียบ:
ต้นทุนต่อผลลัพธ์       = ต้นทุนรวมของโครงการ / จำนวนบุคคลที่บรรลุผลลัพธ์ที่กำหนด

ต้นทุนต่อผู้รับประโยชน์ ≤ ต้นทุนต่อผลลัพธ์ เสมอ เพราะประชากรที่ได้ผลลัพธ์เป็นเซตย่อย
(มักเล็ก) ของประชากรผู้รับประโยชน์
```

## ตัวอย่างการคำนวณ

**ธนาคารอาหาร ปีเดียวกับตัวอย่างต้นทุนต่อผลลัพธ์**:

- ต้นทุนรวมของโครงการ: 450,000 ปอนด์
- ครัวเรือนที่ไม่ซ้ำกันที่ได้รับบริการ (สามชุดขึ้นไป): 1,800

```
ต้นทุนต่อผู้รับประโยชน์ = 450,000 ปอนด์ / 1,800 = 250 ปอนด์ต่อครัวเรือนที่ได้รับบริการ
```

เปรียบเทียบตัวชี้วัดทั้งสองเคียงข้างกัน:

| ตัวชี้วัด | ตัวหาร | ผลลัพธ์ |
|---|---|---|
| ต้นทุนต่อผู้รับประโยชน์ | 1,800 ครัวเรือนที่ได้รับบริการ | 250 ปอนด์ |
| ต้นทุนต่อผลลัพธ์ | 630 ครัวเรือนที่บรรลุความมั่นคงทางอาหาร | 714 ปอนด์ |

ผู้ให้ทุนที่เห็นเพียง 250 ปอนด์อาจสรุปว่าเป็นองค์กรการกุศลที่มีประสิทธิภาพสูงมาก ผู้ให้ทุนที่เห็นทั้งสองตัวเลขสามารถถามคำถามที่เป็นประโยชน์กว่า: ช่องว่างระหว่างการเข้าถึง (1,800) กับผลลัพธ์ (630) เป็นช่องว่างด้านการเก็บข้อมูล ช่องว่างด้านการออกแบบ หรือการสะท้อนอย่างตรงไปตรงมาว่าการบรรลุความมั่นคงทางอาหารด้วยความช่วยเหลือด้านอาหารเพียงอย่างเดียวยากเพียงใด

**องค์กรการกุศลฝึกอาชีพ เพื่อการอธิบาย**: ต้นทุนต่อผู้รับประโยชน์ (ลงทะเบียน) = 2,000 ปอนด์; ต้นทุนต่อผลลัพธ์ (มีงานทำอย่างยั่งยืนที่ 6 เดือน) = 11,000 ปอนด์ เพราะมีเพียง 18% ของผู้ลงทะเบียนที่เรียนจบและหางานที่ยั่งยืนได้ ตัวเลขสองตัวที่ต่างกันห้าเท่าเป็นเรื่องปกติทุกที่ที่อัตราการเรียนจบหรือความคงทนต่ำ — องค์กรฝึกอาชีพกับธนาคารอาหารมีโครงสร้างเหมือนกันในแง่นี้

## ความเชื่อมโยงกับวิศวกรรมซอฟต์แวร์

ต้นทุนต่อผู้รับประโยชน์เป็นตัวชี้วัดค่าเริ่มต้นในซอฟต์แวร์ขององค์กรไม่แสวงหากำไร เพราะเป็นตัวชี้วัดที่ตกออกมาจากระเบียนผู้รับประโยชน์โดยไม่ต้องทำอะไรเพิ่ม: สร้างกรณี บันทึกบริการ นับแถว การสร้างระบบที่รองรับต้นทุนต่อผลลัพธ์ด้วยหมายถึงการเพิ่มเอนทิตีชั้นหนึ่งตัวที่สองโดยเจตนา — เหตุการณ์ผลลัพธ์ ที่มีวันที่และกำหนดนิยามแยกจากการส่งมอบบริการ — และต้านทานความล่อใจที่จะให้ "ปิดกรณี" แทน "บรรลุผลลัพธ์" เมื่อกำหนดขอบเขตแพลตฟอร์มบริหารจัดการเงินอุดหนุนหรือ CRM ให้ถามว่าแดชบอร์ดแต่ละอันแสดงตัวชี้วัดใดจากสองตัวจริง ๆ และติดป้ายให้ตรง การรวมสองตัวไว้ในแผ่น "ผลกระทบ" เดียวเป็นหนึ่งในสาเหตุระดับซอฟต์แวร์ที่พบบ่อยที่สุดของข้อผิดพลาดด้านล่าง ดู [ฐานข้อมูลต้นทุนต่อหน่วย](../ฐานข้อมูลต้นทุนต่อหน่วย/) สำหรับการเทียบเกณฑ์ตัวชี้วัดใดก็ตามเมื่อติดป้ายถูกต้องแล้ว

## ข้อผิดพลาดที่พบบ่อย

- **นำเสนอต้นทุนต่อผู้รับประโยชน์เป็นผลกระทบ** มันวัดการเข้าถึง ไม่ใช่การเปลี่ยนแปลง ติดป้ายแดชบอร์ดและรายงานว่า "ต้นทุนต่อคนที่ได้รับบริการ" ไม่ใช่ "ต้นทุนต่อคนที่ได้รับความช่วยเหลือ"
- **นับซ้ำข้ามโครงการ** บุคคลที่ได้รับทั้งอาหารและคำปรึกษาด้านหนี้สินจากองค์กรการกุศลเดียวกันเป็นผู้รับประโยชน์หนึ่งราย ไม่ใช่สอง หากตัวหารมีไว้อธิบายการเข้าถึงที่ไม่ซ้ำ ตัดสินใจและบันทึกว่าใช้หลักเกณฑ์ใด
- **ถือว่าตัวเลขที่ต่ำกว่าดีกว่าเสมอ** ชมรมอาหารกลางวันแบบแวะมาเมื่อไรก็ได้จะชนะบริการบริหารจัดการกรณีแบบเข้มข้นในต้นทุนต่อผู้รับประโยชน์เสมอ เพราะการสัมผัสใครเพียงเบา ๆ ใช้เงินน้อยกว่า นั่นไม่ได้บอกอะไรเลยว่าสิ่งใดสร้างการเปลี่ยนแปลงที่ยั่งยืนกว่าต่อปอนด์
- **เปลี่ยนตัวหารระหว่างรายงานอย่างเงียบ ๆ** ตัวเลขต้นทุนต่อผู้รับประโยชน์ที่อ้างในรายงานประจำปีหนึ่งเทียบกับ "ผู้ลงทะเบียน" และในปีถัดไปเทียบกับ "ผู้สำเร็จ" เปรียบเทียบปีต่อปีไม่ได้ ระบุตัวหารทุกครั้ง
