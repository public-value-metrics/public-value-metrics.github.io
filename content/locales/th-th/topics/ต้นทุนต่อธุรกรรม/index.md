# ต้นทุนต่อธุรกรรม

ต้นทุนต่อธุรกรรมคือตัวชี้วัดเศรษฐศาสตร์หน่วยหลักของบริการดิจิทัลภาครัฐ: ต้นทุนรวมในการส่งมอบช่องทางหนึ่ง หารด้วยจำนวนธุรกรรมที่เสร็จสิ้นผ่านช่องทางนั้น เป็นตัวเลขเรือธงบน GOV.UK Performance Platform เดิม และเป็นตัวเลขที่สนับสนุนการลงทุน "ดิจิทัลเป็นค่าเริ่มต้น" มาทศวรรษ — ซึ่งเป็นเหตุผลพอดีที่ทำให้มันเป็นตัวชี้วัดที่ถูกเล่นแร่แปรธาตุได้ง่ายที่สุดด้วย

## เหตุใดจึงสำคัญ

Digital Efficiency Report ปี 2012 ของ Cabinet Office วางการเปรียบเทียบต้นทุนช่องทางในแบบที่ติดหู: ธุรกรรมดิจิทัลพบว่ามีต้นทุนต่ำกว่าทางโทรศัพท์ราว 20 เท่า และต่ำกว่าแบบพบหน้าราว 50 เท่า โดยมีตัวเลขตัวอย่างของรัฐบาลท้องถิ่นประมาณ 0.15 ปอนด์ต่อธุรกรรมเว็บ เทียบกับ 2.83 ปอนด์ทางโทรศัพท์ และ 8.62 ปอนด์แบบพบหน้า การเปรียบเทียบเดียวนั้นกลายเป็นเหตุผลสนับสนุนการออกแบบใหม่ของ 25 บริการตัวอย่างที่ระบุใน Government Digital Strategy และของกรณีทางธุรกิจของกระทรวงทุกฉบับที่อ้างการประหยัดจากการเปลี่ยนช่องทางตั้งแต่นั้นมา ตัวเลขนี้มีประโยชน์จริงในฐานะสัญญาณลำดับขนาด แต่อัตราส่วนขึ้นอยู่กับสิ่งที่นับในแต่ละฝั่งโดยสิ้นเชิง: ต้นทุนช่องทางโทรศัพท์ที่เป็นธรรมรวมบุคลากรศูนย์บริการ สัญญาโทรศัพท์ การฝึกอบรมและสถานที่; ต้นทุนดิจิทัลที่เป็นธรรมรวมโฮสติ้ง เงินเดือนทีมผลิตภัณฑ์ที่ต่อเนื่อง เวลาโต๊ะสนับสนุนสำหรับการใช้งานที่ล้มเหลว และช่องทางดิจิทัลแบบมีผู้ช่วยตามที่ข้อ 5 ของ [มาตรฐานบริการดิจิทัล](../มาตรฐานบริการดิจิทัล/) กำหนด ตัดสิ่งเหล่านี้ออกจากฝั่งดิจิทัลมากพอ บริการใดก็ดูถูก

## คณิตศาสตร์

```
ต้นทุนต่อธุรกรรม = ต้นทุนช่องทางที่จัดสรรทั้งหมด / ธุรกรรมที่เสร็จสิ้น

ต้นทุนช่องทางที่จัดสรรทั้งหมดควรรวม:
  + โฮสติ้งและโครงสร้างพื้นฐาน
  + ต้นทุนทีมผลิตภัณฑ์/วิศวกรรม/สนับสนุน (ตัดจ่ายตามอายุ)
  + ต้นทุนเนื้อหาและการออกแบบบริการ (ตัดจ่ายตามอายุ)
  + ต้นทุนการสนับสนุนดิจิทัลแบบมีผู้ช่วย / การเข้าถึง
  + ต้นทุนความต้องการจากความล้มเหลว (ผู้ใช้ที่ล้มเหลวทางดิจิทัลแล้ว
    ถอยกลับไปใช้โทรศัพท์)
  − ต้นทุนการสร้างครั้งเดียวตัดจ่ายตลอดอายุบริการที่คาดไว้ ไม่ใช่
    บันทึกเป็นค่าใช้จ่ายทั้งหมดในปีแรก

กลเม็ดทางบัญชีที่พบบ่อย:
  "ต้นทุนส่วนเพิ่มต่อธุรกรรม" (เฉพาะโฮสติ้ง เมื่อสร้างเสร็จแล้ว) ถูกอ้าง
  ราวกับเป็น "ต้นทุนเฉลี่ยต่อธุรกรรม" (ต้นทุนรวมรวมทีมที่ยังคงสร้างและ
  ดำเนินการ) ทั้งสองอาจต่างกัน 10 เท่าหรือมากกว่าสำหรับบริการที่มี
  ทีมส่งมอบขนาดใหญ่ที่ยังทำงานอยู่
```

## ตัวอย่างการคำนวณ

**บริการต่อภาษีรถยนต์**: 4 ล้านธุรกรรม/ปี

```
ตัวเลขส่วนเพิ่มเท่านั้น (กลเม็ด):
  โฮสติ้ง + การประมวลผลการชำระเงินเท่านั้น = 180,000 ปอนด์/ปี
  ต้นทุนต่อธุรกรรม = 180,000 / 4,000,000 = 0.045 ปอนด์
  → ตัวเลขพาดหัวที่อ้างในกรณีทางธุรกิจ

ตัวเลขเต็มจำนวน (ตัวเลขที่ซื่อตรง):
  โฮสติ้ง + การชำระเงิน                  180,000 ปอนด์
  ทีมผลิตภัณฑ์/วิศวกรรม (8 FTE)        720,000 ปอนด์
  โต๊ะสนับสนุน (ธุรกรรมที่ล้มเหลว/สอบถาม) 310,000 ปอนด์
  สายโทรศัพท์ดิจิทัลแบบมีผู้ช่วย         140,000 ปอนด์
  รวม                                 1,350,000 ปอนด์
  ต้นทุนต่อธุรกรรม = 1,350,000 / 4,000,000 = 0.3375 ปอนด์

ตัวเลขเต็มจำนวนยังคงถูกกว่าเกณฑ์เทียบช่องทางโทรศัพท์ 2.83 ปอนด์จาก
Digital Efficiency Report ราว 8 เท่า — การประหยัดที่แท้จริงและป้องกันได้ —
แต่สูงกว่าตัวเลขส่วนเพิ่มเท่านั้นที่อ้างในเวอร์ชันทางลัด 7.5 เท่า
ทั้งสองตัวเลข "เป็นจริง"; มีเพียงตัวเดียวที่เปรียบเทียบได้กับ
ต้นทุนช่องทางโทรศัพท์ที่นำมาวางเทียบ
```

## ความเชื่อมโยงกับวิศวกรรมซอฟต์แวร์

ต้นทุนต่อธุรกรรมคือจุดที่การตัดสินใจด้านสถาปัตยกรรมกลายเป็นตัวเลขทางการเงิน: บริการที่ปรับขนาดอัตโนมัติได้อย่างสะอาดและต้องการการแทรกแซงด้วยมือน้อยดันตัวเลขนี้ลงเมื่อเวลาผ่านไป; บริการที่สร้างปริมาณตั๋วสนับสนุนสูงจากสถานะข้อผิดพลาดที่สับสนดันตัวเลขขึ้นโดยไม่คำนึงถึงประสิทธิภาพโฮสติ้ง เป็นตัวชี้วัดคู่ที่เป็นธรรมชาติของข้อ 10 ใน [มาตรฐานบริการดิจิทัล](../มาตรฐานบริการดิจิทัล/) ("กำหนดว่าความสำเร็จหน้าตาเป็นอย่างไร และเผยแพร่ข้อมูลประสิทธิภาพ") และ [มาตรฐานบริการและตัวชี้วัดธุรกรรม](../มาตรฐานบริการและตัวชี้วัดธุรกรรม/) ซึ่งระบุชุด KPI ที่เต็มกว่าที่ตัวเลขนี้อยู่ภายใน และยังป้อนตรงเข้าสู่การคำนวณ [การประหยัดจากการเปลี่ยนช่องทาง](../การประหยัดจากการเปลี่ยนช่องทาง/) และควรกระทบยอดกับ [ต้นทุนรวมของการเป็นเจ้าของ (TCO) ในไอทีภาครัฐ](../ต้นทุนรวมของการเป็นเจ้าของ-ในไอทีภาครัฐ/) เพื่อไม่ให้ค่าใช้จ่ายส่วนกลางของแพลตฟอร์มและบริการร่วมหล่นหายไปอย่างเงียบ ๆ

## ข้อผิดพลาดที่พบบ่อย

- **ต้นทุนส่วนเพิ่มที่แต่งตัวเป็นต้นทุนเฉลี่ย**: การอ้างต้นทุนโฮสติ้งเพียงอย่างเดียวเมื่อบริการสร้างเสร็จ โดยละเว้นทีมที่ยังคงดูแล พัฒนาต่อ และสนับสนุน — ดูตัวอย่างการคำนวณข้างต้น
- **ไม่รวมต้นทุนดิจิทัลแบบมีผู้ช่วย**: ช่องทางไม่ถือว่าสอดคล้อง "ดิจิทัลเป็นค่าเริ่มต้น" และต้นทุนที่แท้จริงไม่ถูกจับ หากช่องทางสำรองทางโทรศัพท์/กระดาษที่ [การเข้าถึงดิจิทัลอย่างทั่วถึง](../การเข้าถึงดิจิทัลอย่างทั่วถึง/) กำหนดถูกคิดต้นทุนแยกหรือถูกละเลย
- **เพิกเฉยต่อความต้องการจากความล้มเหลว**: ธุรกรรมที่เริ่มทางดิจิทัลแล้วล้มเหลวและสร้างการโทรหรือแบบฟอร์มกระดาษอยู่ดี เป็นต้นทุนของช่องทางดิจิทัล ไม่ใช่ของช่องทางที่รับความล้มเหลวนั้น
- **เปรียบเทียบธุรกรรมที่ซับซ้อนต่างกันข้ามช่องทาง**: โทรศัพท์รับมือกรณียากเป็นสัดส่วนที่มากกว่า (ผู้อยู่ในอุปการะหลายคน การแก้ไขข้อผิดพลาด ผู้ยื่นคำขอที่เปราะบาง); การเปรียบเทียบต้นทุนโทรศัพท์เฉลี่ยกับต้นทุนดิจิทัลเฉลี่ยทำให้อัตราส่วนสูงเกินจริง เว้นแต่จะจับคู่ส่วนผสมของธุรกรรม
