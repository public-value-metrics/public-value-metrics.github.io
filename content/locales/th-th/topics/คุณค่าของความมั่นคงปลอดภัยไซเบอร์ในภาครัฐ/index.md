# คุณค่าของความมั่นคงปลอดภัยไซเบอร์ในภาครัฐ

คุณค่าของความมั่นคงปลอดภัยไซเบอร์ในภาครัฐคือวินัยในการกำหนดราคาการลดความเสี่ยง: การทำให้การละเมิดข้อมูลของประชาชนมีโอกาสเกิดน้อยลงมีมูลค่าเท่าใด เมื่อพิจารณาว่ารายจ่ายด้านความมั่นคงปลอดภัยไม่ก่อให้เกิดผลผลิตที่มองเห็นได้เมื่อทำงาน และมองเห็นชัดเจนเมื่อล้มเหลว? สำหรับบริการที่ถือระเบียนสวัสดิการ ข้อมูลสุขภาพ หรือระเบียนภาษี คุณสมบัติ "มองไม่เห็นเมื่อทำงาน" นั้นพอดีคือเหตุผลที่ต้องมีข้อโต้แย้งด้านคุณค่าที่ชัดเจน ไม่ใช่แค่ติ๊กถูกเรื่องการปฏิบัติตามกฎระเบียบ

## เหตุใดจึงสำคัญ

Cyber Assessment Framework (CAF) ของ National Cyber Security Centre แห่งสหราชอาณาจักรให้องค์กรภาครัฐมีวิธีที่มีโครงสร้างในการทำให้ความมั่นคงปลอดภัยเป็นวินัยที่ประเมินได้ บนพื้นฐานผลลัพธ์ แทนที่จะเป็นเช็กลิสต์: กำหนดสี่วัตถุประสงค์ระดับสูง (การจัดการความเสี่ยงด้านความมั่นคงปลอดภัย การป้องกันการโจมตีทางไซเบอร์ การตรวจจับเหตุการณ์ความมั่นคงปลอดภัยไซเบอร์ และการลดผลกระทบของเหตุการณ์) แยกย่อยเป็นผลลัพธ์ที่มีส่วนร่วมซึ่งเจ้าของระบบสามารถถูกประเมินได้ ด้วยเจตนารมณ์เดียวกับข้อ 9 ของ [มาตรฐานบริการดิจิทัล](../มาตรฐานบริการดิจิทัล/) ("สร้างบริการที่ปลอดภัยซึ่งปกป้องความเป็นส่วนตัวของผู้ใช้") สิ่งที่การประเมิน CAF ปกป้องมีป้ายราคาที่บันทึกไว้: รายงาน Cost of a Data Breach ของ IBM ติดตามต้นทุนเฉลี่ยของการละเมิดตามภาคส่วน และพบสม่ำเสมอว่าภาครัฐอยู่ด้านล่างของช่วงเมื่อเทียบกับการเงินหรือสาธารณสุข — ฉบับล่าสุดระบุค่าเฉลี่ยภาครัฐประมาณ 2.6–2.9 ล้านดอลลาร์ต่อการละเมิดหนึ่งครั้ง — แต่ "ต่ำกว่าการเงิน" ไม่ใช่ "ต่ำ" และการละเมิดของรัฐบาลมีต้นทุนที่ตัวเลขของรายงานจับไม่ครบ: การสูญเสียความไว้วางใจของประชาชนต่อช่องทางดิจิทัล ซึ่งลด [การใช้ดิจิทัล](../การประหยัดจากการเปลี่ยนช่องทาง/) ที่กรณีทางธุรกิจของการเปลี่ยนช่องทางพึ่งพา และต้นทุนทางการเมืองและกฎหมายของการเปิดเผยข้อมูลที่รัฐบังคับให้ประชาชนส่งมอบตั้งแต่แรก

## คณิตศาสตร์

การลงทุนด้านความมั่นคงปลอดภัยประเมินค่าเหมือนรายจ่ายลดความเสี่ยงทั่วไป: เป็นการลดการสูญเสียที่คาดหมาย โดยใช้เอกลักษณ์การบริหารความเสี่ยงแบบคลาสสิก

```
การสูญเสียที่คาดหมายรายปี (ALE) = การสูญเสียที่คาดหมายต่อครั้ง (SLE)
                                  × อัตราการเกิดเหตุรายปี (ARO)

มูลค่าของมาตรการควบคุมความมั่นคงปลอดภัย =
  ALE_ก่อนมีมาตรการ − ALE_หลังมีมาตรการ − ต้นทุนรายปีของมาตรการ

มาตรการคุ้มค่าที่จะให้ทุนเมื่อ:
  (ALE_ก่อน − ALE_หลัง) > ต้นทุนรายปีของมาตรการ

การประเมิน CAF ไม่ได้ให้ความน่าจะเป็นโดยตรง แต่โปรไฟล์ผลลัพธ์ CAF
ของบริการ (ผลลัพธ์ที่มีส่วนร่วมใดที่ "บรรลุ" "บรรลุบางส่วน" หรือ "ไม่บรรลุ")
เป็นปัจจัยนำเข้าตัวแทนที่สมเหตุสมผลเพื่อประมาณ ARO — ระบบที่ไม่จัดการ
สิทธิ์การเข้าถึงระดับสูงหรือไม่มีแผนรับมือเหตุการณ์ที่ผ่านการทดสอบ
มี ARO ที่สมจริงสูงกว่าอย่างมีนัยสำคัญเมื่อเทียบกับระบบที่มีทั้งสองอย่าง
```

## ตัวอย่างการคำนวณ

**ระบบบริหารจัดการกรณีของสภาเทศมณฑลที่ถือระเบียนบริการสังคมของผู้อยู่อาศัย 40,000 คน**:

```
การสูญเสียที่คาดหมายต่อครั้ง (ต้นทุนการละเมิด) โดยใช้ค่าเฉลี่ยภาครัฐจาก
รายงาน Cost of a Data Breach ของ IBM ฉบับล่าสุด ≈ 2.1 ล้านปอนด์
(แปลงค่าแล้ว เป็นตัวเลขลำดับขนาด — คำนวณใหม่จากรายงานฉบับปัจจุบันเสมอ
แทนที่จะใช้ตัวเลขคงที่ซ้ำ)

ARO ปัจจุบัน (สิทธิ์การเข้าถึงระดับสูงไม่ได้รับการจัดการ ไม่มีการรับมือเหตุการณ์
ที่ผ่านการทดสอบ ตามการประเมินตนเอง CAF ภายในที่แสดงหลายผลลัพธ์ "ไม่บรรลุ")
≈ ประมาณการ 8% ต่อปี
  ALE_ก่อน = 2.1 ล้านปอนด์ × 0.08 = 168,000 ปอนด์/ปี

มาตรการที่เสนอ: การจัดการสิทธิ์การเข้าถึงระดับสูง + แผนรับมือเหตุการณ์ที่ผ่านการทดสอบ
ย้ายผลลัพธ์ CAF ที่เกี่ยวข้องไปที่ "บรรลุ" ประมาณการลด ARO เหลือ 3%/ปี
  ALE_หลัง = 2.1 ล้านปอนด์ × 0.03 = 63,000 ปอนด์/ปี

ต้นทุนรายปีของมาตรการ (เครื่องมือ + กระบวนการ + การทดสอบ) = 45,000 ปอนด์

มูลค่าของมาตรการ = (168,000 − 63,000) − 45,000 = 60,000 ปอนด์/ปี
  เป็นบวกสุทธิ — ให้ทุน เลขคณิตยังแสดงว่ามาตรการจะยังคุ้มค่าที่จะให้ทุน
  แม้ต้นทุนเกือบสามเท่า ซึ่งเป็นการตรวจสอบความไวประเภทที่ควรมาพร้อม
  ตัวเลข ALE ใด ๆ ที่สร้างบนความน่าจะเป็นที่ประมาณการ
```

## ความเชื่อมโยงกับวิศวกรรมซอฟต์แวร์

วิศวกรเป็นเจ้าของคันโยกส่วนใหญ่ในสมการ ALE: การออกแบบการควบคุมการเข้าถึง สุขอนามัยของ dependency และแพตช์ ความครอบคลุมของการบันทึกและการตรวจจับ และเครื่องมือรับมือเหตุการณ์ ล้วนขยับพจน์ ARO โดยตรง ซึ่งเป็นเหตุผลที่การประเมิน CAF อ่านเหมือนการทบทวนสถาปัตยกรรมเทคนิคพอ ๆ กับการตรวจสอบนโยบาย นี่คือ [หนี้ทางเทคนิคในฐานะการกัดกร่อนคุณค่าสาธารณะ](../หนี้ทางเทคนิคในฐานะการกัดกร่อนคุณค่าสาธารณะ/) ในรูปแบบที่เฉียบพลันที่สุด — ระบบที่ไม่ได้แพตช์ ไม่ได้เฝ้าติดตาม และควบคุมการเข้าถึงไม่ดี คือหนี้ที่ดอกเบี้ยคือความเสี่ยงหางของการกระจาย ไม่ใช่แรงฉุดคงที่ — และควรกระทบยอดกับ [ต้นทุนรวมของการเป็นเจ้าของ (TCO) ในไอทีภาครัฐ](../ต้นทุนรวมของการเป็นเจ้าของ-ในไอทีภาครัฐ/) เพื่อไม่ให้รายจ่ายด้านความมั่นคงปลอดภัยถูกมองแยกจากต้นทุนการดำเนินงานจริงของระบบ และยังเป็นปัจจัยนำเข้าโดยตรงของการประเมิน [ความคุ้มค่าของเงิน](../ความคุ้มค่าของเงิน/) ภายใต้ Green Book: ต้นทุนที่ปรับตามความเสี่ยงเป็นส่วนหนึ่งของด้าน "ต้นทุน" ในการประเมินทางเลือกใด ๆ ไม่ใช่ส่วนเสริมที่ต่อท้าย

## ข้อผิดพลาดที่พบบ่อย

- **ถือการประเมินตนเอง CAF เป็นความมั่นคงปลอดภัยเอง**: การประเมินที่เสร็จสมบูรณ์อธิบายท่าทีด้านความมั่นคงปลอดภัย ไม่ได้สร้างมันขึ้น — คุณค่าอยู่ที่ผลลัพธ์ที่บรรลุ ไม่ใช่เอกสาร
- **ใช้ต้นทุนการละเมิดเฉลี่ยระดับโลกเป็นประมาณการท้องถิ่นโดยไม่ปรับ**: ตัวเลขของ IBM เป็นค่าเฉลี่ยข้ามตัวอย่างใหญ่และหลากหลาย การสูญเสียที่คาดหมายต่อครั้งที่สมจริงของหน่วยงานท้องถิ่นขนาดเล็กแทบไม่เหมือนของกระทรวงระดับชาติ
- **เพิกเฉยต่อจิตวิทยาความเสี่ยงหางในการตัดสินใจลงทุน**: ความน่าจะเป็นรายปีต่ำทำให้เลื่อนรายจ่ายด้านความมั่นคงปลอดภัยออกไปได้ไม่สิ้นสุด จนถึงปีที่ไม่ใช่ — การทดสอบความไวของการคำนวณ ALE กับช่วงของ ARO ดังในตัวอย่างช่วยต้านสิ่งนี้
- **นับเฉพาะต้นทุนการละเมิดแบบ IBM ไม่นับต้นทุนความไว้วางใจ**: การละเมิดที่ลดความเต็มใจของประชาชนในการใช้ช่องทางดิจิทัลกัดกร่อนกรณี [การประหยัดจากการเปลี่ยนช่องทาง](../การประหยัดจากการเปลี่ยนช่องทาง/) ไปอีกหลายปี ต้นทุนที่แทบไม่รวมในประมาณการต้นทุนการละเมิด
