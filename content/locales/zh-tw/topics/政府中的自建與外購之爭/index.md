# 政府中的自建與外購之爭

自建與外購之爭（build-vs-buy）是一種結構化的、經過風險調整的比較，將定製開發與商用或通用採購方案，在折現後的[總擁有成本](../政府-it-中的總擁有成本/)、價值實現時間和風險三個維度上進行對比。從結構上講，政府本質上是一個採購型部門——技術操守準則（Technology Code of Practice）確立了偏向通用與雲端解決方案的預設立場——但各部門內部的工程團隊仍然預設傾向於自建，理由與世界各地的建設者們如出一轍。

## 為何重要

政府數位服務局（Government Digital Service）的《技術操守準則》（<https://www.gov.uk/guidance/the-technology-code-of-practice>）及配套的《服務手冊》（Service Manual）中關於自建或外購決策的指南，要求各部門在預設"通用能力應當購買而非自建，只有真正新穎、能體現使命差異化的能力才值得定製開發"的前提下，為定製開發提供正當理由。財政部《綠皮書》關於樂觀偏差的補充指南，源自 2002 年 Mott MacDonald 對大型公共採購專案的審查，在所評估的各類別中，IT 專案獲得了最大的上調區間——建議在用於評估之前，將資本成本估算下限上調 10%、上限最高上調 200%，這反映出軟體建設專案在整個公共採購歷史中曾被嚴重低估的程度。自建與外購分析存在的意義，正是要在獲批之前將這種風險調整擺上檯面，而不是讓它以年度超支申請的形式事後浮現。

## 數學原理

```
在相同的 3–5 年週期內比較，按《綠皮書》的社會折現率折現
（參見 social-discount-rate.md）：

方案淨現值 = PV（按價值實現時間調整後的效益） − PV（總擁有成本）

風險調整（《綠皮書》樂觀偏差模式）：
  自建成本 × 1.1–3.0        （IT 專案上調區間，Mott MacDonald）
  自建價值實現時間 + 40–60%  （部署延遲先驗值）
  外購：改為加上整合現實檢驗成本與合同退出成本

決策驅動因素，按通常的決定性順序排列：
  1. 差異化程度——這項能力是使命所在，還是基礎管道？
  2. 價值實現時間 × 延遲成本（參見 cost-of-delay-in-public-programmes.md）
  3. 經風險調整後的總擁有成本
```

## 實例演算

某地方政府需要一套成人社會關懷個案管理系統。外購方案：SaaS 服務，每年 18 萬英鎊，4 個月內上線。自建方案：預估 90 萬英鎊，另加每年 15 萬英鎊維護費，14 個月內上線。

```
經風險調整後的自建成本 = 900,000 × 1.4 = 1,260,000 英鎊
五年總擁有成本：
  外購  = 180,000 × 5 = 900,000 英鎊
  自建  = 1,260,000 + 150,000 × 5 = 2,010,000 英鎊

延遲成本項：該系統每月可避免 40,000 英鎊的重複評估支出；
自建方案比外購方案晚 10 個月上線。
延遲成本 = 10 × 40,000 = 400,000 英鎊

實際比較：900,000 英鎊（外購） vs 2,010,000 + 400,000 = 2,410,000 英鎊（自建）
```

五年內外購方案勝出約 150 萬英鎊，而在自建成本估算本身之外最大的一項，正是純資本支出比較永遠不會揭示出來的延遲成本。

## 與軟體工程的關聯

從這一分析可以直接遷移到交付實踐中的紀律包括：**基於先驗值的風險調整**——Mott MacDonald 的上調係數，就是機械化應用《綠皮書》樂觀偏差原則在軟體領域的對應做法，團隊應當為例外情況爭取論證，而不是想當然地認為自己的估算就是例外；**對照方案的誠實性**——自建的替代方案是可獲得的最佳外購選項，而不是"什麼都不做"，這與[公共支出中的機會成本](../公共支出中的機會成本/)直接相關；以及**誠實的總擁有成本比較**——每一份自建方案都應對照外購方案完整的[總擁有成本](../政府-it-中的總擁有成本/)，而不是其標價來進行比較。在自建確實勝出的情況下，額外自建時間所帶來的[延遲成本](../公共專案中的延遲成本/)應當在商業案例中明確定價，而不是被留作一個"時間不重要"的未言明假設。

## 常見陷阱

- **將供應商標價與未經風險調整的自建估算相比較**：這會使自建方案在成本和工期兩方面都被雙重美化。
- **內部人力零成本化**：公務員的工程工時因已計入部門人頭預算而被視為"免費的"，這掩蓋了該團隊本可從事其他工作所付出的真實機會成本。
- **雙向都未定價的鎖定風險**：供應商退出與資料可移植性成本是真實的，但定製自建方案在其生命週期內對一支規模小、難以替代的內部團隊的依賴（即"巴士因子"風險）同樣真實。
- **將基礎管道包裝成使命差異化能力**："這是我們的核心"這一說法被用於整合中介軟體或檔案儲存系統——應當檢驗：公民或個案工作人員是否真的會在意底層運作的究竟是哪一套系統。
