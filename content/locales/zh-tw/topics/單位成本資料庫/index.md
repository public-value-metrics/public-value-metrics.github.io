# 單位成本資料庫

單位成本資料庫，是一個由預先研究、有證據支撐的社會成果財務代理指標組成的資料庫——從失業轉向就業的價值、孤獨感減輕的價值、一份穩定租約的價值——使從業者能夠為一項成果貨幣化，而無需每次都委託定製的估值研究。它們之所以存在，是為了讓一家撰寫撥款申請的小型慈善機構，能夠透過複用他人已經推導並發表的代理指標，達到與一家資源充足的諮詢公司同等的嚴謹程度。

## 為何重要

由經濟學家 Daniel Fujiwara 使用福祉估值方法開發的 HACT 英國社會價值銀行（UK Social Value Bank），以及 Global Value Exchange（一個開放的、眾包的財務代理指標資料庫），是英國第三部門和公共部門中使用最廣泛的兩個資料庫。兩者之所以存在，是因為底層的估值工作——[福祉估值](../福祉估值/)和[陳述性偏好估值](../陳述性偏好估值/)——成本高昂、方法論要求嚴苛，而且每個專案都從零開始進行既緩慢又費力。一個共享的、已釋出的代理指標庫，將原本需要數月的研究工作變成了一次查詢，這正是它們對[社會投資回報](../社會投資回報/)計算和[社會價值法](../社會價值法/)投標評估都至關重要的原因：如果沒有它們，嚴謹的貨幣化工作將只有規模足夠大、能夠委託自己研究的組織才能負擔得起。

## 數學原理

單位成本資料庫本身不進行任何計算；它為別處進行的一次計算提供一項輸入：

```
財務代理值 = 市場價格，或影子價格，或福祉估值，
             或陳述性偏好價值
             針對一個既定的成果變化單位
             （例如"每有一人從失業轉向就業，每年"）

應用價值 = 已實現的成果數量 × 單位代理值
```

關於在沒有市場價格存在時如何建置一個代理指標，參見[影子定價](../影子定價/)；關於應用價值在經過無謂損失和歸因調整後如何輸入到一個比率中，參見[社會投資回報](../社會投資回報/)。

## 實例演算

**慈善機構（陪伴服務 SROI）**：單位成本資料庫中"孤獨感減輕"這一條目，給出了示例性代理值每人每年 1,100 英鎊。應用於 80 名受益人：80 × 1,100 英鎊 = 88,000 英鎊總體價值。如果同一資料庫中還有一個"心理福祉改善"的代理指標，且該指標借鑑了一項重疊的福祉調查專案，那麼對同一批 80 人疊加使用這兩個代理指標，會對同一潛在變化的一部分重複計算——資料庫提供的是數位，但避免這種重疊是分析人員的責任。

**地方政府（求職俱樂部 SROI）**：單位成本資料庫中"從失業轉向持續性就業"這一條目，以示例性代理值每人每年 8,500 英鎊應用於 45 名參與者：45 × 8,500 英鎊 = 382,500 英鎊總體價值，這還未經過[社會投資回報](../社會投資回報/)中所示的無謂損失和歸因調整。

## 與軟體工程的關聯

為慈善機構或採購方建置報告工具的團隊，受益於建立一份內部的"成果目錄"——一張表格，將產品或服務能夠合理聲稱的每一項成果，對映到一個具名的代理指標、其來源資料庫、釋出日期和版本識別符號——從而使組織內不同的團隊不會各自為同一項成果挑選略有出入的數值。將 Global Value Exchange 的開放資料包裝在一個查詢服務背後，並始終在數位旁邊顯示來源和日期，能使該代理指標保持可審計性，而不是一個埋藏在電子表格中的魔法數位。關於這些代理指標被使用的兩個主要場景，參見[社會投資回報](../社會投資回報/)和[社會價值法](../社會價值法/)。

## 常見陷阱

- **將代理指標當作精確數值。** 大多數已釋出的代理指標，是源自置信區間很寬的福祉估值研究的建模平均值；將其精確到英鎊來引用，會誇大底層研究所能支撐的精確度。
- **對重疊的代理指標重複計算。** 將源自重疊調查構唸的代理指標（例如"孤獨感減輕"和"心理福祉改善"）疊加組合，會對同一潛在變化進行兩次估值。
- **未經調整就使用脫離語境的代理指標。** 一個針對某一國家人群和年份校準的代理指標，在未經通脹或情境調整的情況下應用於別處，會在不知不覺中錯誤地陳述價值。
- **不核實來源。** Global Value Exchange 是開放且眾包的，因此條目品質因貢獻者而異；在撥款申請或採購提交中引用一個數位之前，應核實其底層來源。
