# 政府 IT 中的總擁有成本（TCO）

總擁有成本是一個系統的全生命週期成本——採購成本加上每一年的運作成本——折現到同一個基準日期。在政府 IT 領域，最常見、最可靠的預測錯誤，就是僅憑採購價格對供應商或方案進行比較，而營運和維護成本通常佔據全生命週期總賬單的一半到五分之四之多。

## 為何重要

財政部《綠皮書》要求任何五個論證案例模型商業案例中的財務論證都必須覆蓋全生命週期成本，而不僅僅是資本支出——然而國家審計署一再發現，各部門在批准 IT 投資時所依據的運作成本預測不完整或過於樂觀，直到系統上線、資本預算科目已經結項之後，才發現真實的營運成本。政府數位服務局和中央數位與資料辦公室的《技術操守準則》（<https://www.gov.uk/guidance/the-technology-code-of-practice>）之所以推動各部門轉向雲端和通用託管，部分原因正是它能使持續性成本變得可見、可比較，而不是被埋藏在一個單一的資本採購數位中——這個數位在獲批時看起來誘人的低，三年後卻昂貴得錯得離譜。

## 數學原理

```
TCO = 採購成本 + Σ(t=1..N) 第t年年度營運成本 / (1+r)^t
      − 殘值（已折現）

r = 財政部《綠皮書》標準社會折現率，3.5%/年
    （超過 30 年週期的遞減利率時間表）

營運成本組成部分：託管/授權、支援與維護、
安全補丁與合規、員工工時、計劃性更新/遷移
```

關於折現係數在典型的 5 至 10 年系統生命週期內為何重要，參見[社會折現率](../社會折現率/)；關於 TCO 如何輸入自建/外購決策，參見[政府中的自建與外購之爭](../政府中的自建與外購之爭/)。

## 實例演算

某部門在《綠皮書》3.5% 折現率下，以 5 年為週期比較兩套個案管理系統。

```
系統 A：資本支出 3,500,000 英鎊，營運支出 250,000 英鎊/年
系統 B：資本支出 1,800,000 英鎊（看起來更便宜），
       營運支出 650,000 英鎊/年（更重的供應商支援
       和整合負擔）

僅憑資本支出的樸素比較：B 勝出，180萬 < 350萬。

5 年折現係數之和，3.5%：0.966+0.934+0.902+0.871+0.842 ≈ 4.515

TCO_A = 3,500,000 + 250,000 × 4.515 = 3,500,000 + 1,128,750 = 4,628,750 英鎊
TCO_B = 1,800,000 + 650,000 × 4.515 = 1,800,000 + 2,934,750 = 4,734,750 英鎊
```

TCO 顛覆了這一樸素決策：在對營運成本進行折現並加總後，系統 B 在五年內略貴一些，因為其營運支出佔全生命週期成本的比例高達 62%（2,934,750 / 4,734,750），而系統 A 只有 24%——這正是"維護佔賬單大頭"這一發現的一個具體實例，而僅憑標價比較會將其完全掩蓋。

## 與軟體工程的關聯

TCO 應當是規範每一次[自建與外購](../政府中的自建與外購之爭/)決策和每一份[技術債](../技術債作為公共價值侵蝕/)償還論證的數位，因為債務利息和被推遲的維護，都是應當計入同一個折現總額中的營運成本科目，無論是否有人一直在跟蹤它們。提出平臺或供應商選擇方案的工程師，應當呈現完整的 TCO 表格，而不是採購價格，因為採購價格正是《綠皮書》財務論證設計初衷所要阻止各部門單獨依賴的那個數位。TCO 也是[物有所值](../物有所值/)判斷的誠實分母——VFM 比較的是效益與成本，而一個被低估的成本科目，會誇大商業案例中的每一個 VFM 比率。

## 常見陷阱

- **僅比較資本支出**：最常見的採購錯誤——在沒有為每個方案匹配營運成本預測的情況下，僅比較供應商標價。
- **排除退出和遷移成本**：合同終止時的資料提取、重新平臺化和供應商鎖定罰金，都是真實的 TCO 科目，卻很少出現在原始商業案例中。
- **排除安全和合規成本**：補丁節奏、認證更新和審計成本會隨系統年齡和複雜度而增長——參見[公共部門網路安全價值](../公共部門網路安全價值/)——卻常常被排除在營運支出預測之外。
- **在成本結構不同的方案之間進行未折現比較**：在不進行折現的情況下，將一個資本支出密集型方案與一個營運支出密集型方案相比較，會系統性地偏向那個恰好將更多成本推遲到後期年份的方案。
