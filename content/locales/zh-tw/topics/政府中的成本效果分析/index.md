# 政府中的成本效果分析

成本效果分析（Cost-Effectiveness Analysis，CEA）比較實現*同一*成果的不同方案的成本，以自然單位表示——每安置一名露宿者的成本、每讓一名學生達到預期標準的成本、每減排一噸二氧化碳的成本——而不將成果本身折算成貨幣。

## 為何重要

當[社會成本效益分析](../社會成本效益分析/)要求將每一項效益都貨幣化的做法不僅變得困難、而且變得不誠實時——即對該成果給出可信定價將需要一些實際上根本無人認同的假設——《綠皮書》將 CEA 視為退而求其次的方法（<https://www.gov.uk/government/publications/the-green-book-appraisal-and-evaluation-in-central-government>，第五章，關於成果不易貨幣化情形下的方案評估）。CEA 是從衛生經濟學中借用得最為直接的一種方法——其結構與英國國家衛生與臨床最佳化研究所（NICE）使用每品質調整生命年（QALY）成本比較治療方案的方式完全相同——但被應用於非衛生類公共專案：教育介入以每學生成果分為單位、住房專案以每防止一戶陷入無家可歸為單位、就業專案以每一個持續性就業成果為單位。

CEA 之所以能與 SCBA 並列而不被其取代，是因為強行為某些成果賦予貨幣價值，會產生一個精確得看似權威、卻又充滿爭議得毫無價值的數位——為"一名兒童達到預期閱讀水平"定價，恰恰會招致那種在特別委員會審議中使商業案例脫軌的質疑。CEA 乾脆迴避了這場爭論：它按每單位*成果本身*的成本對各方案進行排序，而將該成果本身是否值得追求這一獨立的政治判斷，留給戰略性論證去處理。

## 數學原理

```
成本效果比（平均） = 總成本 / 已實現的總成果單位數

增量成本效果比（ICER），比較方案 A 與方案 B：
ICER = (成本_A − 成本_B) / (成果_A − 成果_B)

流程：
1. 在所比較的所有方案之間，固定成果單位與測量方法。
2. 在同一基礎上（參見 ../green-book-appraisal/，財務論證部分）、
   在相同的時間跨度內，為每個方案計算成本。
3. 剔除被支配的方案：任何一個方案，若其每單位成本高於
   一個能實現相同或更好成果、成本更低的替代方案，則將其剔除。
4. 按增量而非平均成本效果比，對剩餘方案進行排序。
```

CEA 本身無法回答一個專案是否值得資助——它只能回答，在實現同一目標的若干方法中，哪一種每單位成本最低。而該目標本身是否值得這筆支出，則需要要麼折回到 SCBA（若存在可信的估值方法），要麼依靠數學之外的政治/戰略判斷。當成果確實無法歸約為單一單位——因為一個專案會產生若干種以不同方式各具重要性的成果——則應改用[多準則決策分析](../多準則決策分析/)。

## 實例演算

**地方政府**：某議會比較三種減少露宿人數的方法，均按一年計算成本，對照成果為"個人遷入穩定住所並維持 6 個月以上"：

```
方案                            成本        已實現成果   平均CER
housing First（密集支援）        900,000英鎊  60          15,000英鎊/成果
旅館過渡+後續支援                 600,000英鎊  50          12,000英鎊/成果
外展+私人租賃部門                 350,000英鎊  20          17,500英鎊/成果

增量CER，旅館過渡 vs 外展：(60萬−35萬)/(50−20) = 每新增一個成果 8,333英鎊
增量CER，Housing First vs 旅館過渡：(90萬−60萬)/(60−50) = 每新增一個成果 30,000英鎊
```

從平均成本角度看，外展方案被旅館過渡方案支配，但從外展方案*增量*升級到旅館過渡方案，每多安置一人的成本僅為 8,333 英鎊——相對於從旅館過渡升級到 Housing First 的那一步而言便宜得多，後者每多安置一人的成本為 30,000 英鎊。一個預算有限、準備擴大規模的政府機構，應當優先擴大旅館過渡方案，而不是 Housing First，即便 Housing First 就其自身平均比率而言看起來更優。

**中央政府**：一項識字補救專案在三種交付模式之間以"每讓一名學生達到該年齡段預期閱讀水平的成本"進行比較：一對一輔導（每生 1,800 英鎊）、小組輔導（每生 700 英鎊）、純數位化介入（每生 150 英鎊，但按報名學生計算的成果達成率，在經參與度流失調整後，僅為小組輔導的 40%）。經實際完成率調整後，純數位化介入每達標學生的成本為 375 英鎊——仍是最便宜的，但 CEA 無法回答：如果以與小組輔導相同的預算投入純數位化方案，那種能幫到的學生絕對數量較少，是否是相對於以更大深度幫到較少學生的一種可接受權衡；這是 CEA 交還給決策者的一項分配性判斷。

## 與軟體工程的關聯

每當工程團隊評估針對*同一*服務成果的不同交付方式時，CEA 都是正確的分析框架——比如在三家身份驗證供應商之間比較每一個成功驗證身份的成本、在兩種個案自動化設計之間比較每一個被正確分診案件的成本、在內部處理與外包補救之間比較每一個已解決無障礙缺陷的成本。它直接可以借鑑的紀律是：在比較成本之前先定義成果單位（不是"已關閉的工單"這種產出，而是"使用者需求真正得到解決"），並且始終計算現行系統與擬議替代方案之間的增量比率，而不是孤立地計算每個系統各自的平均成本。參見[成果與產出](../成果與產出/)與[單位成果成本](../單位成果成本/)。

## 常見陷阱

- **在決定是否擴大規模時比較平均比率而非增量比率。** 正如露宿人數示例所示，平均比率最優的方案，未必是購買下一單位成果最便宜的選擇。
- **選擇實質上是產出而非成果的成果單位。** "已轉介人數"或"已開展的輔導場次"衡量的是活動，而不是專案存在的目的所要產生的成果；對產出進行 CEA 會得出一個看似可信、卻回答了錯誤問題的數位。
- **在真正不同的成果之間進行比較。** CEA 只有在所有方案都針對以相同方式測量的同一成果時才有效；比較"每安置一名露宿者的成本"與"每讓一名離開照護體系的青年獲得穩定租約的成本"需要一個通用的成果測量方法或[多準則決策分析](../多準則決策分析/)，而不是 CEA。
- **忽視成果的永續性。** 一個成本更低、但所產生成果不能持續的方案（比如介入結束後學生成績回退），一旦在可比時間跨度上測量，實際上並不更具成本效果；應在所比較的各方案之間統一跟蹤期。
