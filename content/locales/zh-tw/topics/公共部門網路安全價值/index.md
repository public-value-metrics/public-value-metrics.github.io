# 公共部門網路安全價值

公共部門網路安全價值是一門為風險降低定價的學問：既然安全支出在奏效時不產生任何可見的產出、而在失效時卻會產生非常顯眼的後果，那麼降低公民資料被洩露的可能性究竟值多少錢？對於一項持有福利記錄、健康資料或稅務記錄的服務而言，這種"奏效時不可見"的特性，正是它需要一個明確的價值論證、而不只是一個合規打鉤的原因所在。

## 為何重要

英國國家網路安全中心（National Cyber Security Centre，NCSC）的網路評估框架（Cyber Assessment Framework，CAF），為公共部門組織提供了一套結構化方法，將安全變成一門可評估的、以成果為基礎的學科，而不是一份檢查清單：它定義了四大高層目標（管理安全風險、防範網路攻擊、發現網路安全事件、將事件影響降到最低），並將其拆解為系統所有者可據以接受評估的貢獻性成果，其精神與[數位服務標準](../數位服務標準/)第 9 條（"建立一項能保護使用者隱私的安全服務"）如出一轍。CAF 評估所防範的風險，有據可查的價格標籤：IBM《資料洩露成本報告》按行業跟蹤平均洩露成本，並一貫發現公共部門處於該區間的較低端，低於金融或醫療行業——最近幾版報告將公共部門平均洩露成本定在每次約 260 萬至 290 萬美元——但"低於金融行業"不等於"低"，而且政府洩露事件所承擔的成本，是該報告的數位未能完全捕捉到的：公民對數位渠道的信任受損，會壓低渠道轉移商業案例所依賴的[數位化採用率](../渠道轉移節約/)，還有洩露國家強制公民交出的資料所帶來的政治和法律成本。

## 數學原理

安全投資的估值方式，與任何降低風險的支出一樣：作為預期損失的減少，使用經典的風險管理恆等式。

```
年化損失預期（ALE） = 單次損失預期（SLE）
                     × 年化發生率（ARO）

一項安全控制措施的價值 =
  控制措施實施前的 ALE − 控制措施實施後的 ALE − 該控制措施的年度成本

當以下條件成立時，一項控制措施值得投入資金：
  (ALE_實施前 − ALE_實施後) > 該控制措施的年度成本

CAF 評估本身不會直接輸出一個機率，但一項服務的 CAF
成果概況（哪些貢獻性成果是"已達成""部分達成"或"未達成"）
是估計 ARO 的一個合理代理輸入——一個特權訪問未受管理、
或沒有經過測試的事件回應計劃的系統，其現實的 ARO 會
明顯高於兩者都已到位的系統。
```

## 實例演算

**某郡議會持有 40,000 名居民社會關懷記錄的個案管理系統**：

```
單次損失預期（洩露成本），使用 IBM 近期《資料洩露成本報告》
中的公共部門行業平均值 ≈ 210 萬英鎊
（經貨幣換算，數量級示例數位——應始終從當前版本的報告
重新推導，而不是沿用一個固定數位）

當前 ARO（特權訪問未受管理，沒有經過測試的事件回應計劃，
根據內部 CAF 自我評估顯示多項"未達成"成果）≈ 估計每年 8%
  ALE_實施前 = 210萬英鎊 × 0.08 = 168,000 英鎊/年

擬議控制措施：特權訪問管理 + 經過測試的事件回應計劃，
將相關 CAF 成果提升為"已達成"，估計可將 ARO 降至每年 3%
  ALE_實施後 = 210萬英鎊 × 0.03 = 63,000 英鎊/年

該控制措施的年度成本（工具+流程+測試） = 45,000 英鎊

該控制措施的價值 = (168,000 − 63,000) − 45,000 = 60,000 英鎊/年
  淨收益為正——應予資助。這一算式還顯示，即便成本
  接近現在的三倍，該控制措施依然值得資助，這正是
  任何基於估計機率建置的 ALE 數位都應附帶的那種
  敏感性檢驗。
```

## 與軟體工程的關聯

工程師掌握著 ALE 方程中的大多數槓桿：訪問控制設計、依賴項和補丁管理衛生、日誌與檢測覆蓋率、以及事件回應工具，這些都直接影響 ARO 這一項，這正是 CAF 評估讀起來既像技術架構審查、又像政策審計的原因所在。這是[技術債作為公共價值侵蝕](../技術債作為公共價值侵蝕/)最急性的一種表現形式——未打補丁、未受監控、訪問控制不佳的系統是一種其"利息"以尾部風險而非穩定拖累形式支付的債務——它應當與[政府 IT 中的總擁有成本](../政府-it-中的總擁有成本/)相互核對，避免安全支出被當作與系統真實運作成本無關的獨立專案來對待。它也是《綠皮書》下[物有所值](../物有所值/)評估的直接輸入項：經風險調整的成本是任何方案評估中"成本"一側的組成部分，而不是最後附加上去的事後考量。

## 常見陷阱

- **將 CAF 自我評估當作安全本身。** 一份已完成的評估描述的是一種安全態勢；它本身並不創造這種態勢——價值在於所達成的成果，而不在於這份檔案本身。
- **未經調整就將全球平均洩露成本用作本地估計值。** IBM 的數位是跨越大型、多樣化樣本的平均值；一個小型地方政府現實中的單次損失預期，很少與一箇中央政府部門相同。
- **在投資決策中忽視尾部風險心理。** 較低的年度機率使安全支出很容易被無限期推遲——直到它不再是低機率事件的那一年為止——像實例演算中那樣，針對一系列 ARO 值對 ALE 計算進行敏感性檢驗，可以糾正這種傾向。
- **只計算 IBM 式的洩露成本，而不計算信任成本。** 一次壓低公民使用數位渠道意願的洩露事件，會在此後數年侵蝕[渠道轉移節約](../渠道轉移節約/)的論證基礎，而這項成本很少被計入洩露成本估算之中。
