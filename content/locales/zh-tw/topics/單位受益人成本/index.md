# 單位受益人成本

單位受益人成本，是專案總成本除以接受服務的獨立個人數量——只要被接觸到就算，無論其處境是否真正發生了改變。這是一個組織能夠產出的最快速的效率數位，因為"我們服務了誰"幾乎總是已經存在於個案管理系統之中，而"誰真正得到了幫助"通常則不然。

## 為何重要

資助方經常索要單位受益人成本，而且理由充分：它可以立即獲得，可以在一個由差異極大的專案組成的組合中進行比較，而且在觸達範圍方面是誠實的——這一點是成果類宣告（往往需要更長時間才能核實，也更容易被誇大）所不具備的。英國慈善機構 SORP（推薦慣例宣告，Statement of Recommended Practice）規範了慈善機構在 FRS 102 準則下的報告方式，要求受託人年度報告描述相對於宗旨所取得的成就，但大多數較小的慈善機構在管理賬目中仍預設使用基於觸達範圍的單位成本，因為它們製作成本低廉，也便於審計。

危險之處在於，將單位受益人成本當作它無法回答的問題——這筆錢是否真正發揮了作用——的答案來使用。關於真正回答這一問題的指標，參見[單位成果成本](../單位成果成本/)；關於其背後的區分，參見[成果與產出](../成果與產出/)。單位受益人成本是一項合理的分診與觸達範圍指標——它告訴資助方資金能覆蓋多遠——但一個較低的單位受益人成本，既可能意味著真正的效率，也可能意味著一項服務過於單薄，什麼都沒有改變。

## 數學原理

```
單位受益人成本 = 專案總成本 / 獲得服務的獨立個人數

對照：
單位成果成本      = 專案總成本 / 達成既定成果的人數

單位受益人成本總是 ≤ 單位成果成本，因為達成成果的人群
是受益人群體的一個子集（往往是一個很小的子集）。
```

## 實例演算

**某食物銀行，與單位成果成本示例同一年份**：

- 專案總成本：450,000 英鎊
- 獲得服務的獨立家庭數（獲得三份以上救濟包）：1,800

```
單位受益人成本 = 450,000 英鎊 / 1,800 = 每個獲服務家庭 250 英鎊
```

將兩個指標並排對比：

| 指標 | 分母 | 結果 |
|---|---|---|
| 單位受益人成本 | 1,800 個獲服務家庭 | 250 英鎊 |
| 單位成果成本 | 630 個實現食品保障的家庭 | 714 英鎊 |

一個只看到 250 英鎊的資助方，可能會得出這是一家高效率慈善機構的結論。而一個同時看到兩個數位的資助方，則可以提出更有用的問題：觸達範圍（1,800）與成果（630）之間的差距，究竟是資料收集上的缺口、設計上的缺口，還是對僅憑食品援助實現食品保障究竟有多難這一現實的如實反映？

**某職業培訓慈善機構，示例性資料**：單位受益人成本（已報名）= 2,000 英鎊；單位成果成本（6 個月後持續就業）= 11,000 英鎊，因為只有 18% 的報名者完成了專案並找到了持續性工作。這兩個數位相差五倍，在完成率或永續性偏低的地方十分常見——從這一點來看，一家職業培訓慈善機構與一家食物銀行在結構上並無二致。

## 與軟體工程的關聯

單位受益人成本之所以成為非營利軟體中的預設指標，是因為它是從一條受益人記錄中無需額外工作即可得出的指標：建立一個個案、記錄一次服務、統計行數。要建置一個同樣支援單位成果成本的系統，就意味著要有意新增第二個一等實體——一個獨立於服務交付而被定義和標註日期的成果事件——並抵制讓"個案已關閉"頂替"成果已達成"的誘惑。在規劃撥款管理或 CRM 平臺的範圍時，應當詢問每一塊儀表盤展示的究竟是這兩個指標中的哪一個，並相應地加以標註；在單一的"影響力"圖塊中將兩者混為一談，是導致下文常見陷阱的最常見軟體層面原因之一。關於在正確標註後對任一指標進行基準比較，參見[單位成本資料庫](../單位成本資料庫/)。

## 常見陷阱

- **將單位受益人成本當作影響力來呈現。** 它衡量的是觸達範圍，而不是改變。儀表盤和報告應標註為"每服務人次成本"，而不是"每幫助一人成本"。
- **跨專案重複計算。** 如果分母的目的是描述獨立觸達人數，那麼一個同時接受同一慈善機構食物救濟包和債務諮詢的人，應算作一名受益人，而不是兩名；應確定並記錄所採用的統計慣例。
- **認為數位越低就一定越好。** 一個隨到隨吃的午餐俱樂部，在單位受益人成本上總會勝過一項密集的個案管理服務，因為輕度接觸某人的成本更低。這絲毫說明不了哪一項服務每英鎊能產生更持久的改變。
- **在不同報告之間悄悄更換分母。** 一份年度報告中按"已報名"人數計算的單位受益人成本，與下一份報告中按"已完成"人數計算的數位，年度間不具可比性；每次都應明確說明所用的分母。
