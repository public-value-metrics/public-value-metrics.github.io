# 多準則決策分析（MCDA）

MCDA 同時針對若干個獨立的、加權的標準對各方案進行評分和權衡，產出一個排名比較結果，而不強行將每一項標準都壓縮排一個貨幣或自然單位的尺度中。它是那些真正無法歸約為單一數位的重要成果所對應決策場景的評估方法。

## 為何重要

《綠皮書》明確認可 MCDA（其方框 2 的案例研究附錄和附錄 A 都直接討論了它），用於那些效益"真正不可通約"的評估——即透過[社會成本效益分析](../社會成本效益分析/)將一切折算成貨幣、或透過[成本效果分析](../政府中的成本效果分析/)折算成單一成果，會扭曲而非澄清該決策的情形（<https://www.gov.uk/government/publications/the-green-book-appraisal-and-evaluation-in-central-government>）。例如，為一座新監獄選址，需要在資本成本、社群影響、交通連通性、環境影響和員工招募可行性之間做出權衡——這些標準沒有共同的單位，而強行賦予一個共同單位（通常是貨幣），會把一種關於環境影響相對於成本孰輕孰重的價值判斷，包裝成客觀的算術運算而偷偷帶入。

MCDA 的誠實性同時也是它最大的脆弱之處：因為權重是由負責該評估的人（或一個評審小組）設定的，該方法的合法性完全取決於權重設定過程本身。《綠皮書》指南明確要求，標準和權重必須在對各方案打分*之前*就商定並公佈，正是為了防止評審者從一個已屬意的方案倒推出能夠為其辯護的權重。

## 數學原理

```
對每個方案 i 和每項標準 j：
  分數_ij   = 該方案在該標準上的表現（通常為 0-100 或
              1-10，來自證據、專家判斷或利益相關方評分）
  權重_j    = 標準 j 的相對重要性，各權重之和為 1（或 100）

方案 i 的加權分數 = Σ_j (分數_ij × 權重_j)

流程：
1. 在對任何方案打分之前，先商定標準集合和權重
   （擺動權重法或成對比較法，例如層次分析法 AHP，
   是常見的權重徵詢方法）。
2. 儘可能依據證據，在同一尺度上對每個方案的每一項
   標準進行打分。
3. 計算加權總分；對各方案排序。
4. 對權重進行敏感性檢驗：如果對各標準應有多重要存在
   合理的分歧，排名結果是否依然穩健？
```

MCDA 不像 SCBA 的淨現值那樣產出一個可辯護的絕對數值——它只產出一個以所商定權重為條件的排名。當決策真正涉及在不可通約的多種善之間進行權衡時，這是一個優點；但如果被用來逃避原本可行的、更為艱難的貨幣化工作，這就成了一個缺陷。

## 實例演算

**地方政府**：某議會在為新建家庭廢棄物回收中心選址時，在實地考察之前，由一個跨部門評審小組針對四項標準對三處場地進行了加權評分：

```
標準（權重）：            資本成本(30%)  交通可及性(25%)
                          社群影響(25%)  環境影響(20%)

場地評分（0-100，越高越好）：
場地 A：成本 80，可及性 60，社群 40，環境 70
場地 B：成本 60，可及性 90，社群 70，環境 50
場地 C：成本 90，可及性 50，社群 80，環境 60

加權總分：
場地 A = 80(.30) + 60(.25) + 40(.25) + 70(.20) = 24+15+10+14 = 63
場地 B = 60(.30) + 90(.25) + 70(.25) + 50(.20) = 18+22.5+17.5+10 = 68
場地 C = 90(.30) + 50(.25) + 80(.25) + 60(.20) = 27+12.5+20+12 = 71.5
```

場地 C 排名最高。將社群影響權重從 25% 調升至 35%（從資本成本中扣去 10 個百分點）的敏感性測試，會使場地 C 的總分變為 71.5 − 3 + 8 = 76.5，場地 B 的總分變為 68 − 6 + 7 = 69——場地 C 仍然領先，因此該排名對這種合理的權重分歧具有穩健性，而這正是《綠皮書》期望看到被報告出來的那種檢驗。

**慈善機構**：一家撥款基金會在債務諮詢服務、食物銀行網路和財務素養專案之間進行資助選擇時，使用 MCDA 而非 SROI（參見[社會投資回報](../社會投資回報/)），正是因為受託人們出於善意，在危機救助與預防孰重孰輕的問題上存在分歧——MCDA 讓他們能夠就這一分歧的*形態*（一個權重區間）達成一致，而不是假裝一個單一的 SROI 比率就能解決它。

## 與軟體工程的關聯

當各項標準真正相互衝突時，MCDA 是供應商和架構選型的天然工具——在選擇雲託管與本地部署的個案管理系統之間，需要在成本、資料主權風險、可及性和交付速度之間進行權衡，而這些無法歸約為一個數位。工程負責人應當堅持在對各方案打分之前就完成權重設定，正如《綠皮書》所要求的那樣，因為在看到備選名單之後才進行的權重設定，幾乎必然會向房間裡已經偏好的那個方案漂移。關於 MCDA 的一個常見應用，參見[政府中的自建與外購之爭](../政府中的自建與外購之爭/)；關於一個相關的、在決策*之後*而非決策*之前*使用的結構化評分工具，參見[公共價值計分卡](../公共價值計分卡/)。

## 常見陷阱

- **在看到各方案之後才設定權重。** 這是 MCDA 最常見的被操縱方式，無論是否出於故意；應在打分之前公佈權重，並記錄是誰設定的。
- **將加權總分當作一個硬性數位。** 71.5 對比 68 的分差，除非敏感性分析證實排名是穩定的，否則並不具有統計學意義；應報告區間，而不是虛假的精確度。
- **用 MCDA 來回避本來可行的貨幣化工作。** 如果大多數標準本可以被可信地定價，預設使用 MCDA 而非 [SCBA](../社會成本效益分析/) 會丟棄該評估本可利用的資訊。
- **讓一位占主導地位的利益相關方獨自設定全部權重。** 《綠皮書》的良好實踐期望權重是從一個具有代表性的評審小組中徵詢而來的，而不是來自主辦的負責人，以避免評估結果只是重新推匯出那個人本來就想要的答案。
