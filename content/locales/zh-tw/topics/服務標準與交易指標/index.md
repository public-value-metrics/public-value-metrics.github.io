# 服務標準與交易指標

GOV.UK 服務標準是英國政府用於建置和運作公共數位服務的 14 條檢查清單，與之配套的是一小組強制性的定量交易指標——單筆交易成本、完成率、數位化採用率和使用者滿意度——各團隊必須為每一項線上運作的中央政府服務釋出這些指標。該標準與這些指標合在一起，正是本倉庫中更廣泛的公共價值與關鍵績效指標框架在營運、日常層面的具體化，直接面向軟體交付團隊。

## 為何重要

服務標準維護在 GOV.UK 服務手冊中，要求政府數位服務在每一次時點評估（Alpha、Beta、正式上線）中，在其 14 條款中證明團隊理解使用者需求、以多學科團隊方式工作、頻繁迭代與改進，並*評估工具、系統和工作方式*。歷史上，這與一個公開的 Performance Platform 並存，每項線上服務都在該平臺上公開發布其交易資料；該平臺如今已退役，但透過服務手冊中"衡量成功"的指南，測量併發布這四項核心指標的基本義務依然存在。這與通用軟體關鍵績效指標儀表盤不同的原因在於，這些指標被明確設計為一個相互關聯的單一經濟模型，而不是四個獨立的分數：數位化政府的整個節約論證——政府數位服務局的《數位效率報告》發現，就可比的地方政府服務而言，數位交易的成本大約是電話交易的二十分之一，是面對面交易的五十分之一——只有在完成率保持高位、數位化採用率真正上升的情況下才能實現，而不僅僅是在未改變的昂貴渠道旁邊增加一個廉價渠道。

## 數學原理

```
單筆交易成本   = 服務總運作成本 / 已完成交易數
完成率         = 已完成交易數 / 已開始交易數 × 100
數位化採用率   = 數位渠道交易數 / 所有渠道交易數 × 100
使用者滿意度     = 滿意 + 非常滿意的百分比，服務內 5 級量表調查

渠道轉移節約 = 交易量 × 採用率轉移幅度 × (舊渠道單筆交易成本
              − 數位渠道單筆交易成本)

失敗需求成本 = (1 − 完成率) × 嘗試以數位方式辦理的交易數 ×
              這些使用者轉而使用的備用渠道成本
```

## 實例演算

**示例性的中央政府牌照續期服務**，每年 200 萬筆交易，目前 65% 透過電話辦理（每筆 3.00 英鎊），35% 透過數位方式辦理（每筆 0.30 英鎊），完成率 80%。一次針對 14 條服務標準的重新設計，將數位化採用率提升至 60%，完成率提升至 92%：

```
採用率轉移節約 = 2,000,000 × 0.25 × (3.00 − 0.30) = 1,350,000 英鎊/年

改進前的失敗需求成本：
  2,000,000 × 0.35 × (1 − 0.80) × 3.00 英鎊 = 420,000 英鎊/年
  （放棄辦理者轉回電話渠道）

改進後的失敗需求成本：
  2,000,000 × 0.60 × (1 − 0.92) × 3.00 英鎊 = 288,000 英鎊/年

淨失敗需求節約 = 420,000 − 288,000 = 132,000 英鎊/年

年度總節約 ≈ 1,350,000 + 132,000 = 1,482,000 英鎊/年
```

這一計算清楚地說明了為什麼完成率不是一項次要指標：如果沒有從 80% 提升到 92% 這一改善，採用率轉移帶來的節約，會因失敗需求將沮喪的數位使用者直接轉回昂貴的電話渠道而被部分抵消。

## 與軟體工程的關聯

這四項指標是一個成本-後果儀表盤的實例：一項成本指標與三項成果/品質指標分開呈現，刻意不將其壓縮成單一分數——這與[公共部門關鍵績效指標](../公共部門關鍵績效指標/)中所論證的紀律相同。對工程師而言，這分解成了具體的、可擔責的工作：完成率是一個漏斗儀表化問題，旅程中的每一個放棄節點原則上都是可定位、可修復的；單筆交易成本需要真正的單位成本核算，包括人工輔助渠道和紙質渠道的成本，而不僅僅是雲託管支出（參見[單筆交易成本](../單筆交易成本/)和[政府 IT 中的總擁有成本](../政府-it-中的總擁有成本/)）；而數位化採用率則是一個披著效率外衣的公平性指標——那些無法或不願轉換渠道的公民，不成比例地更可能是老年人、殘障人士或數位弱勢群體，因此激進地關閉渠道，會把一筆"節約"變成一次可及性損害（參見[數位包容](../數位包容/)和[渠道轉移節約](../渠道轉移節約/)）。這 14 條款標準本身，正是這些數位背後的流程規範——完整標準參見[數位服務標準](../數位服務標準/)；關於此處的滿意度數位與更廣泛的信任測量之間的關係，參見[公民滿意度指標](../公民滿意度指標/)。

## 常見陷阱

- **透過關閉替代渠道來獲得採用率提升**：關閉一條電話線會在算術上拉高數位化採用率百分比，同時將失敗需求轉嫁給剩下的渠道（往往是更昂貴的輔助數位或面對面渠道）；應始終測量整個系統的總成本，而不僅僅是這個比率本身。
- **從漏斗的第二步開始測量完成率**：在第一個真正的流失點之後才開始計算"已開始"數位，會美化完成率，並掩蓋最大的一處可修復損失。
- **單筆交易成本排除輔助數位支援**：一個僅計算純數位渠道的單位成本、忽略了幫助無法自助辦理使用者所花費的人員工時，會低估該渠道的真實成本。
- **在沒有跨服務共享定義的情況下發布指標**：除非"交易"和"已完成"這類定義在各服務團隊之間經過標準化並有版本管理，否則其含義在不同團隊之間會有所不同，使跨服務比較不可靠。
