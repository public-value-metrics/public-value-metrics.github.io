# 開放資料的價值

開放資料的價值，是一個在政府和公共資料沒有價格的情況下估算其價值的問題：它不被出售，因此沒有收入科目，但釋出它（氣象記錄、交通時刻表、郵編邊界、公司註冊資訊）明顯會在下游產生經濟和社會活動。恰當地為其估值之所以重要，是因為"釋出它不花錢"和"它毫無價值"這兩種說法都是錯誤的，而一位正在決定是否開放某個 API 或資料集的軟體工程師，需要比這兩種說法更好的論據。

## 為何重要

被引用最多的自上而下估算，來自麥肯錫全球研究院（McKinsey Global Institute）2013 年的報告《開放資料：用流動資訊釋放創新與績效》（"Open data: Unlocking innovation and performance with liquid information"），該報告估計，在教育、交通、消費品、電力、石油天然氣、醫療保健和消費金融這七個領域，全球開放資料的潛在年價值達 3 萬億至 5 萬億美元，實現機制包括提高透明度、更高效地匹配供需，以及支援基於資料建置的新產品和新服務。這一數位是一個情景估計，而非一個已實測的成果，但它常常被錯誤引用，彷彿這是政府可以直接獲取的收入，而實際上，這種價值大部分累積到了使用這些資料的第三方——企業、研究人員、公民——身上，而這正是開放資料、而非出售資料的意義所在。英國開放資料研究所（Open Data Institute）由 Tim Berners-Lee 爵士和 Nigel Shadbolt 爵士於 2012 年共同創立，此後積累了一批更細緻、自下而上的案例研究——按行業、按資料集逐一分析——這些研究對於建置一份真正的商業案例而言，比麥肯錫的頭條數位有用得多，因為它們展示的是價值創造的機制，而不僅僅是其彙總規模。

## 數學原理

開放資料沒有市場價格，因此需要替代性的估值方法；有三種方法反覆出現，但任何一種單獨使用都不充分：

```
1. 成本規避/替代成本法：
   價值 ≈ 使用者如果自行生產或授權獲取等價資料本會
   支付的成本——這是一個下限，忽略了原始生產者
   從未預見到的用途所創造的價值

2. 市場類比/下游活動法：
   價值 ≈ 基於該資料建置的企業/服務所產生的收入或
   節約（例如基於開放地圖和交通資料建置的導航應用）
   ——捕捉到了真實的經濟活動，但很難乾淨利落地
   將其歸因於資料釋出本身（參見 additionality-and-deadweight）

3. 或有/陳述性偏好法：
   價值 ≈ 使用者聲稱他們願意為此支付的金額，或聲稱
   為其節省的時間——關於通用方法及其偏差，參見
   stated-preference-valuation

以上任何一種方法都無法產出像市場價格那樣乾淨利落的數位；
可信的開放資料商業案例會綜合運用兩種或以上方法，並明確
說明是哪種機制在起作用。
```

## 實例演算

**示例性的全國地圖/地址資料釋出**（方法參照 ODI 式案例研究，數位為此類研究通常發現的規模的示例）：

```
成本規避估算：
  原本需要商業授權獲取等價地址匹配資料的企業，
  估計平均授權成本為每年 4,000 英鎊，估計有 15,000
  家中小企業現在使用這份免費的開放資料集
  = 15,000 × 4,000 英鎊 = 60,000,000 英鎊/年
  ——僅避免的授權費用一項

下游活動估算（更具推測性，需要一個反事實情形）：
  基於該開放資料建置的、若無該資料便不會存在或會
  明顯遜色的新配送路線規劃和物流產品——需要與資料
  保持封閉或商業授權的反事實情形相比較
  （counterfactual-analysis），因為其中一部分活動
  無論如何都會發生，只是要以更高價格使用付費資料，
  這在"開放所創造的價值"意義上屬於無謂損失

一份站得住腳的商業案例，會將成本規避數位作為可靠的
下限來報告，並將下游活動數位視為一個上限情景，而非
一個事實。
```

## 與軟體工程的關聯

對工程師而言，實際的開放資料價值問題通常比全國性的頭條數位要窄得多：開放這個具體的 API 或資料集（而不是將其保留在合作伙伴協議背後），是否能帶來足夠的複用增量，從而證明將其作為公共介面進行持續檔案編制、版本管理和支援所需的成本是合理的？這項維護成本是真實存在的，也正是[政府即平臺](../政府即平臺/)"一次建置、反覆複用"經濟學的對應物——這兩個主題是近親，一個關於共享程式碼和基礎設施，另一個關於共享資料。任何開放資料價值宣告，在被寫入商業案例之前，都應對照[增益性與無謂損失](../增益性與無謂損失/)加以檢驗：那些無論如何都會發生、只是使用商業授權資料的活動，並不是"開放"這一行為所創造的價值。

## 常見陷阱

- **將麥肯錫 3 萬億至 5 萬億美元的數位當作英國專屬數位或當作某一具體資料集的份額來引用**：這是一個 2013 年針對全球七個行業的情景估算——將其作為單一國家資料集的精確乘數使用，會曲解這個數位本來的含義。
- **沒有反事實情形**：將所有基於開放資料的下游經濟活動都歸功於開放本身，而不追問其中有多少無論如何都會發生，只是要以更高價格使用付費或授權資料（參見[增益性與無謂損失](../增益性與無謂損失/)和[反事實分析](../反事實分析/)）。
- **將生產成本與所創造的價值相混淆**：一個採整合本高昂的資料集，未必釋出起來就自動有價值；一個廉價的資料集，也未必自動價值低——價值取決於下游使用情況，而不是上游成本。
- **忽視"開放"所帶來的持續維護成本**：釋出一次性的 CSV 資料匯出，與運作一個有檔案、有版本管理、有支援的開放 API，是完全不同程度的承諾——在啟動公告之後對後者投入不足，是一種常見的失敗模式。
