# 社会成本效益分析（Social Cost-Benefit Analysis, SCBA）

社会成本效益分析，将一项政策或项目的每一项成本和效益——无论是否具有市场性——都换算成一个共同的货币单位，将未来的流量折现为现值，再相减得出一个单一数字：这项提案是否让社会变得更好，好了多少？

## 为何重要

SCBA 是[绿皮书评估](../green-book-appraisal/)经济论证中的默认定量方法：财政部指南要求，只要效益能够被可信地货币化，提案就必须证明其净现值社会价值（NPSV）为正，并以支付意愿作为非市场性物品估值的基本原则（<https://www.gov.uk/government/publications/the-green-book-appraisal-and-evaluation-in-central-government>，第五章）。它所强制推行的纪律是："社会"成本效益分析与私营部门的投资评估并不是同一回事：它必须涵盖落在非交易方第三方身上的成本和效益（外部性），必须使用[社会折现率](../social-discount-rate/)而非商业资本成本，并应在一英镑对贫困家庭比对富裕家庭意义更大的场合应用[分布性加权](../distributional-weighting/)。

SCBA 崩溃的地方恰恰是其批评者所预料的：没有市场类比物的商品——清洁空气、社会凝聚力、挽救一条生命的价值——必须使用[陈述性偏好](../stated-preference-valuation/)或[显示性偏好](../revealed-preference-valuation/)方法来货币化，或者必须构建一个[影子价格](../shadow-pricing/)。当货币化不仅仅是困难、而是存在争议时，《绿皮书》自身建议退回到[成本效果分析](../cost-effectiveness-analysis-in-government/)或[多准则决策分析](../multi-criteria-decision-analysis/)，而不是强行给出一个无人相信的数字。

## 数学原理

```
NPSV = Σ [t=0 到 T] (效益_t − 成本_t) / (1 + r)^t

其中：
  效益_t = 第 t 年所有已货币化的效益，包括通过陈述性/
           显示性偏好或影子价格估值的非市场性物品
  成本_t = 第 t 年所有已货币化的成本，包括资源的机会成本
           （参见 ../opportunity-cost-in-public-spending/）
  r      = 社会折现率（财政部设定为 3.5%，第 30 年之后按
           《绿皮书》附录 A 降至更低利率）
  T      = 评估周期

效益成本比（BCR） = Σ PV(效益) / Σ PV(成本)
```

BCR 高于 1（或 NPSV 高于零）表示净社会价值为正。《绿皮书》的物有所值分类（用于交通和基础设施评估）为 BCR 区间设定了标签：低于 1.0 为物有所值差，1.0–1.5 为低，1.5–2.0 为中等，2.0–4.0 为高，高于 4.0 为极高。敏感性分析——在悲观和乐观假设下重新运行 NPSV 计算——是强制性的，而非可选项，因为已货币化的非市场性效益带有很宽的不确定性区间。

## 实例演算

**地方政府**：某议会对一项 300 万英镑的骑行与步行网络投资进行评估，评估周期为 20 年，折现率 3.5%。

```
成本：第 0 年资本支出 300 万英镑，第 1-20 年每年维护费 50,000 英镑
PV(维护) ≈ 50,000 × 14.2（20年期3.5%年金系数）≈ 710,000 英镑
总 PV(成本) ≈ 371万英镑

效益（均通过已发布的交通部/世卫组织估值工具货币化）：
  体力活动增加带来的健康效益：180,000 英镑/年
  缺勤减少：40,000 英镑/年
  拥堵缓解（减少汽车出行）：60,000 英镑/年
  效益流合计：280,000 英镑/年
PV(效益) ≈ 280,000 × 14.2 ≈ 398万英镑

NPSV = 398万 − 371万 = +27万英镑
BCR = 3.98 / 3.71 = 1.07 → "低"物有所值
```

该方案勉强通过了门槛，但也仅仅是勉强通过；一项将健康效益估计下调 20%（反映体力活动估值中真实存在的不确定性）的敏感性测试，会使 BCR 翻转到 1.0 以下，这正是《绿皮书》要求将敏感性表格与头条数字一并公布、而不仅仅是公布中心估计值的原因所在。

**慈善机构**：一项每年耗资 50 万英镑的婴儿死亡率预防项目，使用统计生命价值（VSL，一个影子价格，而非观测到的市场价格）约 210 万英镑（财政部 2023 年更新的数字，本身也源自陈述性偏好研究）进行评估。以 50 万英镑的成本每年避免一例婴儿死亡，得出 BCR 为 4.2，轻松达到"极高"物有所值——但整个结果都建立在 VSL 这个数字之上，这正是任何使用 VSL 的 SCBA 都必须将其作为一项假设、而非一个事实来披露的原因。

## 与软件工程的关联

SCBA 是政府软件中平台和基础设施投资决策的天然框架——例如，将一个共享身份验证平台与各部门各自为政的解决方案相比较，需要将诸如减少重复入职成本、减少欺诈、更快的服务上线时间等本身没有市场价格的效益货币化。构建底层服务的工程师，应当预期项目负责人会要求提供这一分析所需的输入：交易的单位成本（参见[单笔交易成本](../cost-per-transaction/)）、预期交易量，以及性能下降/停机成本。最值得借鉴的纪律是：对未来效益进行折现，明确指出反事实基线（参见[反事实分析](../counterfactual-analysis/)），并且绝不在没有敏感性区间的情况下只呈现一个单点估计。

## 常见陷阱

- **效益重复计算。** 将"节省的时间"和"由此获得的生产力提升"都作为独立的效益项来计算，会夸大论证；节省的时间本身就是效益，其下游用途除非有独立证据支持，否则不是一项额外效益。
- **遗漏被转移的成本。** 一个将拥堵从一条道路转移到另一条道路、或将欺诈从一个渠道转移到另一个渠道的方案，并没有创造其头条 NPSV 所暗示的净效益——参见[置换与归因](../displacement-and-attribution/)。
- **使用私营部门折现率。** 使用商业资本成本（比如 8–10%）而非社会折现率，会系统性地低估健康和环境收益等长周期公共效益的价值——参见[社会折现率](../social-discount-rate/)。
- **将无争议的部分货币化、对有争议的部分含糊其辞。** 如果一项提案三分之二的效益是一项被自信地货币化的效率节约，而三分之一是一项估值不稳固的福祉增益，头条 NPSV 就会在不知不觉中将一个硬数字与一个软数字混合在一起；应分开报告两者。
