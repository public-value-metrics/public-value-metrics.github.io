# 技术债作为公共价值侵蚀（Technical Debt as Public Value Erosion）

技术债是 Ward Cunningham 在 1992 年提出的隐喻，用以描述过去权宜性编码决策所隐含的未来成本：一笔**本金**（所欠下的整改工作）和一份**利息**（它对交付施加的持续拖累）。在一个遗留的政府 IT 资产中，这份利息是直接从公共价值中支付的——更慢的法定变更交付速度、面向公民服务更高的失败率，以及一个能够安全触碰该系统的人才库正日益萎缩。

## 为何重要

英国各政府部门的遗留大型机和 COBOL 时代系统——其中最常被提及的是税务海关总署（HMRC）和就业与养老金部（DWP）——承载着国家审计署反复标注的、有充分记录且不断升级的风险，包括在其《政府数字化转型》（*Digital Transformation in Government*，<https://www.nao.org.uk/>）报告中所指出的：老化的平台变更成本高昂、安全保障日益困难，并依赖于一支退休速度快于补充速度的专业人才队伍。与私营部门的积压不同，这笔债务直接横亘在公民与其法定权益之间——一个无法被安全变更的福利计算引擎，是一项政策交付层面的约束，而不仅仅是工程上的不便。2013 年 Universal Credit IT 项目的重启——当时国家审计署发现原始构建方案无法实现物有所值，相当一部分软件资产不得不被注销——是未被定价的技术债追上一个部长级公众可见的在办公共项目的典型例证。

## 数学原理

```
SQALE 本金 = Σ 各违规项 (整改时间) × 开发者成本费率
技术债比率（TDR） = 整改成本 / 重新开发成本 × 100
                   （SonarQube 分级：A ≤5%，B ≤10%，C ≤20%，D ≤50%）

利息（为偿还债务提供理由的数字）：
  年利息 = Δ交付速度 × 单位速度价值
         + Δ面向公民事件率 × 单位事件成本
         + 专业技能溢价 × 受影响人头数
偿还方案 = PV(评估周期内避免的利息) − 整改成本
          （按《绿皮书》社会折现率折现，参见
          social-discount-rate.md）
```

本金陈述的是负债；利息才是向公共账目委员会证明该投资合理性的数字。

## 实例演算

一个用遗留第四代语言编写的 25 万行理赔处理引擎。使用 CAST Appmarq 基准，每行代码约 3.61 美元的技术债本金（按常见汇率折算约 2.85 英镑）：

```
本金 ≈ 250,000 × 2.85 英镑 ≈ 712,500 英镑
TDR ≈ 16%（C 级）
```

已测量的利息：该部门保留了三名专业合同工，其日薪比标准高级工程师高出 40%，因为内部技能已经流失——一个六人团队因此每年多花费 180,000 英镑。该系统每年还导致四次重大处理中断，每次都使约 5,000 名申领人的决定被暂停，并将他们转向呼叫中心，每通电话成本约 25 英镑：

```
利息 ≈ 180,000 英镑（技能溢价）
     + 4 × 5,000 × 25 英镑 = 500,000 英镑（转移接触成本）
     ≈ 680,000 英镑/年
```

针对表现最差模块的定向整改，成本为 1,200,000 英镑，建模预计可削减 70% 的利息：

```
利息削减 = 0.70 × 680,000 = 476,000 英镑/年
回收期 ≈ 1,200,000 / 476,000 ≈ 2.5 年
```

定向性很重要：整改极少被触碰的代码毫无收益，因为利息集中在变更频率和债务密度都达到峰值的地方。

## 与软件工程的关联

将技术债论证提升到超越"代码老旧"层次的公共价值框架是：将遗留资产表述为一份"已损失交付能力集中在何处"的清单，并将其明确与[总拥有成本](../total-cost-of-ownership-in-government-it/)关联起来，因为无论财务部门是否曾要求过，利息都是应当计入总拥有成本科目的一项运营成本。负债累累的系统也带有不成比例的[网络安全](../public-sector-cybersecurity-value/)暴露风险，因为补丁节奏与债务密度是相关的——一个无法打补丁的遗留系统，其技术债的利息是以事件风险、而非英镑的形式支付的。而每一次整改与新功能之间的权衡取舍，本身就是一项[延迟成本](../cost-of-delay-in-public-programmes/)决策：偿还债务会推迟下一次法定变更，而后者本身也有其延迟成本，必须与所节省的利息相权衡。

## 常见陷阱

- **只报告本金。** 一个庞大、令人担忧的整改估算，如果没有配套的利息数字，无法向支出审批人证明任何合理性。
- **将工具生成的债务数字照单全收。** SQALE 式扫描工具统计的是规则违规；它们会遗漏最昂贵的那类债务——架构决策和未被记录的遗留业务规则——却会标注一些琐碎细节。
- **"推倒重写能避免这一切"。** 替代方案项目必须经受住与任何其他商业论证同样的纪律考验——反事实成本、成功概率和折现——而不能豁免于此，2013 年 Universal Credit 的重启就证明了这一点。
- **零债务的乌托邦主义。** 最优的债务水平不是零；债务是一种曾经换来更早交付的杠杆。真正的问题永远是利率是多少，而不是债务是否存在。
