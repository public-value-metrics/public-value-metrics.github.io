# 单笔交易成本（Cost Per Transaction）

单笔交易成本，是政府数字服务的头条单位经济性指标：交付某一渠道的总成本，除以通过该渠道完成的交易数量。它曾是旧版 GOV.UK Performance Platform 上的旗舰数字，也是资助了十年"数字优先"投资的那个数字——而这正是它也最容易被操纵的原因所在。

## 为何重要

内阁办公室（Cabinet Office）2012 年的《数字效率报告》（Digital Efficiency Report）以一种令人印象深刻的方式给出了渠道成本比较：数字交易的成本被发现约为电话渠道的二十分之一、约为面对面渠道的五十分之一，地方政府的示例数字大致为每笔网络交易 0.15 英镑，对比每笔电话交易 2.83 英镑和每笔面对面交易 8.62 英镑。这一单一比较，成为了重新设计《政府数字战略》（Government Digital Strategy）中所列 25 项示范服务的理由，也成为此后每一份引用渠道转移节约的部门商业论证的依据。作为一个数量级信号，这个数字确实有用，但其比率完全取决于双方各自计入了哪些内容：一个公允的电话渠道成本应包括呼叫中心的人员、电话合同、培训和场地；一个公允的数字渠道成本应包括托管费用、持续性的产品团队薪酬、办理失败旅程所需的支持台工时，以及[数字服务标准](../digital-service-standard/)第 5 条所要求的辅助数字渠道。只要从数字一侧剔除足够多这类成本，任何服务看起来都会很便宜。

## 数学原理

```
单笔交易成本 = 渠道总分摊成本 / 已完成交易数

渠道总分摊成本应包括：
  + 托管与基础设施
  + 产品/工程/支持团队成本（摊销）
  + 内容与服务设计成本（摊销）
  + 辅助数字/无障碍支持成本
  + 失败需求成本（数字渠道办理失败、转回电话的用户）
  − 一次性建设成本应按预期服务生命周期摊销，
    而不是全部计入第一年费用

常见的会计花招：
  将"边际单笔交易成本"（建成后仅计托管费用）当作
  "平均单笔交易成本"（包含持续构建与运行该服务的
  团队在内的总成本）来引用。对于拥有庞大、活跃交付
  团队的服务而言，两者可相差 10 倍甚至更多。
```

## 实例演算

**车辆税续期服务**：每年 400 万笔交易。

```
仅边际成本数字（花招版）：
  仅托管费+支付处理 = 180,000 英镑/年
  单笔交易成本 = 180,000 / 4,000,000 = 0.045 英镑
  → 在商业论证中引用的头条数字

全成本数字（诚实版）：
  托管+支付                        180,000 英镑
  产品/工程团队（8 名全职员工）     720,000 英镑
  支持台（失败/咨询交易）           310,000 英镑
  辅助数字电话热线                  140,000 英镑
  合计                            1,350,000 英镑
  单笔交易成本 = 1,350,000 / 4,000,000 = 0.3375 英镑

全成本数字仍然比《数字效率报告》中 2.83 英镑的电话渠道
对照数字便宜约 8 倍——这是一笔真实且站得住脚的节省——
但比捷径版本中引用的仅边际成本数字高出 7.5 倍。两个数字
都是"真实的"；但只有一个数字才能与它所对照的电话渠道
成本相比较。
```

## 与软件工程的关联

单笔交易成本正是架构决策转化为财务数字的地方：一项能够平稳自动扩展、几乎不需要人工干预的服务，会随着时间推移压低这个数字；而一项因令人困惑的错误状态而产生大量支持工单的服务，无论托管效率多高，都会推高这个数字。它是[数字服务标准](../digital-service-standard/)第 10 条（"定义成功的样子，并发布性能数据"）以及[服务标准与交易指标](../service-standards-and-transaction-metrics/)（其中列出了这一数字所属的更完整关键绩效指标集合）的天然搭档指标。它还直接输入到[渠道转移节约](../channel-shift-savings/)的计算之中，并应与[政府 IT 中的总拥有成本](../total-cost-of-ownership-in-government-it/)相互核对，以确保平台与共享服务的间接成本不会被悄悄遗漏。

## 常见陷阱

- **将边际成本包装成平均成本**：在服务建成后只引用仅托管成本的数字，遗漏了持续维护、迭代和支持它的团队——参见上文的实例演算。
- **排除辅助数字成本**：如果[数字包容](../digital-inclusion/)所要求的电话/纸质备用渠道被单独计价或被忽略，那么一个渠道就不符合"数字优先"的要求，其真实成本也未被真正捕获。
- **忽视失败需求**：以数字方式开始办理却失败、进而仍然产生一通电话或一份纸质表格的交易，其成本应算在数字渠道头上，而不是算在接住这次失败的渠道头上。
- **在不同复杂度的交易之间跨渠道比较**：电话不成比例地处理更多疑难案例（多个受抚养人、纠错、弱势申请人）；除非交易组合是匹配的，否则将平均电话成本与平均数字成本相比较会夸大两者的比率。
