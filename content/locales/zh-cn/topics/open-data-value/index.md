# 开放数据的价值（Open Data Value）

开放数据的价值，是一个在政府和公共数据没有价格的情况下估算其价值的问题：它不被出售，因此没有收入科目，但发布它（气象记录、交通时刻表、邮编边界、公司注册信息）明显会在下游产生经济和社会活动。恰当地为其估值之所以重要，是因为"发布它不花钱"和"它毫无价值"这两种说法都是错误的，而一位正在决定是否开放某个 API 或数据集的软件工程师，需要比这两种说法更好的论据。

## 为何重要

被引用最多的自上而下估算，来自麦肯锡全球研究院（McKinsey Global Institute）2013 年的报告《开放数据：用流动信息释放创新与绩效》（"Open data: Unlocking innovation and performance with liquid information"），该报告估计，在教育、交通、消费品、电力、石油天然气、医疗保健和消费金融这七个领域，全球开放数据的潜在年价值达 3 万亿至 5 万亿美元，实现机制包括提高透明度、更高效地匹配供需，以及支持基于数据构建的新产品和新服务。这一数字是一个情景估计，而非一个已实测的成果，但它常常被错误引用，仿佛这是政府可以直接获取的收入，而实际上，这种价值大部分累积到了使用这些数据的第三方——企业、研究人员、公民——身上，而这正是开放数据、而非出售数据的意义所在。英国开放数据研究所（Open Data Institute）由 Tim Berners-Lee 爵士和 Nigel Shadbolt 爵士于 2012 年共同创立，此后积累了一批更细致、自下而上的案例研究——按行业、按数据集逐一分析——这些研究对于构建一份真正的商业论证而言，比麦肯锡的头条数字有用得多，因为它们展示的是价值创造的机制，而不仅仅是其汇总规模。

## 数学原理

开放数据没有市场价格，因此需要替代性的估值方法；有三种方法反复出现，但任何一种单独使用都不充分：

```
1. 成本规避/替代成本法：
   价值 ≈ 用户如果自行生产或授权获取等价数据本会
   支付的成本——这是一个下限，忽略了原始生产者
   从未预见到的用途所创造的价值

2. 市场类比/下游活动法：
   价值 ≈ 基于该数据构建的企业/服务所产生的收入或
   节约（例如基于开放地图和交通数据构建的导航应用）
   ——捕捉到了真实的经济活动，但很难干净利落地
   将其归因于数据发布本身（参见 additionality-and-deadweight）

3. 或有/陈述性偏好法：
   价值 ≈ 用户声称他们愿意为此支付的金额，或声称
   为其节省的时间——关于通用方法及其偏差，参见
   stated-preference-valuation

以上任何一种方法都无法产出像市场价格那样干净利落的数字；
可信的开放数据商业论证会综合运用两种或以上方法，并明确
说明是哪种机制在起作用。
```

## 实例演算

**示例性的全国地图/地址数据发布**（方法参照 ODI 式案例研究，数字为此类研究通常发现的规模的示例）：

```
成本规避估算：
  原本需要商业授权获取等价地址匹配数据的企业，
  估计平均授权成本为每年 4,000 英镑，估计有 15,000
  家中小企业现在使用这份免费的开放数据集
  = 15,000 × 4,000 英镑 = 60,000,000 英镑/年
  ——仅避免的授权费用一项

下游活动估算（更具推测性，需要一个反事实情形）：
  基于该开放数据构建的、若无该数据便不会存在或会
  明显逊色的新配送路线规划和物流产品——需要与数据
  保持封闭或商业授权的反事实情形相比较
  （counterfactual-analysis），因为其中一部分活动
  无论如何都会发生，只是要以更高价格使用付费数据，
  这在"开放所创造的价值"意义上属于无谓损失

一份站得住脚的商业论证，会将成本规避数字作为可靠的
下限来报告，并将下游活动数字视为一个上限情景，而非
一个事实。
```

## 与软件工程的关联

对工程师而言，实际的开放数据价值问题通常比全国性的头条数字要窄得多：开放这个具体的 API 或数据集（而不是将其保留在合作伙伴协议背后），是否能带来足够的复用增量，从而证明将其作为公共接口进行持续文档编制、版本管理和支持所需的成本是合理的？这项维护成本是真实存在的，也正是[政府即平台](../government-as-a-platform/)"一次构建、反复复用"经济学的对应物——这两个主题是近亲，一个关于共享代码和基础设施，另一个关于共享数据。任何开放数据价值声明，在被写入商业论证之前，都应对照[增益性与无谓损失](../additionality-and-deadweight/)加以检验：那些无论如何都会发生、只是使用商业授权数据的活动，并不是"开放"这一行为所创造的价值。

## 常见陷阱

- **将麦肯锡 3 万亿至 5 万亿美元的数字当作英国专属数字或当作某一具体数据集的份额来引用**：这是一个 2013 年针对全球七个行业的情景估算——将其作为单一国家数据集的精确乘数使用，会曲解这个数字本来的含义。
- **没有反事实情形**：将所有基于开放数据的下游经济活动都归功于开放本身，而不追问其中有多少无论如何都会发生，只是要以更高价格使用付费或授权数据（参见[增益性与无谓损失](../additionality-and-deadweight/)和[反事实分析](../counterfactual-analysis/)）。
- **将生产成本与所创造的价值相混淆**：一个采集成本高昂的数据集，未必发布起来就自动有价值；一个廉价的数据集，也未必自动价值低——价值取决于下游使用情况，而不是上游成本。
- **忽视"开放"所带来的持续维护成本**：发布一次性的 CSV 数据导出，与运行一个有文档、有版本管理、有支持的开放 API，是完全不同程度的承诺——在启动公告之后对后者投入不足，是一种常见的失败模式。
