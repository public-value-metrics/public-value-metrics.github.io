# คุณค่าของข้อมูลเปิด

คุณค่าของข้อมูลเปิดคือปัญหาการประมาณว่าข้อมูลภาครัฐและข้อมูลสาธารณะมีมูลค่าเท่าใดเมื่อไม่มีราคา: ไม่ได้ขาย จึงไม่มีรายการรายได้ แต่การเปิดเผย (บันทึกสภาพอากาศ ตารางเวลาการคมนาคม เขตรหัสไปรษณีย์ ทะเบียนบริษัท) สร้างกิจกรรมทางเศรษฐกิจและสังคมปลายน้ำได้อย่างปรากฏชัด การประเมินมูลค่าให้ดีสำคัญเพราะทั้ง "เปิดเผยฟรี" และ "ไร้ค่า" ผิดทั้งคู่ และวิศวกรซอฟต์แวร์ที่ตัดสินใจว่าจะเปิด API หรือชุดข้อมูลหรือไม่ต้องการเหตุผลที่ดีกว่าทั้งสองอย่าง

## เหตุใดจึงสำคัญ

ประมาณการจากบนลงล่างที่ถูกอ้างถึงมากที่สุดมาจากรายงานปี 2013 ของ McKinsey Global Institute เรื่อง "Open data: Unlocking innovation and performance with liquid information" ซึ่งประเมินมูลค่ารายปีที่เป็นไปได้ของข้อมูลเปิดข้ามเจ็ดสาขา — การศึกษา การขนส่ง สินค้าอุปโภคบริโภค ไฟฟ้า น้ำมันและก๊าซ การดูแลสุขภาพ และการเงินผู้บริโภค — ที่ 3 ถึง 5 ล้านล้านดอลลาร์ต่อปีทั่วโลก ผ่านกลไกรวมถึงความโปร่งใสที่เพิ่มขึ้น การจับคู่อุปทานกับอุปสงค์ที่มีประสิทธิภาพกว่า และการเปิดทางให้ผลิตภัณฑ์และบริการใหม่ที่สร้างบนข้อมูล ตัวเลขนั้นเป็นประมาณการตามสถานการณ์ ไม่ใช่ผลลัพธ์ที่วัดได้ และมักถูกอ้างผิดราวกับเป็นรายได้ที่รัฐบาลจับได้โดยตรง ทั้งที่คุณค่าส่วนใหญ่ตกกับบุคคลที่สาม — ธุรกิจ นักวิจัย ประชาชน — ที่ใช้ข้อมูล ซึ่งเป็นประเด็นของการเปิดเผยแทนการขาย Open Data Institute ของสหราชอาณาจักร ซึ่งก่อตั้งร่วมโดย Sir Tim Berners-Lee และ Sir Nigel Shadbolt ในปี 2012 ได้สร้างชุดกรณีศึกษาจากล่างขึ้นบนที่ละเอียดกว่า — รายภาคส่วน รายชุดข้อมูล — ซึ่งมีประโยชน์กว่าตัวเลขพาดหัวของ McKinsey มากสำหรับกรณีทางธุรกิจจริง เพราะแสดงกลไกการสร้างคุณค่า ไม่ใช่เพียงขนาดรวม

## คณิตศาสตร์

ข้อมูลเปิดไม่มีราคาตลาด วิธีการประเมินมูลค่าจึงเข้ามาแทน; สามแนวทางเกิดซ้ำ และไม่มีแนวทางใดเพียงพอโดยลำพัง:

```
1. วิธีต้นทุนที่หลีกเลี่ยงได้ / ต้นทุนทดแทน:
   มูลค่า ≈ สิ่งที่ผู้ใช้จะจ่ายเพื่อผลิตหรือซื้อสิทธิ์ใช้
   ข้อมูลเทียบเท่าด้วยตนเอง — ขอบเขตล่าง ละเลยมูลค่าที่เกิดจาก
   การใช้งานที่ผู้ผลิตเดิมไม่เคยคาดคิด

2. วิธีเทียบเคียงตลาด / กิจกรรมปลายน้ำ:
   มูลค่า ≈ รายได้หรือการประหยัดที่ธุรกิจ/บริการซึ่งสร้างบนข้อมูลก่อให้เกิด
   (เช่น แอปนำทางที่สร้างบนข้อมูลแผนที่และจราจรแบบเปิด) — จับกิจกรรมเศรษฐกิจจริง
   แต่ระบุที่มาให้ชัดกับการเปิดเผยข้อมูลเองได้ยาก (ดู additionality-and-deadweight)

3. วิธีเชิงเงื่อนไข/ความพึงพอใจที่แถลง:
   มูลค่า ≈ สิ่งที่ผู้ใช้บอกว่าจะยอมจ่าย หรือเวลาที่เขาบอกว่าประหยัดได้ —
   ดู stated-preference-valuation สำหรับวิธีทั่วไปและอคติของมัน

ไม่มีวิธีใดให้ตัวเลขสะอาดเท่าราคาตลาด; กรณีทางธุรกิจของข้อมูลเปิดที่น่าเชื่อถือ
ตรวจสอบสามเส้าข้ามอย่างน้อยสองวิธี และชัดเจนว่ากลไกใดทำงานอยู่
```

## ตัวอย่างการคำนวณ

**ตัวอย่างการเปิดเผยข้อมูลแผนที่/ที่อยู่ระดับชาติ** (ระเบียบวิธีตามกรณีศึกษาแบบ ODI ตัวเลขเป็นตัวอย่างของขนาดที่การศึกษาเหล่านี้มักพบ):

```
ประมาณการต้นทุนที่หลีกเลี่ยงได้:
  ธุรกิจที่มิฉะนั้นจะซื้อสิทธิ์ใช้ข้อมูลจับคู่ที่อยู่เทียบเท่าเชิงพาณิชย์
  ที่ค่าสิทธิ์เฉลี่ยโดยประมาณ 4,000 ปอนด์/ปี ข้าม SME ที่ประมาณการไว้
  15,000 รายที่ใช้ชุดข้อมูลเปิดฟรีในปัจจุบัน
  = 15,000 × 4,000 ปอนด์ = 60,000,000 ปอนด์/ปี จากค่าสิทธิ์ที่หลีกเลี่ยงได้เท่านั้น

ประมาณการกิจกรรมปลายน้ำ (คาดเดามากกว่า ต้องมีสภาพตรงข้ามกับข้อเท็จจริง):
  ผลิตภัณฑ์เส้นทางจัดส่งและโลจิสติกส์ใหม่ที่สร้างบนข้อมูลเปิด
  ซึ่งจะไม่มีหรือจะแย่ลงอย่างมากหากไม่มีข้อมูลนั้น —
  ต้องเปรียบเทียบกับสภาพตรงข้ามกับข้อเท็จจริงที่ข้อมูลยังปิดหรือมีใบอนุญาตเชิงพาณิชย์
  (counterfactual-analysis) เพราะกิจกรรมบางส่วนจะเกิดขึ้นอยู่แล้วบนข้อมูลแบบเสียเงิน
  ในราคาสูงกว่า ซึ่งเป็นส่วนสูญเปล่าในความหมายของ "คุณค่าที่สร้างจากการเปิดเผย"

กรณีทางธุรกิจที่ป้องกันได้รายงานตัวเลขต้นทุนที่หลีกเลี่ยงได้เป็น
ขอบเขตล่างที่มั่นคง และถือตัวเลขกิจกรรมปลายน้ำเป็นสถานการณ์
ขอบเขตบน ไม่ใช่ข้อเท็จจริง
```

## ความเชื่อมโยงกับวิศวกรรมซอฟต์แวร์

สำหรับวิศวกร คำถามเชิงปฏิบัติเรื่องคุณค่าของข้อมูลเปิดมักแคบกว่าตัวเลขพาดหัวระดับชาติ: การเปิด API หรือชุดข้อมูลเฉพาะนี้ (แทนที่จะเก็บไว้หลังข้อตกลงกับพันธมิตร) เพิ่มการนำกลับมาใช้พอที่จะคุ้มกับต้นทุนต่อเนื่องของการจัดทำเอกสาร ควบคุมเวอร์ชัน และสนับสนุนมันในฐานะอินเทอร์เฟซสาธารณะหรือไม่? ต้นทุนการบำรุงรักษานั้นเป็นของจริงและเป็นคู่ของเศรษฐศาสตร์สร้างครั้งเดียวใช้ซ้ำบ่อยของ [รัฐบาลในฐานะแพลตฟอร์ม](../รัฐบาลในฐานะแพลตฟอร์ม/) — สองหัวข้อนี้เป็นญาติใกล้ชิด หนึ่งเกี่ยวกับโค้ดและโครงสร้างพื้นฐานร่วม อีกหนึ่งเกี่ยวกับข้อมูลร่วม ข้อกล่าวอ้างเรื่องคุณค่าข้อมูลเปิดทุกข้อควรตรวจสอบเทียบกับ [ผลเพิ่มเติมและส่วนสูญเปล่า](../ผลเพิ่มเติมและส่วนสูญเปล่า/) ก่อนใส่ในกรณีทางธุรกิจ: กิจกรรมที่จะเกิดขึ้นอยู่แล้วบนข้อมูลที่มีใบอนุญาตเชิงพาณิชย์ ไม่ใช่คุณค่าที่ *การเปิดเผย* สร้าง

## ข้อผิดพลาดที่พบบ่อย

- **อ้างตัวเลข 3–5 ล้านล้านดอลลาร์ของ McKinsey ว่าเฉพาะสหราชอาณาจักรหรือเป็นส่วนแบ่งของชุดข้อมูลนี้**: เป็นประมาณการตามสถานการณ์ระดับโลกเจ็ดภาคส่วนจากปี 2013 — การใช้เป็นตัวคูณที่แม่นยำสำหรับชุดข้อมูลระดับชาติชุดเดียวบิดเบือนว่าตัวเลขนั้นคืออะไร
- **ไม่มีสภาพตรงข้ามกับข้อเท็จจริง**: อ้างเครดิตกิจกรรมเศรษฐกิจปลายน้ำทั้งหมดที่สร้างบนข้อมูลเปิด โดยไม่ถามว่าส่วนใดจะเกิดขึ้นอยู่แล้วบนข้อมูลแบบเสียเงินหรือมีใบอนุญาตในราคาสูงกว่า (ดู [ผลเพิ่มเติมและส่วนสูญเปล่า](../ผลเพิ่มเติมและส่วนสูญเปล่า/) และ [การวิเคราะห์สภาพตรงข้ามกับข้อเท็จจริง](../การวิเคราะห์สภาพตรงข้ามกับข้อเท็จจริง/))
- **สับสนต้นทุนการผลิตกับคุณค่าที่สร้าง**: ชุดข้อมูลที่เก็บแพงไม่ได้มีค่าที่จะเผยแพร่โดยอัตโนมัติ และชุดที่ถูกไม่ได้มีค่าต่ำโดยอัตโนมัติ — คุณค่าตามการใช้ปลายน้ำ ไม่ใช่ต้นทุนต้นน้ำ
- **มองข้ามต้นทุนการบำรุงรักษาต่อเนื่องของ "เปิด"**: การเผยแพร่ CSV ครั้งเดียวไม่ใช่ข้อผูกพันเดียวกับการดำเนิน API เปิดที่มีเอกสาร ควบคุมเวอร์ชัน และมีผู้สนับสนุน — การให้ทุนอย่างหลังน้อยเกินไปหลังประกาศเปิดตัวเป็นรูปแบบความล้มเหลวที่พบบ่อย
