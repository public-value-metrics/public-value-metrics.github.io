# ต้นทุนต่อผลลัพธ์

ต้นทุนต่อผลลัพธ์คือค่าใช้จ่ายรวมของโครงการหารด้วยจำนวนคนที่บรรลุการเปลี่ยนแปลงที่กำหนดไว้อย่างมีความหมายในสถานการณ์ของตน — ไม่ใช่จำนวนคนที่เพียงได้รับบริการ เป็นตัวชี้วัดประสิทธิภาพที่คมที่สุดที่ผู้ให้ทุนหรือทีมส่งมอบใช้ได้ เพราะบังคับให้ตอบคำถามเบื้องต้นที่องค์กรการกุศลส่วนใหญ่หลีกเลี่ยง: อะไรกันแน่ที่นับว่าสำเร็จ?

## เหตุใดจึงสำคัญ

ธนาคารอาหารสามารถรายงานตัวเลขสองตัวที่ต่างกันมากจากบัญชีของปีเดียวกัน ต้นทุนต่อถุงอาหารที่แจกอาจเป็น 15 ปอนด์ ต้นทุนต่อครัวเรือนที่ต่อมาบรรลุความมั่นคงทางอาหาร — ไม่ต้องพึ่งความช่วยเหลือด้านอาหารฉุกเฉินอีก ตรวจสอบ ณ จุดติดตามผล — อาจเป็น 340 ปอนด์ ทั้งสองเป็นความจริง มีเพียงตัวเดียวที่บอกผู้ให้ทุนว่าเงินกำลังได้ผลหรือไม่ ช่องว่างระหว่างสองตัวคือช่องว่างระหว่างผลผลิตกับผลลัพธ์: ถุงอาหารที่ส่งมอบเป็นผลผลิต; ครัวเรือนที่ไม่อยู่ในภาวะวิกฤตอีกต่อไปเป็นผลลัพธ์ ดู [ผลลัพธ์กับผลผลิต](../ผลลัพธ์กับผลผลิต/)

ภาคส่วนที่สามของสหราชอาณาจักรใช้เวลาสองทศวรรษสร้างโครงสร้างพื้นฐานเพื่อบังคับความแตกต่างนี้ "แนวทางสี่เสา" ของ New Philanthropy Capital ว่าด้วยประสิทธิผลขององค์กรการกุศลขอให้องค์กรระบุผลลัพธ์ก่อนผลผลิตอย่างชัดเจน และ Inspiring Impact — ความร่วมมือด้านการวัดผลกระทบของสหราชอาณาจักรที่มีผู้ให้ทุนหนุนหลัง — เผยแพร่ Outcomes Matrix ที่ใบสมัครขอทุนจำนวนมากขณะนี้กำหนดให้องค์กรการกุศลกรอก โครงการวิจัยประจำปี "State of Hunger" ของ Trussell Trust ที่ดำเนินการร่วมกับ Heriot-Watt University มีอยู่ก็เพราะการนับถุงอาหารเพียงอย่างเดียวไม่ได้บอกอะไรเลยว่าผู้คนหลุดพ้นจากความไม่มั่นคงทางอาหารหรือไม่

ต้นทุนต่อผลลัพธ์มีความหมายก็ต่อเมื่อกำหนดสภาพตรงข้ามกับข้อเท็จจริงไว้แล้ว: ผลลัพธ์ที่บรรลุ "อยู่แล้ว" ไม่ใช่ผลลัพธ์ที่โครงการซื้อมา ดู [การวิเคราะห์สภาพตรงข้ามกับข้อเท็จจริง](../การวิเคราะห์สภาพตรงข้ามกับข้อเท็จจริง/) และ [การเคลื่อนย้ายผลและการระบุที่มา](../การเคลื่อนย้ายผลและการระบุที่มา/)

## คณิตศาสตร์

```
ต้นทุนต่อผลลัพธ์ = ต้นทุนรวมของโครงการ / จำนวนผู้รับประโยชน์ที่บรรลุผลลัพธ์ที่กำหนด

โดยที่:
  ต้นทุนรวมของโครงการ = ต้นทุนการส่งมอบโดยตรง + ส่วนแบ่งที่เหมาะสมของค่าใช้จ่ายดำเนินงาน
  ผลลัพธ์ที่กำหนด     = การเปลี่ยนแปลงสถานะที่ระบุล่วงหน้าและวัดได้
                          (เช่น "มั่นคงทางอาหารเมื่อติดตามผลที่ 6 เดือน"
                          ไม่ใช่ "ได้รับถุงอาหาร")
```

เปรียบเทียบกับ [ฐานข้อมูลต้นทุนต่อหน่วย](../ฐานข้อมูลต้นทุนต่อหน่วย/) (เช่น เกณฑ์อ้างอิงต้นทุนต่อหน่วยเฉพาะภาคส่วน) เพื่อตัดสินว่าต้นทุนต่อผลลัพธ์ที่กำหนดนั้นดี ปานกลาง หรือแย่เมื่อเทียบกับการแทรกแซงที่เทียบเคียงได้

## ตัวอย่างการคำนวณ

**ธนาคารอาหาร หนึ่งปี**:

- ต้นทุนรวมของโครงการ: 450,000 ปอนด์
- ถุงอาหารที่แจก: 30,000
- ต้นทุนต่อถุง (ตัวชี้วัดผลผลิต): 450,000 / 30,000 = **15 ปอนด์**

องค์กรการกุศลยังทำแบบสำรวจติดตามผลหกเดือนกับตัวอย่างครัวเรือน พบว่า 35% ของครัวเรือนที่ได้รับสามถุงขึ้นไปรายงานว่าไม่ต้องการความช่วยเหลือด้านอาหารฉุกเฉินอีกและได้คะแนนเกินเกณฑ์ความมั่นคงทางอาหารในโมดูลแบบสำรวจความมั่นคงทางอาหารมาตรฐาน จาก 1,800 ครัวเรือนที่ได้รับสามถุงขึ้นไปในปีนั้น 630 ครัวเรือนบรรลุผลลัพธ์นั้น

```
ต้นทุนต่อผลลัพธ์ = 450,000 ปอนด์ / 630 = 714 ปอนด์ต่อครัวเรือนที่บรรลุความมั่นคงทางอาหาร
```

ตัวเลข 714 ปอนด์นั้นคือสิ่งที่ผู้ให้ทุนซึ่งเปรียบเทียบองค์กรการกุศลนี้กับโครงการนำร่องการโอนเงินหรือบริการให้คำปรึกษาด้านหนี้สินควรใช้ — ไม่ใช่ 15 ปอนด์ หากโครงการโอนเงินที่เทียบเคียงได้ในภูมิภาคเดียวกันบรรลุความมั่นคงทางอาหารที่ 500 ปอนด์ต่อครัวเรือน ธนาคารอาหารก็ไม่ใช่เส้นทางที่มีประสิทธิภาพกว่าอย่างชัดเจนสู่ผลลัพธ์เดียวกัน แม้ต้นทุนต่อถุงจะดูถูก

## ความเชื่อมโยงกับวิศวกรรมซอฟต์แวร์

ระบบบริหารจัดการกรณีส่วนใหญ่สร้างขึ้นเพื่อบันทึกผลผลิต เพราะผลผลิตคือสิ่งที่เกิดขึ้นภายในธุรกรรม (ส่งมอบถุงอาหาร ส่งแบบฟอร์ม) ผลลัพธ์มักเกิดขึ้นทีหลัง มักอยู่นอกช่วงเวลาเก็บข้อมูลปกติของระบบ และต้องการการตัดสินใจออกแบบอย่างตั้งใจ: สร้างกลไกติดตามผล (ตัวกระตุ้นแบบสำรวจ เวิร์กโฟลว์ติดต่อกลับ การเชื่อมโยงข้อมูล) เป็นฟีเจอร์ชั้นหนึ่ง ไม่ใช่สิ่งที่คิดทีหลังแล้วต่อเติมเพื่อรายงานประจำปี วิศวกรที่สร้างแพลตฟอร์มบริหารจัดการเงินอุดหนุนหรือกรณีสำหรับภาคส่วนนี้ควรถือว่า "เหตุการณ์ผลลัพธ์คืออะไร และเราสังเกตได้อย่างไร" เป็นคำถามด้านความต้องการที่ถามก่อนกำหนดโมเดลข้อมูล — การเพิ่มฟิลด์ผลลัพธ์ภายหลังยากกว่าตัวนับผลผลิตมาก ดู [ผลลัพธ์กับผลผลิต](../ผลลัพธ์กับผลผลิต/) และ [แบบจำลองตรรกะ](../แบบจำลองตรรกะ/) สำหรับวิธีจัดโครงสร้างการสนทนาเรื่องความต้องการนั้น และ [ต้นทุนต่อผู้รับประโยชน์](../ต้นทุนต่อผู้รับประโยชน์/) สำหรับตัวชี้วัดที่เร็วและหยาบกว่าที่ทีมหันไปใช้เมื่อยังไม่ได้สร้างการติดตามผลลัพธ์

## ข้อผิดพลาดที่พบบ่อย

- **รายงานผลผลิตที่แต่งตัวเป็นผลลัพธ์** "ผู้คนที่เข้าถึง" ไม่ใช่ "ผู้คนที่ได้รับความช่วยเหลือ" หากตัวชี้วัดผลิตได้จากบันทึกระบบโดยไม่ต้องติดต่อกลับ แทบแน่นอนว่าเป็นผลผลิต
- **การเล่นแร่แปรธาตุตัวหาร** การจำกัดประชากรผลลัพธ์เป็น "ผู้ที่เรียนจบโครงการ" ตัดผู้ที่ลาออกไปอย่างเงียบ ๆ — มักเป็นกรณียากที่สุด — และทำให้อัตราที่เห็นสูงเกินจริง ให้ระบุตัวหารเป็นทุกคนที่เริ่ม ไม่ใช่ทุกคนที่จบ
- **ไม่มีสภาพตรงข้ามกับข้อเท็จจริง** การนับทุกคนที่บรรลุผลลัพธ์ รวมถึงผู้ที่จะบรรลุอยู่แล้ว ทำให้ประเมินสิ่งที่โครงการซื้อมาสูงเกินจริง ดู [การวิเคราะห์สภาพตรงข้ามกับข้อเท็จจริง](../การวิเคราะห์สภาพตรงข้ามกับข้อเท็จจริง/)
- **เปรียบเทียบข้ามนิยามผลลัพธ์ที่เข้ากันไม่ได้** "มั่นคงทางอาหาร" ที่วัดด้วยโมดูลแบบสำรวจที่ผ่านการตรวจสอบความตรงเปรียบเทียบกับ "มั่นคงทางอาหาร" ที่รายงานเองในแบบฟอร์มความพึงพอใจไม่ได้ ตารางจัดอันดับต้นทุนต่อผลลัพธ์จะซื่อตรงก็ต่อเมื่อนิยามผลลัพธ์ตรงกัน
