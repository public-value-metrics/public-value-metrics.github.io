# グリーンブック評価（五事例モデル）

グリーンブックは、英国政府の支出提案を評価するためのHM Treasuryの必須指針である。その中心的なツールである五事例モデルは、ビジネスケースに五つの別々の問いに答えることを強制する——それは良い考えか、価値を提供するか、調達可能か、負担可能か、提供可能かという問いであり、すべてを大臣が一括承認できる単一の数字に押し込めることを避ける。

## 重要な理由

省庁の委任限度額を超える英国中央政府のあらゆる支出提案は、資金が拠出される前にグリーンブック評価を通過しなければならない。HM TreasuryのGreen Book Review 2020（この過程が貧しい地域に対して偏っているという批判を受けて発表された）は、選択肢が真の「最小限実施」のベースラインと比較されること、そして物有所値が評価される前に戦略的整合性が示されることという要件を強化した。五事例モデル自体はグリーンブックより古く、標準的なビジネスケース構造としてOffice of Government Commerceに端を発するが、2022年版グリーンブックは、それをTreasuryの承認を求めるあらゆるビジネスケースの必須の形式として組み込んでいる。

ケースを五つに分割する意味は、他がどうであれ、いずれか一つの次元だけで提案が失敗しうるという点にある。戦略的に健全でコスト効果の高いITプラットフォーム移行であっても、それを提供できるサプライヤーが一社しかない場合（単独入札のリスクを生む）には商業事例で失敗しうるし、その省庁がその規模のプログラムを提供した実績がない場合にはマネジメント事例で失敗しうる。単一の「物有所値」スコアは、まさにこの種の失敗モードを隠してしまう。

## 計算式

五事例モデルは公式ではなく構造であるが、各事例には独自の定量的あるいはエビデンスに基づくテストがある。

```
1. 戦略事例
   組織戦略に結びついた支出目的の証拠。
   テスト：そもそも変化のためのケースがあるか？（「何もしない」
   は常に一つの選択肢である。）

2. 経済事例
   「最小限実施」のベースラインに対する選択肢の評価、社会的費用
   便益分析あるいは費用効果分析を用いる。
   テスト：どの選択肢が公共純価値を最大化するか？
   ../social-cost-benefit-analysis/ と ../cost-effectiveness-analysis-in-government/ を参照

3. 商業事例
   市場関与、調達経路、購入者と供給者間のリスク配分。
   テスト：好ましい選択肢は許容できる条件で調達可能か？

4. 財務事例
   省庁の予算限度内での負担可能性、資金源、貸借対照表上の
   取り扱い。
   テスト：今年、そして今後毎年、それを負担できるか？

5. マネジメント事例
   ガバナンス、プロジェクト計画、便益実現計画、リスク登録簿。
   テスト：この組織は実際にそれを提供できるか？
   ../benefits-realization/ を参照
```

経済事例は定量的な評価が行われる場所である。選択肢は、[社会的割引率](../social-discount-rate/)で調整された純現在価値の基準で、あるいは[社会的費用便益分析](../social-cost-benefit-analysis/)の方法で比較される。便益を正直に金銭化できない場合は、[費用効果分析](../cost-effectiveness-analysis-in-government/)または[多基準意思決定分析](../multi-criteria-decision-analysis/)を通じて比較される。

## 計算例

**地方自治体**：1,200万£の住宅修繕ITシステムを評価している自治体が、五つの事例を以下のように進める。戦略事例：介入策がなければ18か月以内に修繕の滞留が法定の適正住宅基準に違反する。経済事例：三つの選択肢を、3.5%の割引率（2022年版グリーンブックの標準的な社会的時間選好率に基づく）で10年間の評価期間にわたってコスト計算する——「最小限実施」（レガシーシステムの部分修正、NPV −410万£）、「購入」（COTSプラットフォーム、NPV +230万£）、「構築」（オーダーメイドのプラットフォーム、グリーンブック付属書Aに従って未割引の資本コストに対してソフトウェア開発の楽観バイアス40%を適用した後、NPV +60万£）。経済事例では「購入」が勝つ。商業事例：実行可能なサプライヤーが二社存在し、競争入札が可能——合格。財務事例：資本はPublic Works Loan Boardから調達可能であり、経常費用は中期財政計画内に収まる——合格。マネジメント事例：自治体は過去5年間に二つの同等のシステムを提供した実績がある——合格。この提案は「購入」で進む。

**中央省庁**：強力な経済事例（NPV +4,000万£）を持つ提案だが、関連する認証を保有するサプライヤーが一社しかないため、競争的な緊張感を求める商業事例のテストに失敗する。これは、単独入札の適用除外（それ自体の精査負担を伴う）か、市場を開くための仕様の再設計のいずれかを強いる——経済事例だけでは、これを決して明らかにしなかったであろう。

## ソフトウェア開発との関連

政府あるいは助成金を受ける組織内のエンジニアリングチームは、通常、経済事例だけしか目にしない。なぜなら、それが製品・技術リーダーシップが正当化を求められる部分だからである（「この移行のROIは何か？」）。しかしTreasuryや助成金委員会を通過するビジネスケースには五つすべてが必要であり、エンジニアはしばしば商業事例（それは実際に調達可能か、それとも特定ベンダーの独自フォーマットに縛られるのか？）とマネジメント事例（提供能力があるか、それとも特定の三人が辞めないことに依存しているか？）に答える最適な立場にある。「ビジネスケースの数字だけ」を求める要求は、実際の意思決定の五分の一を求める要求として扱うこと。経済事例の結果が通常どのように要約されるかについては[物有所値](../value-for-money/)を、財務事例の通常の定量的な核については[政府ITにおける総所有コスト](../total-cost-of-ownership-in-government-it/)を参照。

## 落とし穴

- **経済事例を先に書き、それに合わせて戦略事例を書くこと。** Green Book Review 2020は、まさにこの失敗パターンが、既にエビデンスが充実している場所やセクターに評価の偏りをもたらし、地域間格差を固定化していることを発見した。戦略事例は、選択肢が比較される前に目的を確立するべきである。
- **「最小限実施」を「何もしない」と混同すること。** 正しいベースラインは、最低限の法的あるいは安全上の義務を満たし続ける最安の選択肢であり、支出ゼロという空想ではない。文字通りゼロと比較すると、すべての選択肢の見かけ上の価値が膨らむ。
- **経済事例が強いという理由で商業事例とマネジメント事例を省略すること。** 競争的に調達できない、あるいは提案元の組織が提供できない高NPVの提案は資金提供に値しない。Treasuryのレビュアーは、説得力のある経済事例があっても、これらの理由で日常的に却下する。
- **五事例モデルを最初に一度だけ適用すること。** グリーンブックは、コストとエビデンスが固まるにつれて、その後の承認ゲート（戦略的概要事例、概要ビジネスケース、完全なビジネスケース）ごとにケースを再検討することを求めている——概要段階で固定されたケースは、後のゲートで捕捉されていたであろうコストの増大を見逃す。
