# オープンデータの価値

オープンデータの価値は、政府と公共のデータが価格を持たないときにそれが何の価値を持つかを推定する問題である——それは売られないため、収益の行が存在しない。それにもかかわらず、それを公開すること（気象記録、交通時刻表、郵便番号の境界、会社登記簿）は、下流で経済的・社会的な活動を明らかに生み出す。それをうまく評価することが重要なのは、「公開はタダだ」と「それは無価値だ」の両方が間違っているからであり、APIあるいはデータセットを開くかどうかを決めるソフトウェアエンジニアは、そのどちらよりも良い論拠を必要とする。

## 重要な理由

最も引用されるトップダウンの推定値は、マッキンゼー・グローバル・インスティテュートの2013年の報告書「Open data: Unlocking innovation and performance with liquid information」から来ており、それは、教育、交通、消費者製品、電力、石油・ガス、ヘルスケア、消費者金融という7つの分野にわたるオープンデータの潜在的な年間価値を、透明性の向上、供給と需要のより効率的なマッチング、そしてそのデータに基づいた新しい製品・サービスの実現を含む仕組みを通じて、世界全体で年間3兆ドルから5兆ドルと見積もった。その数字はシナリオの推定値であり測定された実績ではない。そしてそれは、価値がほとんど政府ではなく、そのデータを使う第三者——企業、研究者、市民——に発生するにもかかわらず、あたかも政府が直接獲得できる収益であるかのように日常的に誤って引用される。これはまさに、それを売るのではなく公開することの要点である。ティム・バーナーズ=リー卿とナイジェル・シャドボルト卿によって2012年に共同設立された英国のOpen Data Instituteは、それ以来、セクターごとに、データセットごとに、より粒度の細かいボトムアップの事例研究の蓄積を構築してきた。これらは、マッキンゼーの見出しの数字よりも実際のビジネスケースにとってはるかに有用である。なぜなら、それらは集計された規模だけでなく、価値創造の仕組みを示すからである。

## 計算式

オープンデータには市場価格がないため、評価方法がそれに代わる。三つのアプローチが繰り返し現れ、どれも単独では十分ではない。

```
1. 費用回避/代替コスト法：
   価値 ≈ 利用者が同等のデータを自分で生成あるいはライセンス
   取得するために支払っていたであろうもの——下限であり、元の
   生産者がまったく予想しなかった使用によって生み出された価値を
   無視する

2. 市場類推/下流活動法：
   価値 ≈ そのデータに基づいて構築された事業/サービスによって
   生み出された収益あるいは節約（例えば、オープンな地図・交通
   データに基づいて構築されたカーナビアプリ）——実際の経済活動を
   捕捉するが、そのデータのリリース自体にきれいに帰属させることが
   難しい（additionality-and-deadweightを参照）

3. 条件付き/表明選好法：
   価値 ≈ 利用者が支払うであろうと言う額、あるいは節約されると
   言う時間——一般的な方法とそのバイアスについては
   stated-preference-valuationを参照

これらのいずれも市場価格ほどきれいな数字を生み出さない。信頼
できるオープンデータのビジネスケースは、二つ以上を三角測量し、
どの仕組みが機能しているかについて明示的である。
```

## 計算例

**例示的な全国的な地図/住所データのリリース**（ODI方式の事例研究に基づく方法論、そのような研究が通常見出す規模を例示する数字）。

```
費用回避の推定：
  そうでなければ商用で同等の住所照合データをライセンス取得
  していたであろう事業、推定平均ライセンスコスト£4,000/年、
  現在無料のオープンデータセットを使用している推定15,000の
  中小企業にわたって
  = 15,000 × £4,000 = £60,000,000/年、回避されたライセンス
  コストだけで

下流活動の推定（より投機的、反実仮想が必要）：
  それがなければ存在しない、あるいは実質的に劣っていたであろう
  オープンデータに基づいて構築された新しい配送ルーティングと
  ロジスティクス製品——そのデータが閉じられたまま、あるいは
  商用でライセンスされたままであるという反実仮想との比較が
  必要である（counterfactual-analysis）。なぜなら、その活動の
  一部は、より高い価格の有料データでどのみち起こっていた
  であろうからであり、これは「それを開くことによって創造された
  価値」という意味では死荷重である

擁護可能なビジネスケースは、費用回避の数字を確固たる下限として
報告し、下流活動の数字を事実としてではなく上限のシナリオとして
扱う。
```

## ソフトウェア開発との関連

エンジニアにとって、実務上のオープンデータ価値の問いは、通常、全国的な見出しの数字よりも狭い——この特定のAPIあるいはデータセットを（パートナー契約の裏に保持するのではなく）開くことは、それを公共インターフェースとして文書化し、バージョン管理し、サポートし続けるコストを正当化するほど再利用を増やすか？ その保守コストは本物であり、[Government as a Platform](../government-as-a-platform/)の「一度構築して何度も再利用する」経済学の対応物である——この二つのトピックは近いいとこである。一方は共有コードとインフラについてであり、もう一方は共有データについてである。あらゆるオープンデータ価値の主張は、それがビジネスケースに入る前に、[追加性と死荷重](../追加性と死荷重/)に照らしてチェックされるべきである——商用でライセンスされたデータでどのみち起こっていたであろう活動は、その*公開*が創造した価値ではない。

## 落とし穴

- **マッキンゼーの3〜5兆ドルという数字を、英国固有のもの、あるいはこのデータセットの取り分として引用すること**——それは2013年の、グローバルで7セクターのシナリオ推定値である。それを単一の全国的なデータセットに対する正確な乗数として使うことは、その数字が何であるかを誤って表現する。
- **反実仮想がないこと**——それがより高い価格の有料あるいはライセンスされたデータでどのみち起こっていたであろうかを問うことなく、オープンデータに基づいて構築された下流の経済活動すべての手柄を主張すること（[追加性と死荷重](../追加性と死荷重/)と[反実仮想分析](../反実仮想分析/)を参照）。
- **生産コストと創造された価値を混同すること**——収集に高価だったデータセットは自動的にリリースする価値があるわけではなく、安価なものが自動的に低価値であるわけでもない——価値は上流のコストではなく下流の使用を追跡する。
- **「オープン」の継続的な保守コストを無視すること**——一回限りのCSV抽出を公表することは、文書化され、バージョン管理され、サポートされたオープンAPIを運用することと同じコミットメントではない——ローンチの発表後に後者に資金を出さないことは一般的な失敗モードである。
