# 公共プログラムにおける遅延コスト（CoD）

遅延コストは、プログラム、サービス、あるいはシステム変更がまだ提供*されていない*単位時間あたりに失われる公共価値である。これは本章の要となる橋渡しの指標である——それは「稼働開始が6か月遅れた」を、週あたりのポンド、あるいは週あたりのWELLBYへと変換し、遅延がビジネスケースそのものと同じ通貨で議論できるようにする。

## 重要な理由

ラインアーツェンの法則——「一つだけ定量化するなら、遅延コストを定量化せよ」——は、ほとんどそのまま政府に持ち込まれる。なぜなら、公共プログラムはそれに異常にさらされているからである——ビジネスケースは予測された便益ストリームに対して承認されるが、そのストリームは稼働開始時にしか流れ始めず、遅延の毎週が、誰もリスクレジスターに価格付けしない失われた価値の一週間である。National Audit OfficeによるUniversal Creditの展開に対する繰り返しの精査（その「Rolling Out Universal Credit」報告書を参照、<https://www.nao.org.uk/>）は、このパターンを示している——スケジュールの遅延は追跡され報告されたが、次の受給者群に改革されたシステムを*まだ*提供していないことの週あたりポンドのコストは、それが優先順位付けとエスカレーションを駆動すべき数字であったにもかかわらず、見出しの数字として述べられることはめったになかった。CoDの数字がなければ、遅延したプログラムは提供理事会にとってスケジュールの問題に見える——それがあれば、会計責任者にとって価値侵食の問題になる。

## 計算式

```
CoD = 提供されていない間に失われる単位時間あたりの便益
     （£/週、あるいはWELLBY/週）

総遅延損失 = CoD × 遅延期間

公共プログラムに対して合計する便益ストリーム：
  現金創出型の節約   （不正/誤りの削減、回避された一時的コスト）
+ 非現金の解放された容量（ケースワーカー/職員時間 × 負荷コスト）
+ 幸福便益           （WELLBY × £13,000/WELLBY、HMT Green Bookの
                       幸福補足ガイダンス、2019年価格）
```

市民向けサービスについては、金額だけでなく幸福でも表示すること——根底にある単位については[幸福調整生存年](../幸福調整生存年/)を、遅延した1ポンドが代わりに何に資金を出せたかについては[公共支出における機会費用](../公共支出における機会費用/)を参照。

## 計算例

**地方自治体**：住宅給付システムのアップグレードが、20,000件の現行請求全体にわたって過払い誤りを請求あたり年間£150削減する。

```
年間便益 = 150 × 20,000 = £3,000,000/年
CoD = 3,000,000 / 52 ≈ £57,700/週
12か月の実装遅延は、52 × 57,700 ≈ £3,000,000の回避可能な誤りの
コストがかかる。
```

**中央政府機関**：障害給付の評価サービスが計画より6か月（26週）遅れて提供され、20万人の請求者/年が平均3週間長く決定を待つことを意味する。財務的不確実性の追加の1週間ごとに、−0.0018 WELLBY（人生満足度ポイント）の効果としてモデル化される。

```
請求者あたりのWELLBY損失 = 3 × 0.0018 = 0.0054
年間WELLBY損失 = 200,000 × 0.0054 = 1,080 WELLBY/年
CoD_幸福 = 1,080 / 52 ≈ 20.8 WELLBY/週
CoD_金額 = 20.8 × £13,000 ≈ £270,000/週の幸福価値
```

したがって26週間の遅延は、およそ540 WELLBY——Green Bookの幸福評価でおよそ£700万に相当——を「コスト」とし、稼働開始日を逃したことを、プロジェクトマネジメントの脚注ではなく市民の福祉の出来事として再構成する。

## ソフトウェア開発との関連

CoDこそが、[DORA指標](../公共価値のためのdora指標/)と[フロー指標](../政府提供におけるフロー指標/)を財務的に読める形にするものである——パイプラインにおけるリードタイム × CoDは、市民に到達する前にキューで燃やされたお金（あるいは幸福）である。具体的には次の通りである。

- **優先順位付け**：ステークホルダーの序列ではなくCoD÷期間でバックログをランク付けすること——これは、誰が尋ねているかではなく価値に基づいて選択肢を評価するというGreen Bookの要件のソフトウェア工学における類似物である。
- **調達**：12〜18か月のフレームワーク調達サイクルにはCoDがある。それを価格付けすることは、加速された経路のための緊急性のケースを変え、価値実現までの時間が意思決定要因である[内製か購入か](../政府における内製か購入か/)の決定に直接供給する。
- **便益ケース**：承認時に引用されたすべてのCoDの数字は、[便益実現](../便益実現/)で再び現れるべきである——遅延コストが本物であったなら、加速された便益は稼働開始後に測定可能であるべきである。

## 落とし穴

- **線形のCoDを仮定すること**：一部の公共サービスは、滑らかな週次レートではなく、締め切り型の価値を持つ（法定コンプライアンス日——CoDはその日以降執行リスクの水準に跳ね上がり、それ以前はほぼゼロである）。掛け算する前に緊急性のプロファイルを分類すること。
- **誰も必要としないアウトプットに対するCoD**：遅延は、提供されていないものに価値がある場合にのみコストを持つ。誰も使わないであろうシステムは、どれだけ遅れていてもCoDはゼロである。
- **遅延と割引の二重計上**：[社会的割引率](../社会的割引率/)はすでに複数年の評価期間にわたって時間を価格付けしている。CoDは、数週間・数か月に対する、期間内の運用上のバージョンである。スケジュールの遅延にはCoDを、複数年の再フェーズ化にはNPVシフトを使うこと。
