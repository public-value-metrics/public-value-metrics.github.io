# 公共価値

公共価値とは、政府や社会セクターの組織が市民全体のために生み出す価値のことである——単にその組織が生み出す成果物や支出した金額だけでなく、その組織が存在し、実際に行った活動によって社会がより良くなったかどうかを指す。マーク・ムーアが1995年に示した「戦略的三角形」は標準的なテストである。すなわち、公共の取り組みは、*正当性があり支持されていること*、*実質的な価値があること*、*運用上実現可能であること*の三つすべてを同時に満たして初めて正当化される。

## 重要な理由

民間セクターの価値は比較的価格をつけやすい——収益からコストを差し引いたもので、離脱可能な顧客によって判定される。公共価値にはそれに相当する市場シグナルがない。刑務所サービス、税務当局、児童保護チームはいずれも、市民が単純に「買わない」という選択ができないものを生み出しており、「顧客」（納税者、犯罪者、子ども）は予算を承認する政治的な主体と同一人物でないことが多い。ムーアの『Creating Public Value: Strategic Management in Government』（ハーバード大学出版局、1995年）は、この欠けている規律を提供する。すなわち、マネージャーは（1）自らの取り組みがどのような公共価値を生み出すのか、（2）その正当性と資金の出どころ——大臣、議会、委任、助成金——はどこにあるのか、（3）その組織が手元にある人材、技術、プロセスで実際にそれを提供できるのかを、それぞれ述べられなければならない。三角形の一辺または二辺でしか高得点を取れないプログラムは、どれほど善意であっても、まだ正当化されていない。

これが実務上重要なのは、公共セクターのソフトウェア失敗の多くが技術的な失敗ではないからである。あるシステムが技術的に優れており運用上実現可能であっても、正当化する環境——大臣、監督委員会、一般市民——の中で、そのシステムが最適化しようとしているものを実際に望んでいた人が誰もいなければ、それでも失敗しうる。Universal Creditのデジタルサービスと、NHSのNational Programme for ITは、いずれも英国の行政文献において、三角形の運用面と正当性面がミッション面とずれていた事例として引用されている。

## 計算式

公共価値は公式ではなく枠組みであるが、他の方法では曖昧になりがちな投資案件を、三つの検証可能な問いへと構造化する。

```
戦略的三角形テスト——三つすべてが成り立つ場合にのみ先へ進む：

1. 正当性と支持：誰がこれを承認したのか、そして正当化する環境
   （立法府、大臣、議会、理事会、世論）は、資源が投入される段階に
   なっても、それをまだ支持しているか？

2. 公共価値：これは市民や社会に対して、具体的で説明可能などのような
   利益——安全、健康、機会、信頼、公正——を、誰のために生み出すのか？

3. 運用能力：組織は、現在の人材、技術、パートナー、法的権限で
   それを実際に提供できるのか——あるいは、それらを獲得するための
   信頼できる計画があるか？
```

弱い取り組みは通常、少なくとも一辺で失敗する。技術的には提供可能だが権限がない（誰も承認していないデータ共有パイロット）、人気はあるが提供不可能（技術的な実装能力のない約束されたデジタルサービス）、あるいは権限があり提供可能だが価値が空虚（誰も使わないダッシュボード）といった具合である。

## 計算例

**地方自治体**：ある自治体のデジタルチームが、住宅給付申請のためのAIトリアージツールを提案する。

- *正当性*：自治体の内閣はデジタルファースト戦略を承認しているが、社会保障を担当する選出議員は自動意思決定について具体的な承認をしていない——これはギャップであり、青信号ではない。
- *公共価値*：処理の高速化（主張されている利益：10日から2日へ）は、申請者が誤って却下されない限りにおいてのみ真の価値である。価値の主張には速度だけでなく正確性も含まれなければならない。
- *運用能力*：自治体にはデータサイエンティストが1名しかおらず、モデル監視プロセスもないため、主張されている2日間のターンアラウンドは、示されているエラー率では現状提供できない。

三辺のうち二辺が失敗している。ムーアの枠組みはこう言う——このまま進めてはならない。まず自動意思決定に対する明示的な権限を確保し、監視能力を構築せよ。さもなければ、ビジネスケースで主張されている「公共価値」は架空のものである。

**中央政府**：ある税務当局のオンライン申告サービスは、強い正当性（法定の権限）と強い運用能力（既存チームが確実に稼働している）を持つが、デジタル排除された人々——[デジタル・インクルージョン](../digital-inclusion/)を参照——が使えないチャネルに押し込まれることで利用率が低ければ、公共価値は弱い。三角形は、提供のみに焦点を当てたダッシュボードが隠してしまうものを明らかにする。

## ソフトウェア開発との関連

公共価値は、このリポジトリ全体が位置づけられる包括的な概念である。[物有所値（Value for Money）](../value-for-money/)は、資源がうまく使われたかどうかについて、経済性・効率性・有効性のテストを与える。[公共支出における機会費用](../opportunity-cost-in-public-spending/)は、そのお金が他に何をできたかを価格づける。そして[追加性と死荷重](../additionality-and-deadweight/)、[置き換えと帰属](../displacement-and-attribution/)、[反実仮想分析](../counterfactual-analysis/)は、主張されている価値が想定にすぎないものではなく現実のものかどうかを共同で検証する。エンジニアにとって、戦略的三角形は公共セクターの製品に関するあらゆる意思決定に役立つ事前検証となる。

- 機能を設計する前に、誰がそれを承認したのか、そしてその承認がまだ有効かどうかを問うこと——あるその後異動した大臣のために作られた機能は、正当性の辺を静かに失っている可能性がある。
- 「作れるか」と「作るべきか」を本当に別の問いとして扱うこと。技術的な実装能力は三角形の第三の辺にしか答えない。
- 公共サービスの製品要件文書は、ユーザーストーリーだけでなく、公共価値の主張を明示的に述べるべきである。なぜなら、ユーザー価値と公共価値は必ずしも同じものではないからである（[成果と産出](../outcomes-vs-outputs/)を参照）。

## 落とし穴

- **運用能力を十分な正当化として扱うこと。** 「作れる」は三角形の一辺にしか答えない。実装能力の高いチームは、誰も望んでいたと権限を与えていないものを日常的に出荷し、説明可能な公共の利益を何も生み出さないことがよくある。
- **正当性と合法性を混同すること。** プログラムは合法でありながら、困難な提供フェーズを乗り切るために必要な政治的・公的支持を欠くことがある。法的な裏付けは委任と同じではない。
- **公共価値を、委託した部門が言うことがすべてだと想定すること。** ムーアのモデルは、価値の主張が資金提供者によって単に主張されるだけでなく、市民の実際の利益に照らして検証可能であることを要求する——そうでなければ、この枠組みは自己認証に崩れてしまう。
