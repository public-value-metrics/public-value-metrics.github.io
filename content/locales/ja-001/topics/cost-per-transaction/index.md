# 取引あたりコスト

取引あたりコストは、政府デジタルサービスの見出しとなる単位経済性の指標である——あるチャネルを提供する総コストを、それを通じて完了した取引数で割ったものである。これは旧GOV.UK Performance Platformの旗艦的な数字であり、10年にわたる「デフォルトでデジタル」への投資に資金を提供した数字である——まさにそれゆえに、これは最も操作されやすい指標でもある。

## 重要な理由

Cabinet Officeの2012年のDigital Efficiency Reportは、定着することになるチャネルコスト比較を提示した——デジタル取引は電話のおよそ20分の1、対面のおよそ50分の1のコストであることが判明し、地方自治体の例示的な数字ではウェブ取引あたりおよそ£0.15に対し電話は£2.83、対面は£8.62であった。この単一の比較が、Government Digital Strategyで名指しされた25の模範サービスを再設計する正当化となり、それ以来チャネル移行による節約を引用してきたすべての省庁のビジネスケースの正当化となった。この数字は桁数のシグナルとして本当に有用であるが、その比率は各側で何がカウントされるかに完全に依存する——公正な電話チャネルのコストにはコールセンターのスタッフ、電話契約、研修、資産が含まれる。公正なデジタルコストには、ホスティング、継続的なプロダクトチームの給与、失敗したジャーニーのサポートデスク時間、そして[デジタルサービス標準](../digital-service-standard/)の第5項目が求める支援付きデジタルチャネルが含まれる。デジタル側からそれらを十分に取り除けば、どんなサービスも安く見える。

## 計算式

```
取引あたりコスト = 配分された総チャネルコスト / 完了した取引数

配分された総チャネルコストには以下を含むべきである：
  + ホスティングとインフラ
  + プロダクト/エンジニアリング/サポートチームのコスト（償却済み）
  + コンテンツとサービスデザインのコスト（償却済み）
  + 支援付きデジタル/アクセシビリティサポートのコスト
  + 失敗需要のコスト（デジタルで失敗し電話に戻る利用者）
  − 一回限りの構築コストは、初年度に全額計上されるのではなく、
    予想されるサービス寿命にわたって償却される

一般的な会計上のトリック：
  「取引あたり限界コスト」（構築後のホスティングのみ）が、あたかも
  「取引あたり平均コスト」（構築・運用を続けるチームを含む総コスト）
  であるかのように引用される。この二つは、大規模で活発な提供
  チームを持つサービスでは10倍以上異なりうる。
```

## 計算例

**車両税更新サービス**：年間400万件の取引。

```
限界コストのみの数字（トリック）：
  ホスティング＋支払い処理のみ = £180,000/年
  取引あたりコスト = 180,000 / 4,000,000 = £0.045
  → ビジネスケースで引用される見出しの数字

完全に負荷を含んだ数字（正直なもの）：
  ホスティング＋支払い                    £180,000
  プロダクト/エンジニアリングチーム（8人）  £720,000
  サポートデスク（失敗/問い合わせのあった取引）£310,000
  支援付きデジタル電話回線                £140,000
  合計                                    £1,350,000
  取引あたりコスト = 1,350,000 / 4,000,000 = £0.3375

完全に負荷を含んだ数字は、Digital Efficiency Reportの£2.83の
電話チャネル比較対象よりも依然としておよそ8倍安い——本物で
擁護可能な節約である——しかし、簡略版で引用される限界コストのみの
数字より7.5倍高い。どちらの数字も「真実」であるが、電話チャネルの
コストと比較可能なのは一方だけである。
```

## ソフトウェア開発との関連

取引あたりコストは、アーキテクチャの決定が財務上の数字になる場所である——きれいに自動スケールし手動介入をほとんど必要としないサービスは、時間とともにこの数字を押し下げる。紛らわしいエラー状態から高いサポートチケット量を生み出すサービスは、ホスティングの効率性にかかわらずこれを押し上げる。これは、[デジタルサービス標準](../digital-service-standard/)の第10項目（「成功とは何かを定義し、業績データを公表する」）と、この数字が属するより完全なKPIセットを定める[サービス標準と取引指標](../service-standards-and-transaction-metrics/)の自然な相棒指標である。これはまた[チャネル移行による節約](../channel-shift-savings/)の計算に直接供給し、プラットフォームと共有サービスのオーバーヘッドが静かに脱落しないよう、[政府ITにおける総所有コスト](../total-cost-of-ownership-in-government-it/)と照合されるべきである。

## 落とし穴

- **平均コストに見せかけた限界コスト**：サービスが構築された後のホスティングのみのコストを引用し、それを維持・反復・サポートする継続的なチームを省略すること——上記の計算例を参照。
- **支援付きデジタルコストを除外すること**：[デジタル・インクルージョン](../digital-inclusion/)が求める電話/紙のフォールバックが別々にコスト計算されるか無視される場合、そのチャネルは「デフォルトでデジタル」に準拠しておらず、その真のコストは捕捉されていない。
- **失敗需要を無視すること**：デジタルで始まり失敗し、どのみち電話や紙のフォームを生み出す取引は、それを受け止めるチャネルのコストではなく、デジタルチャネルのコストである。
- **チャネルをまたいで複雑さの異なる取引を比較すること**：電話は不均衡に困難なケース（複数の扶養家族、誤りの修正、脆弱な申請者）を処理する。取引の組み合わせが一致していない限り、平均電話コストと平均デジタルコストを比較することはその比率を過大に見せる。
