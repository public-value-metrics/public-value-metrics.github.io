# 公共セクターのサイバーセキュリティの価値

公共セクターのサイバーセキュリティの価値は、リスク低減を価格付けする規律である——セキュリティ支出は機能しているときには目に見えるアウトプットを何も生み出さず、失敗したときには非常に目に見えるものを生み出すことを考えると、市民のデータの侵害をより起こりにくくすることにはどれほどの価値があるのか？ 給付記録、健康データ、あるいは税務記録を保持するサービスにとって、その「機能しているときは見えない」という性質こそが、それがコンプライアンスのチェックだけではなく明示的な価値の論拠を必要とする理由である。

## 重要な理由

英国のNational Cyber Security CentreのCyber Assessment Framework（CAF）は、公共セクターの組織に、セキュリティをチェックリストとしてではなく評価可能な成果ベースの規律とするための構造化された方法を提供する——それは四つの高レベルの目標（セキュリティリスクの管理、サイバー攻撃からの保護、サイバーセキュリティイベントの検知、インシデントの影響の最小化）を定め、それらをシステムの所有者が評価されうる貢献成果へと分解する。これは[デジタルサービス標準](../digital-service-standard/)の第9項目（「利用者のプライバシーを保護する安全なサービスを作る」）と同じ精神である。CAF評価が守るものには文書化された値札がある——IBMのCost of a Data Breach Reportはセクター別の平均侵害コストを追跡しており、金融やヘルスケアと比較して公共セクターは一貫して範囲の下方に位置することを発見してきた——最近の版では公共セクターの平均を侵害あたりおよそ260万〜290万ドルとしている——しかし「金融より低い」は「低い」ではなく、政府の侵害は、この報告書の数字が完全には捕捉しないコストを伴う——デジタルチャネルへの市民の信頼の喪失。これは、チャネル移行のビジネスケースが依存する[デジタル利用](../channel-shift-savings/)を押し下げ、そもそも国家が市民に差し出すことを強いたデータを露出させることの政治的・法的コストである。

## 計算式

セキュリティ投資は、あらゆるリスク低減支出が評価されるのと同じ方法で評価される——古典的なリスクマネジメントの恒等式を使った、予想される損失の低減としてである。

```
年間化損失期待値（ALE） = 単一損失期待値（SLE）
                        × 年間化発生率（ARO）

セキュリティ対策の価値 =
  対策前のALE − 対策後のALE − その対策の年間コスト

対策は以下の場合に資金を出す価値がある：
  (対策前のALE − 対策後のALE) > その対策の年間コスト

CAF評価は確率を直接出力しないが、あるサービスのCAF成果
プロファイル（どの貢献成果が「達成」「部分的に達成」あるいは
「未達成」か）は、AROを推定するための合理的な代理入力である
——管理されていない特権アクセスあるいはテストされていない
インシデント対応計画を持つシステムは、その両方を備えている
システムよりも実質的に高い現実的なAROを持つ。
```

## 計算例

**40,000人の住民のソーシャルケア記録を保持する州議会のケースマネジメントシステム**：

```
単一損失期待値（侵害コスト）、最近のIBM Cost of a Data Breach
Reportからの公共セクター平均を使用 ≈ £210万
（換算、桁数の数字——常に固定の数字を再利用するのではなく
現行の報告書版から再導出すること）

現在のARO（管理されていない特権アクセス、テストされていない
インシデント対応、複数の「未達成」成果を示す内部のCAF自己
評価によれば） ≈ 年間8%と推定
  対策前のALE = £210万 × 0.08 = £168,000/年

提案される対策：特権アクセス管理＋テストされたインシデント
対応計画、関連するCAF成果を「達成」に移行させ、AROを年間3%に
削減すると推定される
  対策後のALE = £210万 × 0.03 = £63,000/年

その対策の年間コスト（ツール＋プロセス＋テスト） = £45,000

対策の価値 = (168,000 − 63,000) − 45,000 = £60,000/年
  純プラス——資金を出すこと。この算術はまた、この対策が
  ほぼ3倍のコストでも依然として資金を出す価値があることを
  示しており、これは推定された確率に基づいて構築された
  あらゆるALEの数字に伴うべき種類の感度チェックである。
```

## ソフトウェア開発との関連

エンジニアはALE方程式のレバーのほとんどを所有している——アクセス制御の設計、依存関係とパッチの衛生状態、ロギングと検知の適用範囲、インシデント対応ツールはすべて直接ARO項を動かす。これが、CAF評価がポリシー監査であると同時に技術アーキテクチャレビューのように読める理由である。これは[技術的負債による公共価値の侵食](../technical-debt-as-public-value-erosion/)の最も急性の形である——パッチが当てられず、監視されず、アクセス制御が不十分なシステムは、その利子の支払いが着実な足かせではなくテールリスクである負債である——そしてこれは、セキュリティ支出がシステムの真の運用コストとは別のものとして扱われないよう、[政府ITにおける総所有コスト](../total-cost-of-ownership-in-government-it/)と照合されるべきである。これはまた、Green Bookのもとでの[バリュー・フォー・マネー](../value-for-money/)評価への直接的な入力でもある——リスク調整後のコストは、最後に後付けされるものではなく、あらゆる選択肢評価の「コスト」側の一部である。

## 落とし穴

- **CAF自己評価をセキュリティそのものとして扱うこと**：完了した評価はセキュリティの姿勢を記述する；それを作り出すのではない——価値は達成された成果にあり、文書にあるのではない。
- **調整なしにグローバル平均の侵害コストをローカルの推定値として使うこと**：IBMの数字は大規模で多様なサンプル全体の平均である。小規模な地方自治体の現実的な単一損失期待値は、国の省庁のそれとめったに同じではない。
- **投資決定においてテールリスク心理を無視すること**：低い年間確率は、その年が来るまさにその時まで、セキュリティ支出を無期限に先送りしやすくする——計算例のように、一連のAROに対してALEの計算を感度テストすることがこれに対抗する。
- **IBM方式の侵害コストだけを数え、信頼のコストを数えないこと**：デジタルチャネルを使う市民の意欲を押し下げる侵害は、その後何年にもわたって[チャネル移行による節約](../channel-shift-savings/)のケースを侵食する。これは侵害コストの推定にめったに含まれないコストである。
