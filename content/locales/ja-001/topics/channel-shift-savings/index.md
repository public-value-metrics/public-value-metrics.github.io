# チャネル移行による節約

チャネル移行による節約は、電話、対面窓口、紙の郵送のような高価なチャネルから、安価なデジタルセルフサービスへと取引量を移動させることによる予測されたコスト削減である。これは「デフォルトでデジタル」の背後にある財務エンジンであり、同時にビジネスケースの中で最も誤りである可能性が高い項目でもある。なぜなら、それが依拠する前提——デジタル利用が上昇するにつれてオフラインチャネルが縮小する——は、時にしか真実ではないからである。

## 重要な理由

Digital Efficiency Reportの[取引あたりコスト](../cost-per-transaction/)の数字を使うと、算術は議論の余地がないように見える——100万件の取引を£8.62の対面訪問から£0.15のデジタルへ移行させれば、節約は£800万を超える。しかし、節約が再配置のために解放された現金になるのは、縮小するチャネルの*固定容量*が実際に廃止された場合だけである——コールセンターの席、窓口スタッフ、電話契約の分数——そして地方自治体のデジタルプログラムは、総接触量がデジタル利用に沿って低下しないことを繰り返し発見してきた。地方自治体のデジタルトランスフォーメーションプログラムやSocitmやLocal Government Associationのような団体による研究は、繰り返し起こるパターンを文書化している——デジタルチャネルは本物の新しい接触を引き寄せる（それがより簡単になったため、以前は電話や訪問をしなかったであろう市民が今はする）、そして「デジタル」取引の相当な割合が途中で失敗し、どのみち電話をかけることになる——そのため、電話の量は、デジタル利用のパーセンテージが示唆するよりもはるかに少ししか低下せず、総接触に占める*割合*が低下しても、絶対量ではまったく低下しないこともある。

## 計算式

```
総チャネル移行節約 = 移行した量 × (旧チャネルのコスト − デジタル
                    のコスト)

純（実現された）節約 = 総節約
                      − より簡単なチャネルによって生み出された
                        新規/シャドー需要
                      − 失敗需要のコスト（それでも電話や窓口訪問を
                        生み出すデジタルの失敗）
                      − 廃止されていない固定容量のコスト
                        （コールセンターは離散的な単位でしか
                        スタッフを減らせない；15%の量の低下は
                        めったに人員の15%削減を許さない）

実現の閾値：節約は、量が旧チャネルの次に小さい離散的な容量
ステップでスタッフを配置できる水準を下回って初めて現金化できる
（例えば1シフト分、1デスク分、1契約人員帯を失うこと）
```

## 計算例

**州議会のブルーバッジ更新サービス**：年間60,000件の更新、以前は取引あたり£6.40で100%電話/紙。新しいデジタルサービスが開始され、1年以内にデジタル取引あたり£0.30で65%のデジタル利用を達成する。

```
素朴な（総）節約の計算：
  39,000件が移行 × (£6.40 − £0.30) = £237,900/年

実際に起こったこと、その議会のコンタクトセンターのデータによれば：
  電話の量は年間60,000件から46,000件へ低下（−23%、−65%ではない）
  理由：9,000件のデジタルジャーニーが失敗しフォローアップの電話を
       生み出した（失敗需要の漏出）、そして4,000人が、オンラインで
       それが簡単だと分かったため、以前はまったく更新していなかった
       のに今は更新している（シャドー需要——本物のアクセス改善だが、
       節約ではない）

  電話のコンタクトセンターは8,000件の電話/常勤換算のバンドで
  人員配置されている；14,000件の減少（60,000→46,000）は1.75人の
  常勤換算を解放し、実務上は切り下げられて実際に再配置された
  のは1人の常勤換算 = £34,000/年

実現された節約 = £34,000/年に加え、39,000件の取引で回避された
  デジタルチャネルの構築/運用コスト ≈ £34,000 +（39,000×£0.30の
  デジタルコストはすでに計算済み）——サービスがユーザーにとって
  依然として明確により良いものであるにもかかわらず、£237,900の
  見出しのほんの一部にすぎない。
```

## ソフトウェア開発との関連

エンジニアリング上の教訓は、チャネル移行による節約が、ソフトウェアの出荷によってではなく、*運用上の*決定（配置計画、廃止、契約再交渉）によって実現されるということである——誰も旧チャネルの固定容量を廃止しなければ、チームはあらゆる[デジタルサービス標準](../digital-service-standard/)の項目を達成しながら、それでも純節約ゼロを提供しうる。失敗需要（デジタルジャーニーのどこで利用者が離脱し、次に何をするか）を計装することは解決可能な漏斗分析の問題であり、エンジニアリングチームが節約のケースを守るためにできる最もレバレッジの高い単一のことである。これはまた、失敗需要が静かに膨らませる[取引あたりコスト](../cost-per-transaction/)への直接的なリンクでもある。ビジネスケースの節約が実際に着地することを確認するより広い規律については[便益実現](../benefits-realization/)を、なぜオフラインチャネルが通常完全に廃止できない、また廃止すべきでないかについては[デジタル・インクルージョン](../digital-inclusion/)を参照。

## 落とし穴

- **1対1のチャネル代替を仮定すること**：地方自治体のチャネル移行の研究で文書化されたシャドー需要と失敗需要の漏出を無視して、デジタル利用を電話/窓口の量からの直接的な差し引きとしてモデル化すること。
- **廃止前に総節約を計上すること**：利用が上昇した年に、旧チャネルの容量が実際に削減された年（もしあれば）ではなく、ビジネスケースにおいてその節約を数えること。
- **人員配置コストの階段関数的な性質を無視すること**：20%の量の低下がめったに20%のコスト低下に変換されない。なぜなら、コンタクトセンターと窓口は連続的にではなく離散的なバンドで人員配置されるからである。
- **シャドー需要を無駄として扱うこと**：以前は除外されていた、あるいは以前は思いとどまっていた利用者からの新しい接触は、[公共価値](../public-value/)における本物の増加であり、モデル化の誤りではない——それは雑音として相殺されるのではなく、アクセス上の成果として報告されるべきである。
