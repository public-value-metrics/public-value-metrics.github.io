# 政府ITにおける総所有コスト（TCO）

総所有コストは、あるシステムの完全なライフサイクルコスト——取得に加え、それを運用するすべての年——を共通の日付に割り引いたものである。政府ITにおいて、単一の最も信頼できる予測の誤りは、運用と保守が典型的には生涯のコストの半分から5分の4を占めるにもかかわらず、供給業者あるいは選択肢を取得価格だけで比較することである。

## 重要な理由

HM TreasuryのGreen Bookは、あらゆる五つのケースモデルのビジネスケースの財務ケースが、資本支出だけでなく生涯全体のコストをカバーすることを求めている——それでもNational Audit Officeは、各省庁が不完全あるいは楽観的な運用コスト予測に対してIT投資を承認し、そのシステムが稼働し資本予算の行が閉じられて初めて真の運用コストを発見することを繰り返し発見してきた。Government Digital ServiceとCentral Digital and Data OfficeのTechnology Code of Practice（<https://www.gov.uk/guidance/the-technology-code-of-practice>）は、各省庁をクラウドとコモディティホスティングへと押し進めている。これは部分的に、承認時には魅力的に低く見え3年後には高くつく誤りとなる単一の資本調達の数字の中に埋もれさせるのではなく、継続的なコストを目に見え比較可能にするためである。

## 計算式

```
TCO = 取得コスト + Σ(t=1..N) 年間運用コスト_t / (1+r)^t
      − 残存価値（割引後）

r = HM TreasuryのGreen Bookの標準的な社会的割引率、年3.5%
    （30年を超える期間には低減する率のスケジュール）

運用コストの構成要素：ホスティング/ライセンス、サポートと保守、
セキュリティパッチとコンプライアンス、スタッフ時間、計画された
更新/移行
```

典型的な5〜10年のシステム寿命にわたって割引係数がなぜ重要かについては[社会的割引率](../social-discount-rate/)を、TCOがどう内製か購入かの決定に供給するかについては[政府における内製か購入か](../build-vs-buy-in-government/)を参照。

## 計算例

ある省庁が、Green Bookの3.5%の割引率で5年間の展望にわたって二つのケースマネジメントシステムを比較する。

```
システムA：資本支出£3,500,000、運用支出£250,000/年
システムB：資本支出£1,800,000（安く見える）、運用支出£650,000/年
          （より重いベンダーサポートと統合の負担）

資本支出だけの素朴な比較：Bが勝つ、£180万＜£350万。

割引係数の合計、3.5%で5年間：0.966+0.934+0.902+0.871+0.842
  ≈ 4.515

TCO_A = 3,500,000 + 250,000 × 4.515 = 3,500,000 + 1,128,750
      = £4,628,750
TCO_B = 1,800,000 + 650,000 × 4.515 = 1,800,000 + 2,934,750
      = £4,734,750
```

TCOは素朴な決定を覆す——運用コストが割引され合計されると、システムBはシステムAの生涯コストの24%に対して62%（2,934,750 / 4,734,750）を運用支出が占めるため、5年間でわずかに高くつく——これは、定価を比較することによって完全に隠される「保守が請求の大部分を占める」という発見の具体的な事例である。

## ソフトウェア開発との関連

TCOは、あらゆる[内製か購入か](../build-vs-buy-in-government/)の決定とあらゆる[技術的負債](../technical-debt-as-public-value-erosion/)の返済のケースを規律すべき数字である。なぜなら、負債の利子と先延ばしにされた保守は、誰かがそれを追跡していたかどうかにかかわらず、どちらも同じ割引された合計に属する運用コストの行だからである。プラットフォームあるいはベンダーの選択を提案するエンジニアは、調達価格ではなく完全なTCO表を提示すべきである。なぜなら、調達価格こそが、まさにGreen Bookの財務ケースが各省庁がそれだけに頼ることを止めるために設計された数字だからである。TCOはまた、[バリュー・フォー・マネー](../value-for-money/)の判断の正直な分母でもある——VFMは便益をコストと比較しており、過小に数えられたコストの行は、ビジネスケースにおけるあらゆるVFM比率を膨らませる。

## 落とし穴

- **資本支出だけの比較**：最も一般的な単一の調達上の誤り——各選択肢に対する一致した運用コスト予測なしに、供給業者の定価を比較すること。
- **離脱・移行コストを除外すること**：契約終了時のデータ抽出、プラットフォームの移行、ベンダーロックインのペナルティは、元のビジネスケースにはめったに現れない実際のTCOの行である。
- **セキュリティとコンプライアンスコストを除外すること**：パッチの頻度、認定の更新、監査コストはシステムの年齢と複雑さに応じて拡大する——[公共セクターのサイバーセキュリティの価値](../public-sector-cybersecurity-value/)を参照——そしてこれらは日常的に運用支出の予測から抜け落ちる。
- **異なるコストプロファイルを持つ選択肢を割引なしで比較すること**：資本支出の重い選択肢と運用支出の重い選択肢を割引なしで比較することは、たまたまより多くのコストを後年に先延ばしにしている選択肢を体系的に有利にする。
