# 多准则决策分析（Multi-Criteria Decision Analysis, MCDA）

MCDA 同时针对若干个独立的、加权的标准对各方案进行评分和权衡，产出一个排名比较结果，而不强行将每一项标准都压缩进一个货币或自然单位的尺度中。它是那些真正无法归约为单一数字的重要成果所对应决策场景的评估方法。

## 为何重要

《绿皮书》明确认可 MCDA（其方框 2 的案例研究附录和附录 A 都直接讨论了它），用于那些效益"真正不可通约"的评估——即通过[社会成本效益分析](../social-cost-benefit-analysis/)将一切折算成货币、或通过[成本效果分析](../cost-effectiveness-analysis-in-government/)折算成单一成果，会扭曲而非澄清该决策的情形（<https://www.gov.uk/government/publications/the-green-book-appraisal-and-evaluation-in-central-government>）。例如，为一座新监狱选址，需要在资本成本、社区影响、交通连通性、环境影响和员工招募可行性之间做出权衡——这些标准没有共同的单位，而强行赋予一个共同单位（通常是货币），会把一种关于环境影响相对于成本孰轻孰重的价值判断，包装成客观的算术运算而偷偷带入。

MCDA 的诚实性同时也是它最大的脆弱之处：因为权重是由负责该评估的人（或一个评审小组）设定的，该方法的合法性完全取决于权重设定过程本身。《绿皮书》指南明确要求，标准和权重必须在对各方案打分*之前*就商定并公布，正是为了防止评审者从一个已属意的方案倒推出能够为其辩护的权重。

## 数学原理

```
对每个方案 i 和每项标准 j：
  分数_ij   = 该方案在该标准上的表现（通常为 0-100 或
              1-10，来自证据、专家判断或利益相关方评分）
  权重_j    = 标准 j 的相对重要性，各权重之和为 1（或 100）

方案 i 的加权分数 = Σ_j (分数_ij × 权重_j)

流程：
1. 在对任何方案打分之前，先商定标准集合和权重
   （摆动权重法或成对比较法，例如层次分析法 AHP，
   是常见的权重征询方法）。
2. 尽可能依据证据，在同一尺度上对每个方案的每一项
   标准进行打分。
3. 计算加权总分；对各方案排序。
4. 对权重进行敏感性检验：如果对各标准应有多重要存在
   合理的分歧，排名结果是否依然稳健？
```

MCDA 不像 SCBA 的净现值那样产出一个可辩护的绝对数值——它只产出一个以所商定权重为条件的排名。当决策真正涉及在不可通约的多种善之间进行权衡时，这是一个优点；但如果被用来逃避原本可行的、更为艰难的货币化工作，这就成了一个缺陷。

## 实例演算

**地方政府**：某议会在为新建家庭废弃物回收中心选址时，在实地考察之前，由一个跨部门评审小组针对四项标准对三处场地进行了加权评分：

```
标准（权重）：            资本成本(30%)  交通可及性(25%)
                          社区影响(25%)  环境影响(20%)

场地评分（0-100，越高越好）：
场地 A：成本 80，可及性 60，社区 40，环境 70
场地 B：成本 60，可及性 90，社区 70，环境 50
场地 C：成本 90，可及性 50，社区 80，环境 60

加权总分：
场地 A = 80(.30) + 60(.25) + 40(.25) + 70(.20) = 24+15+10+14 = 63
场地 B = 60(.30) + 90(.25) + 70(.25) + 50(.20) = 18+22.5+17.5+10 = 68
场地 C = 90(.30) + 50(.25) + 80(.25) + 60(.20) = 27+12.5+20+12 = 71.5
```

场地 C 排名最高。将社区影响权重从 25% 调升至 35%（从资本成本中扣去 10 个百分点）的敏感性测试，会使场地 C 的总分变为 71.5 − 3 + 8 = 76.5，场地 B 的总分变为 68 − 6 + 7 = 69——场地 C 仍然领先，因此该排名对这种合理的权重分歧具有稳健性，而这正是《绿皮书》期望看到被报告出来的那种检验。

**慈善机构**：一家拨款基金会在债务咨询服务、食物银行网络和财务素养项目之间进行资助选择时，使用 MCDA 而非 SROI（参见[社会投资回报](../social-return-on-investment/)），正是因为受托人们出于善意，在危机救助与预防孰重孰轻的问题上存在分歧——MCDA 让他们能够就这一分歧的*形态*（一个权重区间）达成一致，而不是假装一个单一的 SROI 比率就能解决它。

## 与软件工程的关联

当各项标准真正相互冲突时，MCDA 是供应商和架构选型的天然工具——在选择云托管与本地部署的个案管理系统之间，需要在成本、数据主权风险、可及性和交付速度之间进行权衡，而这些无法归约为一个数字。工程负责人应当坚持在对各方案打分之前就完成权重设定，正如《绿皮书》所要求的那样，因为在看到备选名单之后才进行的权重设定，几乎必然会向房间里已经偏好的那个方案漂移。关于 MCDA 的一个常见应用，参见[政府中的自建与外购之争](../build-vs-buy-in-government/)；关于一个相关的、在决策*之后*而非决策*之前*使用的结构化评分工具，参见[公共价值计分卡](../public-value-scorecard/)。

## 常见陷阱

- **在看到各方案之后才设定权重。** 这是 MCDA 最常见的被操纵方式，无论是否出于故意；应在打分之前公布权重，并记录是谁设定的。
- **将加权总分当作一个硬性数字。** 71.5 对比 68 的分差，除非敏感性分析证实排名是稳定的，否则并不具有统计学意义；应报告区间，而不是虚假的精确度。
- **用 MCDA 来回避本来可行的货币化工作。** 如果大多数标准本可以被可信地定价，默认使用 MCDA 而非 [SCBA](../social-cost-benefit-analysis/) 会丢弃该评估本可利用的信息。
- **让一位占主导地位的利益相关方独自设定全部权重。** 《绿皮书》的良好实践期望权重是从一个具有代表性的评审小组中征询而来的，而不是来自主办的负责人，以避免评估结果只是重新推导出那个人本来就想要的答案。
