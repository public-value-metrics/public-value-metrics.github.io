# 政府即平台（Government as a Platform, GaaP）

"政府即平台"是这样一种策略：将共享的、可复用的组件——一项通知服务、一项支付服务、一项身份验证服务——只在中央层面构建一次，从而使成百上千项独立的政府服务能够直接调用它们，而不是各自重复构建。它将公共数字基础设施重新定位为一个平台经济学问题：价值不在于任何一次具体的集成，而在于*下一个*采用它的团队所面对的边际成本趋近于零。

## 为何重要

政府数字服务局（GDS）在其 2015 年发布的《政府即平台》（"Government as a Platform"）出版物中正式提出了这一策略，指出政府一直在一个又一个服务中分别重复构建相同的能力——收取支付、用户通知、身份验证、地址查询——每一次都各自承担采购、安全评估和持续支持的负担。替代方案是构建少数几个共享平台，一次性建成高标准并在各处复用：用于发送电子邮件、短信和信件的 GOV.UK Notify、用于在线收款的 GOV.UK Pay，以及用于身份验证的 GOV.UK One Login（早期 GOV.UK Verify 身份项目的后继者）。这些平台所达到的规模，正是这一策略行之有效的最清晰证据：GOV.UK Pay 已在约 1,800 项独立服务中处理了超过 100 亿英镑的交易额——处理第一个 10 亿英镑用了约四年时间，如今处理同样的金额只需约五个月——而 GOV.UK Notify 已代表超过 1,500 个政府机构发送了超过 90 亿条消息。每一个采用这些平台的服务，都省去了自行构建、保障和维护支付网关或消息发送流水线的负担。

## 数学原理

```
每项服务的建设成本（无平台）= N 项服务 × 构建、安全评估
  并运行一套支付/通知/身份验证系统的成本

平台成本 = 固定的平台建设成本
         + 每个采用平台的服务的边际成本
           （集成、配置、持续的平台团队支持）

复用实现盈亏平衡的条件：
  平台建设成本 < N × （单项服务建设成本 − 边际集成成本）

对于一个成熟的平台而言，每新增一个采用者的边际成本
会趋近于仅剩交易/消息费用本身——固定成本被摊销到
整个政府资产范围内，而不是由某一个部门的预算独自承担，
这正是 GaaP 组件通常由中央出资、而不是向早期采用者
按全成本收回费用的原因。
```

## 实例演算

**某地方政府采用 GOV.UK Pay，而不是自建支付网关**：

```
自建方案估算：
  PCI-DSS 合规工作 + 集成 + 持续维护
  ≈ 85,000 英镑建设成本 + 22,000 英镑/年维护成本

采用 GOV.UK Pay：
  集成工作量 ≈ 12,000 英镑（开发者工时）
  交易费用：政府对公民的银行卡支付通常按小比例
  加每笔固定费用收取，议会无需另行承担 PCI-DSS
  合规负担
  ≈ 一次性 12,000 英镑，后续成本随交易量变化而非固定

首年节省 ≈ 85,000 − 12,000 = 73,000 英镑，这还不包括
避免的每年 22,000 英镑维护成本，以及避免在议会自营
系统中持有银行卡数据所带来的合规风险——后一类价值
在 public-sector-cybersecurity-value 中有所论述。
```

将这 73,000 英镑的节省乘以目前使用 GOV.UK Pay 的约 1,800 项服务，政府整体避免的建设成本合计将达到数亿英镑之巨——这一策略的真正价值所在，正是平台经济学本身，而不是任何单次集成。

## 与软件工程的关联

"政府即平台"是支持[政府中的自建与外购之争](../build-vs-buy-in-government/)的一个直接论据：当一个已经过评估、运行良好的共享组件存在时，构建一个定制的等价物，在物有所值方面几乎从来都不是更优的选择，而且几乎从定义上就会未通过[数字服务标准](../digital-service-standard/)第 13 条（"使用并贡献于开放标准、通用组件与设计模式"）。它也改变了[政府 IT 中的总拥有成本](../total-cost-of-ownership-in-government-it/)的形态：采用平台，是用一大笔资本和维护支出，换成一笔更小、与使用量挂钩的运营成本，这更容易预测，也更容易在某项服务下线时停止资助。组件的开放复用，在[开放数据的价值](../open-data-value/)中有一个同类做法——两者都是将政府生产一次的东西，当作共享基础设施而非部门资产来对待的策略。

## 常见陷阱

- **暗中重复自建**：团队因为平台的接入流程比自己动手更慢，而悄悄构建自己的支付或通知集成方案——这是一个治理摩擦问题，而非技术问题，它会在不知不觉中侵蚀整个策略所依赖的复用经济学。
- **平台团队获得的资金与其创造的价值不成比例**：价值累积在使用该平台的各部门，而成本则由平台团队承担，这会造成长期投入不足的风险，除非资金来源集中且受到保护——这是"公地悲剧"的一种变体。
- **仅以使用量衡量平台的成功**：采用数字（已接入的服务数、已发送的消息数）是一个领先指标，而不是价值的证明；真正的检验标准是上文所述的避免建设成本与避免风险的算式。
- **将"平台"等同于"单体系统"**：GaaP 组件之所以成功，是因为每一个都通过狭窄、稳定的接口把一件事做好；将互不相关的能力捆绑进同一个"平台"，只是在另一个尺度上重现了定制自建的问题。
