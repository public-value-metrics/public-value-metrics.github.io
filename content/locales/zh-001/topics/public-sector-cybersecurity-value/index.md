# 公共部门网络安全价值（Public Sector Cybersecurity Value）

公共部门网络安全价值是一门为风险降低定价的学问：既然安全支出在奏效时不产生任何可见的产出、而在失效时却会产生非常显眼的后果，那么降低公民数据被泄露的可能性究竟值多少钱？对于一项持有福利记录、健康数据或税务记录的服务而言，这种"奏效时不可见"的特性，正是它需要一个明确的价值论证、而不只是一个合规打钩的原因所在。

## 为何重要

英国国家网络安全中心（National Cyber Security Centre，NCSC）的网络评估框架（Cyber Assessment Framework，CAF），为公共部门组织提供了一套结构化方法，将安全变成一门可评估的、以成果为基础的学科，而不是一份检查清单：它定义了四大高层目标（管理安全风险、防范网络攻击、发现网络安全事件、将事件影响降到最低），并将其拆解为系统所有者可据以接受评估的贡献性成果，其精神与[数字服务标准](../digital-service-standard/)第 9 条（"创建一项能保护用户隐私的安全服务"）如出一辙。CAF 评估所防范的风险，有据可查的价格标签：IBM《数据泄露成本报告》按行业跟踪平均泄露成本，并一贯发现公共部门处于该区间的较低端，低于金融或医疗行业——最近几版报告将公共部门平均泄露成本定在每次约 260 万至 290 万美元——但"低于金融行业"不等于"低"，而且政府泄露事件所承担的成本，是该报告的数字未能完全捕捉到的：公民对数字渠道的信任受损，会压低渠道转移商业论证所依赖的[数字化采用率](../channel-shift-savings/)，还有泄露国家强制公民交出的数据所带来的政治和法律成本。

## 数学原理

安全投资的估值方式，与任何降低风险的支出一样：作为预期损失的减少，使用经典的风险管理恒等式。

```
年化损失预期（ALE） = 单次损失预期（SLE）
                     × 年化发生率（ARO）

一项安全控制措施的价值 =
  控制措施实施前的 ALE − 控制措施实施后的 ALE − 该控制措施的年度成本

当以下条件成立时，一项控制措施值得投入资金：
  (ALE_实施前 − ALE_实施后) > 该控制措施的年度成本

CAF 评估本身不会直接输出一个概率，但一项服务的 CAF
成果概况（哪些贡献性成果是"已达成""部分达成"或"未达成"）
是估计 ARO 的一个合理代理输入——一个特权访问未受管理、
或没有经过测试的事件响应计划的系统，其现实的 ARO 会
明显高于两者都已到位的系统。
```

## 实例演算

**某郡议会持有 40,000 名居民社会关怀记录的个案管理系统**：

```
单次损失预期（泄露成本），使用 IBM 近期《数据泄露成本报告》
中的公共部门行业平均值 ≈ 210 万英镑
（经货币换算，数量级示例数字——应始终从当前版本的报告
重新推导，而不是沿用一个固定数字）

当前 ARO（特权访问未受管理，没有经过测试的事件响应计划，
根据内部 CAF 自我评估显示多项"未达成"成果）≈ 估计每年 8%
  ALE_实施前 = 210万英镑 × 0.08 = 168,000 英镑/年

拟议控制措施：特权访问管理 + 经过测试的事件响应计划，
将相关 CAF 成果提升为"已达成"，估计可将 ARO 降至每年 3%
  ALE_实施后 = 210万英镑 × 0.03 = 63,000 英镑/年

该控制措施的年度成本（工具+流程+测试） = 45,000 英镑

该控制措施的价值 = (168,000 − 63,000) − 45,000 = 60,000 英镑/年
  净收益为正——应予资助。这一算式还显示，即便成本
  接近现在的三倍，该控制措施依然值得资助，这正是
  任何基于估计概率构建的 ALE 数字都应附带的那种
  敏感性检验。
```

## 与软件工程的关联

工程师掌握着 ALE 方程中的大多数杠杆：访问控制设计、依赖项和补丁管理卫生、日志与检测覆盖率、以及事件响应工具，这些都直接影响 ARO 这一项，这正是 CAF 评估读起来既像技术架构审查、又像政策审计的原因所在。这是[技术债作为公共价值侵蚀](../technical-debt-as-public-value-erosion/)最急性的一种表现形式——未打补丁、未受监控、访问控制不佳的系统是一种其"利息"以尾部风险而非稳定拖累形式支付的债务——它应当与[政府 IT 中的总拥有成本](../total-cost-of-ownership-in-government-it/)相互核对，避免安全支出被当作与系统真实运行成本无关的独立项目来对待。它也是《绿皮书》下[物有所值](../value-for-money/)评估的直接输入项：经风险调整的成本是任何方案评估中"成本"一侧的组成部分，而不是最后附加上去的事后考量。

## 常见陷阱

- **将 CAF 自我评估当作安全本身。** 一份已完成的评估描述的是一种安全态势；它本身并不创造这种态势——价值在于所达成的成果，而不在于这份文件本身。
- **未经调整就将全球平均泄露成本用作本地估计值。** IBM 的数字是跨越大型、多样化样本的平均值；一个小型地方政府现实中的单次损失预期，很少与一个中央政府部门相同。
- **在投资决策中忽视尾部风险心理。** 较低的年度概率使安全支出很容易被无限期推迟——直到它不再是低概率事件的那一年为止——像实例演算中那样，针对一系列 ARO 值对 ALE 计算进行敏感性检验，可以纠正这种倾向。
- **只计算 IBM 式的泄露成本，而不计算信任成本。** 一次压低公民使用数字渠道意愿的泄露事件，会在此后数年侵蚀[渠道转移节约](../channel-shift-savings/)的论证基础，而这项成本很少被计入泄露成本估算之中。
