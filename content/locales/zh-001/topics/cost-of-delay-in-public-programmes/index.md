# 公共项目中的延迟成本（Cost of Delay, CoD）

延迟成本，是指一项项目、服务或系统变更每延迟一个单位时间*尚未*交付所损失的公共价值。它是本章的核心桥梁指标：它将"上线延后了六个月"转化为每周多少英镑，或每周多少 WELLBY，从而使人们能够用与商业论证本身相同的"货币"来讨论延迟问题。

## 为何重要

Reinertsen 的法则——"如果你只量化一件事，那就量化延迟成本"——几乎原封不动地适用于政府领域，因为公共项目对这一问题的暴露程度格外高：商业论证是按照预测的效益流获批的，但该效益流只有在上线之后才开始流动，而每一周的延误都是一周被放弃的价值，却从来没有人在风险登记册上为它定价。国家审计署（National Audit Office）对 Universal Credit 推行工作的多次审查（参见其"Rolling Out Universal Credit"系列报告，<https://www.nao.org.uk/>）正说明了这种模式：进度延误被跟踪和报告，但改革后的系统*尚未*交付给下一批申领人所造成的每周英镑成本，却很少被作为头条数字明确列出，尽管这正是本应驱动优先级排序和上报升级的数字。没有延迟成本数字，一个延误的项目对交付委员会而言看起来只是一个进度问题；有了它，它就是会计官员必须面对的一个价值侵蚀问题。

## 数学原理

```
延迟成本 = 尚未交付期间每单位时间所放弃的效益   （英镑/周 或 WELLBY/周）

总延迟损失 = 延迟成本 × 延迟时长

公共项目应加总的效益流：
  可释放现金的节约  （欺诈/差错减少、避免的临时性成本）
+ 非现金型释放产能  （个案工作人员/官员工时 × 全成本）
+ 福祉效益         （WELLBY × 每 WELLBY 13,000 英镑，财政部
                     《绿皮书》福祉补充指南，2019 年价格）
```

对于面向公民的服务，应同时以福祉和金钱计价——关于其基础单位，参见[福祉调整生命年](../wellbeing-adjusted-life-years/)；关于延迟的那笔钱原本还能资助什么，参见[公共支出中的机会成本](../opportunity-cost-in-public-spending/)。

## 实例演算

**地方政府**：某住房福利系统升级，使 2 万份在办申领案件的多付差错每份每年减少 150 英镑。

```
年度效益 = 150 × 20,000 = 3,000,000 英镑/年
延迟成本 = 3,000,000 / 52 ≈ 57,700 英镑/周
延迟实施 12 个月将造成 52 × 57,700 ≈ 3,000,000 英镑的本可避免差错。
```

**中央政府机构**：某残障福利评估服务比计划推迟六个月（26 周）交付，意味着每年 20 万名申领人平均要多等三周才能拿到决定结果。每多等一周所带来的财务不确定性，按 −0.0018 个 WELLBY（生活满意度点数）的效应建模：

```
每名申领人的 WELLBY 损失 = 3 × 0.0018 = 0.0054
年度 WELLBY 损失 = 200,000 × 0.0054 = 1,080 WELLBY/年
福祉延迟成本 = 1,080 / 52 ≈ 每周 20.8 个 WELLBY
货币化延迟成本 = 20.8 × 13,000 英镑 ≈ 每周 270,000 英镑的福祉价值
```

因此，26 周的延迟大约"耗费"了 540 个 WELLBY——按《绿皮书》的福祉估值约合 700 万英镑——这将一个错过的上线日期重新定性为一起公民福祉事件，而不只是项目管理层面的一条注脚。

## 与软件工程的关联

正是延迟成本，使得 [DORA 指标](../dora-metrics-for-public-value/)与[政府交付中的流动指标](../flow-metrics-in-government-delivery/)具备了财务上的可读性：流水线中的交付前置时间 × 延迟成本，就是在排队等候期间、在触达公民之前被消耗掉的金钱（或福祉）。具体而言：

- **优先级排序**：按延迟成本 ÷ 工期而非利益相关方的级别对积压工作进行排序——这是《绿皮书》要求按价值而非提出者身份评估方案这一原则在软件工程中的对应做法。
- **采购**：一个 12 至 18 个月的框架采购周期本身就有延迟成本；为其定价会改变加速采购路径的紧迫性论证，并直接影响[自建与外购之争](../build-vs-buy-in-government/)中价值实现时间作为决策驱动因素的决策。
- **效益论证**：在获批时引用的每一个延迟成本数字，都应在[效益实现](../benefits-realization/)阶段重新出现——如果延迟成本是真实的，那么加速带来的效益就应当在上线后是可测量的。

## 常见陷阱

- **假定延迟成本是线性的**：某些公共服务的价值呈"截止日期形"（例如某个法定合规日期——延迟成本在该日期之后跳升至执法风险水平，之前则接近于零），而非平滑的周成本率。应先对紧迫性特征进行分类，再进行乘算。
- **为无人需要的产出计算延迟成本**：只有当未交付之物具有价值时，延迟才具有成本；一个无人会使用的系统，无论多晚交付，其延迟成本都为零。
- **将延迟成本与折现重复计算**：[社会折现率](../social-discount-rate/)已经为跨年度评估周期中的时间定价；延迟成本是评估周期*内*、以周和月为单位的运营层面版本。进度延误使用延迟成本，多年度重新分期使用净现值变化。
