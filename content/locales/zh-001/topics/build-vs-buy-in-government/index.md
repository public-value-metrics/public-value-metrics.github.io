# 政府中的自建与外购之争（Build vs Buy）

自建与外购之争（build-vs-buy）是一种结构化的、经过风险调整的比较，将定制开发与商用或通用采购方案，在折现后的[总拥有成本](../total-cost-of-ownership-in-government-it/)、价值实现时间和风险三个维度上进行对比。从结构上讲，政府本质上是一个采购型部门——技术操守准则（Technology Code of Practice）确立了偏向通用与云端解决方案的预设立场——但各部门内部的工程团队仍然默认倾向于自建，理由与世界各地的建设者们如出一辙。

## 为何重要

政府数字服务局（Government Digital Service）的《技术操守准则》（<https://www.gov.uk/guidance/the-technology-code-of-practice>）及配套的《服务手册》（Service Manual）中关于自建或外购决策的指南，要求各部门在预设"通用能力应当购买而非自建，只有真正新颖、能体现使命差异化的能力才值得定制开发"的前提下，为定制开发提供正当理由。财政部《绿皮书》关于乐观偏差的补充指南，源自 2002 年 Mott MacDonald 对大型公共采购项目的审查，在所评估的各类别中，IT 项目获得了最大的上调区间——建议在用于评估之前，将资本成本估算下限上调 10%、上限最高上调 200%，这反映出软件建设项目在整个公共采购历史中曾被严重低估的程度。自建与外购分析存在的意义，正是要在获批之前将这种风险调整摆上台面，而不是让它以年度超支申请的形式事后浮现。

## 数学原理

```
在相同的 3–5 年周期内比较，按《绿皮书》的社会折现率折现
（参见 social-discount-rate.md）：

方案净现值 = PV（按价值实现时间调整后的效益） − PV（总拥有成本）

风险调整（《绿皮书》乐观偏差模式）：
  自建成本 × 1.1–3.0        （IT 项目上调区间，Mott MacDonald）
  自建价值实现时间 + 40–60%  （部署延迟先验值）
  外购：改为加上集成现实检验成本与合同退出成本

决策驱动因素，按通常的决定性顺序排列：
  1. 差异化程度——这项能力是使命所在，还是基础管道？
  2. 价值实现时间 × 延迟成本（参见 cost-of-delay-in-public-programmes.md）
  3. 经风险调整后的总拥有成本
```

## 实例演算

某地方政府需要一套成人社会关怀个案管理系统。外购方案：SaaS 服务，每年 18 万英镑，4 个月内上线。自建方案：预估 90 万英镑，另加每年 15 万英镑维护费，14 个月内上线。

```
经风险调整后的自建成本 = 900,000 × 1.4 = 1,260,000 英镑
五年总拥有成本：
  外购  = 180,000 × 5 = 900,000 英镑
  自建  = 1,260,000 + 150,000 × 5 = 2,010,000 英镑

延迟成本项：该系统每月可避免 40,000 英镑的重复评估支出；
自建方案比外购方案晚 10 个月上线。
延迟成本 = 10 × 40,000 = 400,000 英镑

实际比较：900,000 英镑（外购） vs 2,010,000 + 400,000 = 2,410,000 英镑（自建）
```

五年内外购方案胜出约 150 万英镑，而在自建成本估算本身之外最大的一项，正是纯资本支出比较永远不会揭示出来的延迟成本。

## 与软件工程的关联

从这一分析可以直接迁移到交付实践中的纪律包括：**基于先验值的风险调整**——Mott MacDonald 的上调系数，就是机械化应用《绿皮书》乐观偏差原则在软件领域的对应做法，团队应当为例外情况争取论证，而不是想当然地认为自己的估算就是例外；**对照方案的诚实性**——自建的替代方案是可获得的最佳外购选项，而不是"什么都不做"，这与[公共支出中的机会成本](../opportunity-cost-in-public-spending/)直接相关；以及**诚实的总拥有成本比较**——每一份自建方案都应对照外购方案完整的[总拥有成本](../total-cost-of-ownership-in-government-it/)，而不是其标价来进行比较。在自建确实胜出的情况下，额外自建时间所带来的[延迟成本](../cost-of-delay-in-public-programmes/)应当在商业论证中明确定价，而不是被留作一个"时间不重要"的未言明假设。

## 常见陷阱

- **将供应商标价与未经风险调整的自建估算相比较**：这会使自建方案在成本和工期两方面都被双重美化。
- **内部人力零成本化**：公务员的工程工时因已计入部门人头预算而被视为"免费的"，这掩盖了该团队本可从事其他工作所付出的真实机会成本。
- **双向都未定价的锁定风险**：供应商退出与数据可移植性成本是真实的，但定制自建方案在其生命周期内对一支规模小、难以替代的内部团队的依赖（即"巴士因子"风险）同样真实。
- **将基础管道包装成使命差异化能力**："这是我们的核心"这一说法被用于集成中间件或文档存储系统——应当检验：公民或个案工作人员是否真的会在意底层运行的究竟是哪一套系统。
