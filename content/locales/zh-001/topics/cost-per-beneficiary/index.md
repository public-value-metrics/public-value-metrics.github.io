# 单位受益人成本（Cost per Beneficiary）

单位受益人成本，是项目总成本除以接受服务的独立个人数量——只要被接触到就算，无论其处境是否真正发生了改变。这是一个组织能够产出的最快速的效率数字，因为"我们服务了谁"几乎总是已经存在于个案管理系统之中，而"谁真正得到了帮助"通常则不然。

## 为何重要

资助方经常索要单位受益人成本，而且理由充分：它可以立即获得，可以在一个由差异极大的项目组成的组合中进行比较，而且在触达范围方面是诚实的——这一点是成果类声明（往往需要更长时间才能核实，也更容易被夸大）所不具备的。英国慈善机构 SORP（推荐惯例声明，Statement of Recommended Practice）规范了慈善机构在 FRS 102 准则下的报告方式，要求受托人年度报告描述相对于宗旨所取得的成就，但大多数较小的慈善机构在管理账目中仍默认使用基于触达范围的单位成本，因为它们制作成本低廉，也便于审计。

危险之处在于，将单位受益人成本当作它无法回答的问题——这笔钱是否真正发挥了作用——的答案来使用。关于真正回答这一问题的指标，参见[单位成果成本](../cost-per-outcome/)；关于其背后的区分，参见[成果与产出](../outcomes-vs-outputs/)。单位受益人成本是一项合理的分诊与触达范围指标——它告诉资助方资金能覆盖多远——但一个较低的单位受益人成本，既可能意味着真正的效率，也可能意味着一项服务过于单薄，什么都没有改变。

## 数学原理

```
单位受益人成本 = 项目总成本 / 获得服务的独立个人数

对照：
单位成果成本      = 项目总成本 / 达成既定成果的人数

单位受益人成本总是 ≤ 单位成果成本，因为达成成果的人群
是受益人群体的一个子集（往往是一个很小的子集）。
```

## 实例演算

**某食物银行，与单位成果成本示例同一年份**：

- 项目总成本：450,000 英镑
- 获得服务的独立家庭数（获得三份以上救济包）：1,800

```
单位受益人成本 = 450,000 英镑 / 1,800 = 每个获服务家庭 250 英镑
```

将两个指标并排对比：

| 指标 | 分母 | 结果 |
|---|---|---|
| 单位受益人成本 | 1,800 个获服务家庭 | 250 英镑 |
| 单位成果成本 | 630 个实现食品保障的家庭 | 714 英镑 |

一个只看到 250 英镑的资助方，可能会得出这是一家高效率慈善机构的结论。而一个同时看到两个数字的资助方，则可以提出更有用的问题：触达范围（1,800）与成果（630）之间的差距，究竟是数据收集上的缺口、设计上的缺口，还是对仅凭食品援助实现食品保障究竟有多难这一现实的如实反映？

**某职业培训慈善机构，示例性数据**：单位受益人成本（已报名）= 2,000 英镑；单位成果成本（6 个月后持续就业）= 11,000 英镑，因为只有 18% 的报名者完成了项目并找到了持续性工作。这两个数字相差五倍，在完成率或持久性偏低的地方十分常见——从这一点来看，一家职业培训慈善机构与一家食物银行在结构上并无二致。

## 与软件工程的关联

单位受益人成本之所以成为非营利软件中的默认指标，是因为它是从一条受益人记录中无需额外工作即可得出的指标：创建一个个案、记录一次服务、统计行数。要构建一个同样支持单位成果成本的系统，就意味着要有意添加第二个一等实体——一个独立于服务交付而被定义和标注日期的成果事件——并抵制让"个案已关闭"顶替"成果已达成"的诱惑。在规划拨款管理或 CRM 平台的范围时，应当询问每一块仪表盘展示的究竟是这两个指标中的哪一个，并相应地加以标注；在单一的"影响力"图块中将两者混为一谈，是导致下文常见陷阱的最常见软件层面原因之一。关于在正确标注后对任一指标进行基准比较，参见[单位成本数据库](../unit-cost-databases/)。

## 常见陷阱

- **将单位受益人成本当作影响力来呈现。** 它衡量的是触达范围，而不是改变。仪表盘和报告应标注为"每服务人次成本"，而不是"每帮助一人成本"。
- **跨项目重复计算。** 如果分母的目的是描述独立触达人数，那么一个同时接受同一慈善机构食物救济包和债务咨询的人，应算作一名受益人，而不是两名；应确定并记录所采用的统计惯例。
- **认为数字越低就一定越好。** 一个随到随吃的午餐俱乐部，在单位受益人成本上总会胜过一项密集的个案管理服务，因为轻度接触某人的成本更低。这丝毫说明不了哪一项服务每英镑能产生更持久的改变。
- **在不同报告之间悄悄更换分母。** 一份年度报告中按"已报名"人数计算的单位受益人成本，与下一份报告中按"已完成"人数计算的数字，年度间不具可比性；每次都应明确说明所用的分母。
