# 单位成果成本（Cost per Outcome）

单位成果成本，是项目总支出除以在自身处境中实现了某种既定的、有意义改变的人数——而不是仅仅接受了服务的人数。它是资助方或交付团队能够使用的最锋利的效率指标，因为它迫使人们先面对一个大多数慈善机构都会回避的问题：究竟什么才算成功？

## 为何重要

同一年度的账目，一家食物银行可以报告出两个截然不同的数字。每份发放救济包的成本可能是 15 英镑。而每个实现了食品保障——不再需要紧急食物援助，并在后续跟踪节点得到核实——的家庭的成本，可能是 340 英镑。两个数字都是真实的。但只有一个能告诉资助方这笔钱是否真正发挥了作用。两者之间的差距，正是产出与成果之间的差距：发放一份救济包是产出；一个家庭不再处于危机之中是成果。参见[成果与产出](../outcomes-vs-outputs/)。

英国第三部门花了二十年时间构建基础设施来强制推行这一区分。New Philanthropy Capital 的慈善效能"四支柱方法"明确要求各组织先陈述其成果、再陈述其产出；由资助方支持的英国影响力测量协作组织 Inspiring Impact 发布了一份"成果矩阵"（Outcomes Matrix），许多拨款申请现在都要求慈善机构填写这份矩阵。The Trussell Trust 与赫瑞瓦特大学（Heriot-Watt University）联合开展的年度"饥饿状况"（State of Hunger）研究项目之所以存在，正是因为仅凭救济包数量本身，无法说明人们是否真正摆脱了食品不安全状态。

只有在确定了反事实情形之后，单位成果成本才具有意义："反正也会发生"的成果，并不是该项目所换来的成果。参见[反事实分析](../counterfactual-analysis/)与[置换与归因](../displacement-and-attribution/)。

## 数学原理

```
单位成果成本 = 项目总成本 / 实现既定成果的受益人数

其中：
  项目总成本     = 直接交付成本 + 应分摊的管理费用
  既定成果       = 一个预先设定、可测量的状态变化
                   （例如"6个月后回访时实现食品保障"，
                   而非"收到过一份食物救济包"）
```

将其与[单位成本数据库](../unit-cost-databases/)（例如行业专属的单位成本基准）进行对照，以判断某一单位成果成本相对于可比干预措施而言是良好、平平还是不佳。

## 实例演算

**某食物银行，一年数据**：

- 项目总成本：450,000 英镑
- 已发放救济包数：30,000 份
- 每份救济包成本（一项产出指标）：450,000 英镑 / 30,000 = **15 英镑**

该慈善机构还对一个家庭样本开展了六个月后续调查，发现在获得三份以上救济包的家庭中，有 35% 报告不再需要紧急食物援助，并在标准食品保障调查模块上的得分高于阈值。当年获得三份以上救济包的 1,800 个家庭中，有 630 个实现了这一成果。

```
单位成果成本 = 450,000 英镑 / 630 = 每个实现食品保障的家庭 714 英镑
```

一个将该慈善机构与现金转移试点或债务咨询服务进行比较的资助方，应当使用的是 714 英镑这个数字——而不是 15 英镑。如果同一地区一项可比的现金转移项目以每户 500 英镑的成本实现食品保障，那么该食物银行显然并不是通往同一成果更高效的路径，即便其单位救济包成本看起来很低廉。

## 与软件工程的关联

大多数个案管理系统的构建初衷是记录产出，因为产出是在交易内部发生的事情（发放了一份救济包、提交了一份表格）。而成果通常发生在更晚的时间，往往超出系统正常的捕获窗口，因此需要一个有意为之的设计决策：将后续跟踪机制（一个调查触发器、一个重新联系工作流、一项数据关联作业）构建为一等功能，而不是为了年度报告事后附加上去的东西。为该领域构建拨款管理或个案管理平台的工程师，应当在数据模型确定之前，就把"什么是成果事件、我们如何观测它"作为一个需求问题提出来——事后为成果字段补建远比为产出计数器补建困难得多。关于如何组织这场需求对话，参见[成果与产出](../outcomes-vs-outputs/)与[逻辑模型](../logic-model/)；关于在成果跟踪尚未建成时团队所依赖的那个更快速、更粗糙的指标，参见[单位受益人成本](../cost-per-beneficiary/)。

## 常见陷阱

- **将产出包装成成果来报告。** "触达的人数"不等于"被帮助的人数"。如果一个指标可以仅凭系统日志、无需任何后续联系就产出，那它几乎肯定是一项产出。
- **分母操纵。** 将成果人群窄化为"完成项目的人"，会悄悄剔除中途退出的人——往往正是最棘手的那些案例——从而人为拉高表面上的比率。分母应设定为所有开始参与的人，而不是所有完成参与的人。
- **没有反事实情形。** 将所有实现该成果的人都计入，包括那些反正也会实现的人，会高估该项目真正换来的成果。参见[反事实分析](../counterfactual-analysis/)。
- **在不兼容的成果定义之间进行比较。** 用经过验证的调查模块测量出的"食品保障"，与满意度表单中自我报告的"食品保障"不具可比性；只有当成果定义一致时，单位成果成本的排名表才是诚实的。
