# Метрики потока в государственной реализации

Метрики потока — закон Литтла, лимиты незавершённой работы (WIP) и эффективность потока — описывают,
насколько быстро работа проходит через систему с ограниченной мощностью. Спринт-доска — одна такая
система; очередь заявлений на пособия, реестр заявлений на планирование застройки или очередь дел по
визам — та же самая математика в другой форме.

## Почему это важно

Государственные объёмы дел — это системы массового обслуживания (очередей), а системы очередей
подчиняются законам очередей независимо от того, измеряет ли их кто-либо. Установленные законом сроки
рассмотрения делают это явным: в рамках режима планирования городов и сельской местности (Town and
Country Planning) большинство второстепенных заявлений на планирование застройки несут установленную
законом цель рассмотрения в 8 недель, а крупные заявления — 13 недель, — обязательство по времени
цикла, встроенное прямо в закон. Очередь дел по вопросам предоставления убежища Министерства внутренних
дел, неоднократно проверявшаяся Национальным контрольно-ревизионным управлением (NAO) и профильным
комитетом по внутренним делам, — хорошо задокументированный случай государственной системы, где
незавершённая работа росла быстрее пропускной способности в течение длительного периода, толкая время
цикла далеко за пределы любых установленных законом или сервисных ожиданий. Метрики потока дают
инженерам и руководителям, ведущим дела, общий количественный словарь именно для такого сбоя, а не
оставляют его качественной «проблемой очереди».

## Математика

```
Little's Law:  WIP = Throughput × Cycle Time
           →   Cycle Time = WIP / Throughput

Flow efficiency = active (touch) time / total cycle time   (Vacanti)

WIP limit effect: for fixed throughput, halving WIP roughly halves
average cycle time (Little's Law rearranged) — the lever available
without adding headcount.
```

См. [метрики DORA для общественной ценности](../dora-metrics-for-public-value/) — эквивалентную
математику, применённую к конвейерам развёртывания программного обеспечения, а не к ведению дел.

## Практический пример

**Отдел планирования органа местного самоуправления**: в любой момент открыто 400 заявлений (WIP),
команда закрывает 50 заявлений в неделю (пропускная способность).

```
Cycle time = WIP / Throughput = 400 / 50 = 8 weeks
```

Это приходится ровно на установленную законом цель в 8 недель для второстепенных заявлений — без
какого-либо запаса, а значит, любая изменчивость входящего спроса или времени ответа консультируемых
сторон толкает решения за законный срок.

**Эффективность потока**: из этих 8 недель (56 календарных дней) заявление обычно получает около 6
часов фактического времени обработки сотрудником.

```
Flow efficiency = 6 hours / (56 days × 8 working hours/day)
                = 6 / 448 ≈ 1.3%
```

Ориентир Ваканти для программных команд ставит типичную эффективность потока на уровне 15–20%;
государственное ведение дел, с множественными установленными законом передачами консультируемым
сторонам и окнами общественных консультаций, часто работает на порядок ниже. Эти 98,7% времени
«ожидания» — вот куда на самом деле уходят восемь недель, а не в мощность сотрудников.

**Вмешательство через лимит WIP**: ограничение открытых заявлений на одного сотрудника до 15 вместо
неограниченных 25 (при постоянной пропускной способности) сдвигает WIP с 400 до примерно 240 по
команде из 16 человек:

```
New cycle time = 240 / 50 = 4.8 weeks
```

Почти двукратное сокращение времени цикла от изменения политики, а не от увеличения штата — тот же
рычаг, который используют команды реализации в стиле DORA, когда ограничивают WIP спринта.

## Связь с разработкой программного обеспечения

Метрики потока — общий язык между канбан-доской команды реализации и полом ведения дел, для которого
она разрабатывает программное обеспечение: очередь сотрудника и очередь пул-реквестов обе подчиняются
закону Литтла и обе срывают свои цели по времени цикла одинаковым образом — слишком много незавершённой
работы относительно пропускной способности. Это напрямую важно для
[стоимости задержки в государственных программах](../cost-of-delay-in-public-programmes/): время цикла,
умноженное на стоимость задержки, — это фунты, застрявшие в очереди в любой момент времени, и это важно
для [стандартов услуг и метрик транзакций](../service-standards-and-transaction-metrics/), где
опубликованная цель времени обработки — это обязательство по времени цикла, диагностировать провал
которого способны только метрики потока. Программное обеспечение системы ведения дел должно раскрывать
WIP и время цикла как полноценные операционные метрики, а не хоронить их внутри системы управления
делами, которую никто не запрашивает.

## Подводные камни

- **Добавление лимитов WIP без устранения реального узкого места**: если ограничение — это время ответа
  внешней установленной законом консультируемой стороны, ограничение WIP сотрудника просто сдвигает
  очередь выше по потоку, а не сокращает её.
- **Отношение к эффективности потока как к цели для манипуляции**: ускорение тех самых 1,3% активного
  времени почти не сдвигает время цикла; рычаг почти всегда находится в состояниях ожидания, что обычно
  означает передизайн процесса, а не скорость сотрудника.
- **Игнорирование изменчивости**: закон Литтла описывает средние значения; объём дел с высокой
  дисперсией спроса нуждается в буферной мощности, а не только в более жёстком лимите WIP, иначе
  установленные законом сроки всё равно будут пропускаться в изменчивом хвосте распределения, даже
  когда среднее значение улучшается.
- **Непоследовательное измерение WIP**: дело, «открытое» в системе учёта, но фактически застопорившееся
  в ожидании третьей стороны, всё равно является WIP; его исключение льстит цифрам, не меняя реальность
  для гражданина.
