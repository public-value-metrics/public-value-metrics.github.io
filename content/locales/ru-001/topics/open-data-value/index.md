# Ценность открытых данных (Open Data Value)

Ценность открытых данных — это проблема оценки того, чего стоят государственные и публичные данные,
когда у них нет цены: они не продаются, поэтому нет строки дохода, но их публикация (метеозаписи,
расписания транспорта, границы почтовых индексов, реестры компаний) явно порождает нижестоящую
экономическую и социальную деятельность. Правильная оценка важна, потому что и «публикация бесплатна»,
и «это ничего не стоит» одинаково неверны, а инженеру программного обеспечения, решающему, открывать
ли API или набор данных, нужен более весомый аргумент, чем любое из этих утверждений.

## Почему это важно

Наиболее цитируемая оценка «сверху вниз» происходит из отчёта McKinsey Global Institute 2013 года
«Open data: Unlocking innovation and performance with liquid information», которая оценила
потенциальную годовую ценность открытых данных по семи направлениям — образование, транспорт,
потребительские товары, электроэнергетика, нефть и газ, здравоохранение и потребительские финансы — в
3–5 триллионов $ в год глобально, через механизмы, включающие повышение прозрачности, более
эффективное сопоставление спроса и предложения, и создание новых продуктов и услуг на основе данных.
Эта цифра — сценарная оценка, а не измеренный фактический результат, и её регулярно неверно цитируют,
как будто это доход, который государство может забрать себе напрямую, тогда как ценность в основном
накапливается у третьих сторон — предприятий, исследователей, граждан, — использующих данные, что и
есть весь смысл открытия данных, а не их продажи. Британский институт открытых данных (Open Data
Institute), соучреждённый сэром Тимом Бернерсом-Ли и сэром Найджелом Шедболтом в 2012 году, с тех пор
накопил массив более детализированных практических примеров «снизу вверх» — по секторам, по наборам
данных, — которые гораздо полезнее для реального бизнес-кейса, чем итоговая цифра McKinsey, потому что
они показывают механизм создания ценности, а не только её совокупный размер.

## Математика

У открытых данных нет рыночной цены, поэтому методы оценки заменяют её; повторяются три подхода, и ни
один из них недостаточен сам по себе:

```
1. Cost-avoided / replacement-cost method:
   value ≈ what users would have paid to produce or licence the
   equivalent data themselves — a lower bound, ignores value created
   by uses the original producer never anticipated

2. Market-analogue / downstream-activity method:
   value ≈ revenue or savings generated by businesses/services built
   on the data (e.g. satnav apps built on open mapping and traffic
   data) — captures real economic activity but is hard to attribute
   cleanly to the data release itself (see additionality-and-deadweight)

3. Contingent/stated-preference method:
   value ≈ what users say they would pay, or the time they say it
   saves them — see stated-preference-valuation for the general
   method and its biases

None of these produces a figure as clean as a market price; credible
open data business cases triangulate across two or more, and are
explicit about which mechanism is doing the work.
```

## Практический пример

**Иллюстративная публикация национальных картографических данных/данных адресов** (методология по
образцу практических примеров в стиле ODI, цифры иллюстрируют масштаб, обычно находимый в таких
исследованиях):

```
Cost-avoided estimate:
  Businesses that would otherwise licence equivalent address-matching
  data commercially, at an estimated average licence cost of £4,000/
  year, across an estimated 15,000 SMEs now using the free open dataset
  = 15,000 × £4,000 = £60,000,000/year in avoided licensing cost alone

Downstream-activity estimate (more speculative, needs a counterfactual):
  New delivery-routing and logistics products built on the open data
  that would not exist, or would be materially worse, without it —
  requires a comparison against the counterfactual of the data staying
  closed or commercially licensed (counterfactual-analysis), because
  some of that activity would happen anyway on paid data at a higher
  price, which is deadweight in the "value created by opening it" sense

A defensible business case reports the cost-avoided figure as the
solid lower bound, and treats the downstream-activity figure as an
upper-bound scenario, not a fact.
```

## Связь с разработкой программного обеспечения

Для инженеров практический вопрос ценности открытых данных обычно уже, чем национальные итоговые
цифры: увеличивает ли открытие конкретного API или набора данных (вместо того чтобы держать их за
партнёрским соглашением) переиспользование настолько, чтобы оправдать текущую стоимость
документирования, версионирования и поддержки его как публичного интерфейса? Эта стоимость обслуживания
реальна и является контрпартией экономике «построй один раз — переиспользуй часто» из
[государства как платформы](../government-as-a-platform/) — эти две темы близкие родственники, одна о
разделяемом коде и инфраструктуре, другая о разделяемых данных. Любое заявление о ценности открытых
данных следует проверить на [дополнительность и «мёртвый груз»](../additionality-and-deadweight/),
прежде чем оно попадёт в бизнес-кейс: деятельность, которая произошла бы в любом случае, на коммерчески
лицензированных данных, — это не ценность, созданная именно *открытием*.

## Подводные камни

- **Цитирование цифры McKinsey в 3–5 триллионов $ как специфичной для Великобритании или как доли
  конкретного набора данных**: это глобальная, семисекторная сценарная оценка 2013 года — использование
  её как точного множителя для одного национального набора данных искажает смысл этого числа.
- **Отсутствие контрфактического сценария**: приписывание себе заслуги за всю нижестоящую экономическую
  деятельность, построенную на открытых данных, без вопроса о том, сколько из неё произошло бы в любом
  случае на платных или лицензированных данных по более высокой цене (см.
  [дополнительность и «мёртвый груз»](../additionality-and-deadweight/) и
  [контрфактический анализ](../counterfactual-analysis/)).
- **Смешение стоимости производства с созданной ценностью**: набор данных, дорогой в сборе, не
  автоматически ценен для публикации, а дешёвый — не автоматически малоценен; ценность отслеживает
  нижестоящее использование, а не вышестоящую стоимость.
- **Игнорирование текущей стоимости обслуживания «открытости»**: публикация разового извлечения в CSV —
  не то же обязательство, что ведение документированного, версионированного, поддерживаемого открытого
  API; недофинансирование последнего после объявления о запуске — распространённый сбой.
